实测报告

多花多少 token，记得准不准。

同一组任务，开着和关着 FULI 各跑一遍。每个数字都写明怎么测、用的模型和客户端、哪天测的。

先说结论

  • 开着 FULI 仍会多花输入 token：最新一轮，输入是不开时的 1.53 倍。
  • 需要项目知识的任务，开着 FULI 18 次全做成，不开只做成 3 次。
  • 留出的 32 个提问，入口找到 25 个；8 个不该命中的，误报 2 个。

全部在合成项目上测，样本小，只能看趋势。

「多出的输入占比」= 开 FULI 比不开多出的输入，占开 FULI 时输入的比例。

怎么测的
  • 客户端：Claude Code 2.1.301 无头模式，第 1 轮新开会话，之后每轮接着同一会话。
  • 模型：claude-haiku-5-5。日期：2026-11-06。
  • 任务：一个合成小项目上的 6 轮会话：读代码、改三处、跑测试、纠正一次。
  • 规模：开、关各 2 个会话。开着的一组接独立的测试用 FULI，只有合成数据。
  • 输入 = 每次模型请求的未缓存输入、缓存读取和缓存写入之和；费用是 Claude Code 报告的标价。
要注意
  • 多出的输入大多是缓存读取，所以费用涨得比输入少。
  • 第 5 轮占比仍高：模型多加载了一次工具、多做了一次收尾调用。
  • 两组都没有完整做成的会话，所以还没有「每做成一个任务花多少」的数。

怎么测的
  • 留出题：另一个合成项目，40 个中英文提问。32 个各有一条该找到的知识，8 个什么都不该找到。题目在读召回代码之前写好。
  • 只跑 FULI 的任务入口，不调模型；每个提问 1 次。日期：改版前 2026-11-05，改版后 2026-11-06。
  • 多轮一栏和上面的 token 测量是同一批会话，按模型实际看到的入口内容计。
要注意
  • 错误码那条两次都没找到，是排序问题，还没修。
  • 只说「继续」、不带任何主题的提问，所有检索方法都找不到。

知识送到后，任务做成了吗

6 个任务都需要一条仓库里找不到、或仓库里写的是旧值的项目知识。做完由隐藏检查判定。

怎么测的
  • 客户端：OpenCode。模型：Claude Opus 5.5。日期：2026-11-04。
  • 规模：6 个任务，每组每个任务 3 次，共 54 次；失败的运行也计入。
  • 记住新决定：6 次都成了当前知识（待你确认）。改写旧知识：6 次都由新版本替换旧版本。
