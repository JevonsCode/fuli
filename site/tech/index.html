技术

跑在你的电脑上，由你说了算。

写给正在评估 FULI 的开发者：怎么搭起来、带了哪些 Skill、数据怎么存、为什么这样设计。

本机四层

  1. 接入

    MCP、CLI 与 HTTP

    兼容 MCP 的客户端都能接入，fuli connect 生成通用配置。Codex、Claude Code、Cursor、OpenCode 另有适配器；自动采集对话、唤醒会话取决于适配器。

  2. 编排

    Node 控制台

    CLI、本机管理界面和 MCP 服务。界面和 Agent 工具调用同一套应用服务，业务规则只有一份。

  3. 治理

    Python Provider

    graph-provider/ 是事实源，守住空间与项目范围、来源和确认。

  4. 存储

    本机 Neo4j

    图数据库存知识、关系和历史。Provider 和 Neo4j 只监听本机回环地址，开了局域网模式也一样。

界面上每个改数据的操作，要么有对应的 Agent 工具，要么写明只能由本人在本机操作。

随 FULI 安装的 Skills

Skill 是给 Agent 的说明书，不是付费版本。

  • capturing-session-knowledge

    召回当前项目的知识，应用协作偏好；任务结束时，把值得复用的结果连同来源存下来。

  • operating-fuli

    通过结构化工具查看和修改项目、知识、Agent 与审核，不靠操作浏览器。

  • grilling-project

    先读仓库，再一次问一个问题，建立或补全项目档案；公开前先预览公开边界。

  • flreview

    你输入 /flreview 时，按 FULI 排好的候选，生成一页这次用的知识回顾。

  • fuli

    /fuli start、stop、restart、status：开关当前会话里的 FULI，由 Hook 直接应答。

数据设计

  • 个人空间与项目

    数据按个人空间隔离，空间里分项目。搜索限定在空间和项目范围内，不混查所有项目。

  • 实体与关系

    知识是图里的实体（Entity）和关系（RELATES_TO），带着来源会话、范围和确认状态。

  • 改动写新版本

    修改不覆盖原话：新版本取代旧版本，旧版本保留原文、来源和确认，有效期到新版本开始为止。当前回答只读仍有效的版本。

  • 人来确认

    确认状态分三档：人确认、Agent 确认、待确认。Agent 的使用证据最多升到 Agent 确认。

  • 格式迁移

    图谱格式有版本号。只加索引和约束的步骤自动运行；会改记录的步骤要你确认，并记下撤销所需的内容。旧版 FULI 打不开新格式。

  • 派生索引

    按意思搜索的向量、补全的别名和上下文都是索引：不改原文，不产生版本，可以丢掉重算。

  • 删除

    删除会同时清理本机副本；从旧备份恢复，也不会把删掉的文字带回来。

理念

  • 本地优先

    个人图谱默认留在你的电脑上。凭据、临时日志和原始命令输出不进图谱。

  • 人说了算

    AI 检索、总结、提醒、执行；最终决定在人。重复和相似不等于你的确认。

  • 按需查询

    会话开始不塞入全部历史：入口只带偏好和一小段召回，其余由 Agent 用到时再查。

  • 历史与当前分开

    旧做法当时可能是对的。FULI 保留来源、时间和取代关系；负面反馈只降权或触发复查，不悄悄抹掉。

  • 看复用，不看数量

    节点数和对话数不是目标。目标是确认过的知识在对的项目里被再次用上，少讲一遍、少返工一次。
