# Agent 圆桌 / Agent Roundtable

日期：2026-10-09。用户已授权开发并发布 Beta。本文件描述产品架构；实际执行能力以发布验收为准。

## 产品目标与四个平面

围绕同一个目标，让不同电脑、不同平台的真实 Agent 讨论、分工、实施和审查。每位参与者使用独立执行入口与席位授权，公开结果带着来源回来，由用户验收。没有项目也可以创建独立临时任务作用域。

| 平面 | 责任 |
| --- | --- |
| 身份与知识 | Fuli Provider 管理长期身份、职责、私有记忆、准确项目授权与时间历史；明确授权后按需提供自己席位的私有上下文 |
| 协作 | Node 24 内置 SQLite 保存房间、席位、不可变消息、回合、尝试、任务、产物和结果；事务负责幂等与并发 |
| 执行 | 参与电脑主动领取自己的回合，经公共 participant port 调用本机 CLI 或远端服务，使用明确工作区权限 |
| 接入 | 本地 owner HTTP 控制台、受邀请限定的远端 HTTP/MCP、厂商独立适配器 |

SQLite 是协作日志，不是第二个知识系统。没有 Fuli 运行配置时，协调端提供独立圆桌；存在既有配置时，经应用端口验证项目/Agent/任务绑定。Provider 离线不能成为伪造身份或扩大权限的理由。其他参与者的私有知识不进入公开日志。

## 用户流程

1. `fl roundtable serve` 启动协调端，打开 `/roundtables`，填写目标，选择讨论或协作及 2–6 个席位。
2. 指定一位主持人。协作需要实现者和审查者，可定义任务依赖；实现者的写工作区必须明确指定，审查者只读。
3. 每个席位生成独立邀请。参与端使用自己的客户端、凭据和邀请加入，默认只读。
4. 用户开始。参与端主动领取当前回合，带着限定上下文执行，提交一次最终结果。
5. 用户可以补充要求、暂停、停止、处理阻塞、明确扩展限制。失败与中断保留记录，不自动重复不确定的副作用。
6. 查看结论、分歧、任务、产物和实际执行回执。协作结果等待用户接受；绑定 Fuli 任务时还需要原任务的权威验证和完成状态。

页面提供列表、创建、详情、席位邀请、公开消息、结果和事件视图。加载复用 GrowthLoading 的实际中英文请求标签，刷新保留内容。秘密只显示一次，不保存到浏览器长期缓存。

## 权限与接入

本机用户负责创建、邀请、控制、补充要求、扩展预算和最终接受。参与者只能读自己房间的公开简报、加入自己席位、领取自己的回合并提交自己的尝试。主持职责是讨论和汇总，不获得 owner 控制或额外执行权限。

邀请使用随机 bearer capability，数据库只保存哈希，限定准确房间/席位，有效期有界且可撤销。每次操作重新检查撤销与到期。正文不能指定可信 actor、其他席位或本机用户身份。

owner API 只接受本机连接与正确 Host/Origin。公网代理只公开 `/roundtable-peer/`，保留显式允许的 Host。远端 MCP 仅提供 read_roundtable、join_roundtable、claim_roundtable_turn、submit_roundtable_turn，不提供邀请管理、私有知识、shell 或 owner 控制。

Fuli 应用验证准确项目、活跃 Agent 和可选任务。自己的私有上下文仅在成功领取时经明确端口按需返回，并检查允许的客户端；不持久化到公开日志。独立席位明确标为 standalone。每个客户端有独立来源/会话，不复用主持人的 taskContextToken。

CLI 写入需要本机 --allow-write 与房间实现席位的准确工作区授权同时成立，仅实施阶段启用。审查只读。参数使用数组，提示经 stdin 输入；禁用无关 Hook/MCP/项目扩展，进程与输出有界。凭据由参与端明确配置提供，不存入公开消息。

## 调度与恢复

讨论：discussion → synthesis。协作：discussion → planning → implementation → review → synthesis → 用户验收。

讨论顺序执行；实现任务按无环依赖排序，席位提交自己的任务包。实施席位串行，避免同一工作区并发写入；不提供自动文件合并。每次只有一个 current turn。

领取原子生成 attemptId、fence 和 deadline，两进程竞争只有一个成功。提交消息、记录尝试和推进合法阶段在同一事务中完成。相同幂等键不同内容冲突；过期或终止后的结果进入独立晚到证据，不覆盖当前回合。

硬限制覆盖讨论轮数、Agent 消息数、总时长和回合时限。用户输入不消耗 Agent 消息预算。达到限制后停止发新回合，只有用户显式扩展才继续。暂停保留在途尝试；停止要求工作端取消其拥有的进程树，未确认的远端取消如实记录。

重启检查尝试的实际签发进程；死亡或已关闭签发者的未完成尝试失效，活着的第二连接不误触发恢复。失败和中断需要用户明确恢复或至多一次重试，不自动重跑可能已有副作用的工作。终态不能重启或改写，邀请仍可撤销。

## 结果、完成与证据

自动参与者返回统一 JSON：正文、completed/failed/blocked 状态、产物引用、明确验证结论、分歧。实现成功必须含产物，审查成功必须明确 verification.passed；缺失、否定或运行失败不能进入成功汇总。以前发言中的分歧在汇总时保留。

产物与验证仍是参与者报告，不自动成为人工确认。应用、提供商、模型、会话、远端任务、用量和取消确认只记录执行端报告；缺失显示未知，自报身份不标成认证身份。连接记录和预检不是执行证据。

独立房间或仅绑定项目的协作，最终记录 human_accepted，不完成 Fuli 任务。显式 taskId 与 artifactRevision 绑定时，原任务完成状态及对应质量门都必须通过；请求中的 taskVerification 不被信任。

## 适配器和模块

公共注册表选择适配器，平台细节只在 src/agents/<runtime>/，领域与协议不分支到厂商。

| 入口 | 行为与边界 |
| --- | --- |
| Codex CLI | 新的临时受控会话，真实 JSONL 会话/用量和结果 schema；默认只读，授权后 workspace-write |
| Claude Code CLI | 独立配置，禁继承 Hook/MCP，限定工具与 JSON schema；认证/运行失败保留实际原因 |
| Pi + Ollama | Pi 专用隔离配置、本地模型、工作区工具约束；实际验收单列 |
| Grok API | xAI Responses API，显式环境凭据/模型；缺凭据时只有协议测试 |
| Grok Bot / MCP 客户端 | 在其官方自定义 HTTPS MCP 配置圆桌地址及席位凭据，主动参与；不承诺外部唤醒已有聊天 |
| A2A | 官方 JavaScript SDK 适配 Agent Card、JSON-RPC/REST、任务/事件、输入认证阻塞和取消；不宣称完整规范认证 |

A2A 要求 HTTPS 与可验证公网地址，同源发现、拒绝重定向和私有地址。错误、认证、超时或取消未确认不会转换成模拟成功。没有开放接入接口的闭源平台不承诺支持。

src/roundtables 分别负责领域、存储、服务、应用、HTTP/MCP、进程、工作端和结果契约；入口只接线。Vue 消费同一服务，owner 操作刻意不暴露给外部 Agent。

测试覆盖能力隔离、撤销/到期、SQLite 竞争、幂等/CAS/过期 fence、恢复、阶段/DAG/预算、私有上下文、负面审查、真实 HTTP/MCP 会话、CLI 参数/取消及 API 协议夹具。真实执行验收与模拟夹具单列；物理多电脑和 Grok Bot 登录需用户环境验证。

详见 [Beta 测试指南](roundtable-beta-testing.md) 与 [官方方案研究](roundtable-research.md)。开发分支基于临时项目能力 PR #2，原主工作区用户修改保持独立。
