# Agent 圆桌 / Agent Roundtable

日期：2026-10-09。状态：已通过独立设计审查，等待用户确认；不是已实现功能。

## 产品目标

在 Fuli 中创建一个有明确目标的圆桌，让来自不同 AI 客户端的真实 Agent
交换意见、点名协作、交接工作，并向用户交付有证据的结果。
身份、职责、偏好、项目授权和长期记忆继续由 Fuli 管理；圆桌负责本次协作。

用户可以说：“开一个圆桌，让 Codex 负责实现，Claude 负责审查，先讨论方案，
再完成任务。把分歧、最终方案和实际工作结果给我。”

平台无关指接入协议和领域模型不依赖某一家模型厂商。平台必须提供可调用的
CLI、MCP 接入或兼容远端端点。只有封闭聊天界面、没有接入方式的平台不会
被宣称已经支持；不使用账号共享或模拟发言制造互通。

## 三种实现路径

| 路径 | 优点 | 代价与适用边界 |
| --- | --- | --- |
| MCP 共享圆桌 | 已接入 Fuli 的客户端可读取议题、加入、发言和接任务；适配面广 | 不能仅凭 MCP 发消息就唤醒不在线的客户端；需要 Agent 主动参与 |
| 自动 CLI + 开放 MCP，推荐 | 本机 Codex 和 Claude Code 自动轮流工作；其他平台可通过 MCP 加入 | 需要真实运行时适配器、有效凭据和明确执行授权；必须处理超时与取消 |
| 直接多模型 API | 同一应用内调多家模型，调度简单 | 不等于连接用户已有的独立 Agent；另增 API 凭据、计费和工具执行体系 |

首版采用第二种路径。以两个真实本机客户端自动协作为验收目标，开放 MCP
参与作为同一能力的另一种接入方式，不另建第二套记忆系统。
远端 A2A 适配安排为后续接入，不在首版声称完整 A2A 协议兼容。

## 首版用户流程

1. 从“圆桌”进入，填写目标，选择讨论或协作任务，选择 2–6 位 Agent，指定一位主持人。
2. 有项目时使用确切项目；无项目时复用临时任务项目作用域。项目歧义仍需选择。
   缺少合适人员时复用现有 HR 招聘/借调确认，不因创建圆桌而绕过招聘授权。
3. 为各席位选择已授权执行入口，展示实际就绪状态、工作区及本次执行权限。
4. 选择“开始”。自动模式只有必需席位通过真实预检后才启动；缺凭据时展示阻塞，
   不静默转成模拟或手动模式。用户可以明确改用 MCP 手动参与。
5. 主持人提出问题，参与者按顺序发言、引用公开给圆桌的证据，形成方案或保留分歧。
6. 协作任务进入分工、执行和审查。用户可继续补充要求、暂停、停止或回答必要问题。
7. 结束展示结论、未解决分歧、产物及真实执行表；有价值知识进入既有候选/检查点流程。

首版默认执行策略是讨论和只读审查。创建协作任务时用户明确指定允许写入的
工作区及职责；实施席位才能在该范围修改代码。审查席位默认只读。
外部发消息、付费购买、部署等动作继续遵守既有授权，圆桌启动不自动授权这些动作。

## 页面设计

新增 `/roundtables` 目录和 `/roundtables/:spaceId/:roomId` 详情页。
入口位于控制台主导航，复用现有 Agent 头像、人员目录和任务组件。

- 顶部：目标、所属项目或“临时任务”、阶段、停止条件和开始/暂停/停止。
- 席位区：姓名、职责、显示平台、接入方式、真实连接/授权状态和当前工作。
- 主区：有序公开消息。消息类型为提案、提问、审查、交接、结果和用户输入。
- 结果区：共识、分歧、下一步、产物和真实执行表；详细事件按需展开。

不把运行时技术字段放入首次任务输入。高级设置提供轮数、时限和执行策略。
待加载和提交使用 `GrowthLoading.vue`；标签中英文描述当前真实操作，失败提供重试。
保留已有内容和用户草稿，不用空列表掩盖读取失败。

## 范围与数据

圆桌绑定确切 `personalSpaceId + projectId + coordinatedTaskId`。
它是任务协作视图，不替代已有 Project Agent Task，也不建立第二份任务完成状态。

| 记录 | 责任 |
| --- | --- |
| Roundtable | 目标、模式、主持席位、status、phase、限制、版本及对应任务 |
| Seat | 稳定 Agent ID、职责、执行入口绑定、加入状态；显示平台是元数据 |
| Message | 不可变事件 ID、有序序号、席位、正文、类型、引用、服务器时间和来源 |
| Turn | 指定席位、所需动作、尝试 ID、执行租约/栅栏版本、期限和结果引用 |
| Outcome | 主持人报告的结论与分歧、产物和验证引用；本身不代表人工确认 |

共享消息存于 Provider 的独立私有协作日志，不塞入每位 Agent 的长期工作记忆。
参与者看到圆桌简报和公开给圆桌的消息，不能因同桌而读取别人的私有记忆。
跨项目参与复用已有借调授权；不自动向目标项目分享来源项目的私有上下文。

首版仅支持全圆桌可见消息，不加入私聊子系统。单条正文上限 16 KiB，引用只接受
已授权产物的标识，不接受任意文件读写指令。敏感内容复用现有过滤边界。
读取用序号游标分页；自动上下文使用目标、当前阶段、必要摘要和有限增量消息，
截断必须标明，细节按需读取。

所有写入检查当前项目授权、活跃席位和相关任务状态。创建、发言与提交回合结果
有幂等键；复用幂等键但内容不同返回冲突。结构变化检查最后读取的 revision。
消息序号、幂等检查和写入在同一 Provider 事务内完成。
每个席位拥有独立的宿主任务上下文和检查点，绑定该客户端实际 source/session。
不得把主持人的 `taskContextToken` 发给其他平台复用；roomId 与 taskId 是公开给
获授权参与者的关联标识，不是访问凭据。圆桌汇总通过主持人的原任务提交。

控制面权限在服务端检查，不能由界面按钮是否显示决定：

| 操作 | 允许的执行主体与条件 |
| --- | --- |
| 创建草案 | 用户，或当前任务获授权的负责人；不因创建获得额外执行权限 |
| 改席位、执行授权、扩展预算 | 本地用户；MCP 不得代写人类批准记录 |
| 开始/恢复 | 用户，或主持席位在用户已记录的本圆桌执行授权范围内；所有必需入口重新预检 |
| 指定下一回合、进入下一阶段、汇总 | 用户或主持席位；调度 driver 只执行合法转换 |
| 读公开消息、接受/提交回合 | 用户或已授权席位；席位只能提交自己的当前回合 |
| 暂停/停止整个圆桌 | 用户或主持席位；受已有执行授权及实际取消能力限制 |
| 报告自身阻塞/取消自身回合 | 所属席位；不能因此停止或调度其他席位 |

主持职责不含启动任意进程或扩大工作区权限。普通席位不能更换主持人、
改变预算、指定其他席位、改变阶段或标记整个任务完成。

## 发言、交接与停止

首版采用确定性的轮流发言，主持人可点名下一位和请求特定审查。
不增加一个模型只为决定谁发言。每次点名产生 Turn；席位明确接受并完成该 Turn。

一个讨论轮次是当前参与者列表依次获得一次发言机会；主持人可调整本轮顺序，
不能给同一席位第二次机会来规避轮数限制。跳过离线席位需显式记录原因。
循环结束后才进入下一轮。实施/审查回合按调用次数和总时间限制，不冒充讨论轮次。

每个 Agent 发言必须属于该席位已接受的当前 `turnId + attemptId + fenceVersion`。
每次尝试只允许提交一个最终公开消息；过程/心跳是系统状态事件，不算额外发言。
提交最终消息、尝试结果与推进回合在同一事务中完成，幂等键由回合尝试派生。
过期提交不能发布为当前讨论消息，只保留独立的过期执行证据。
自动 CLI 不获得公开发言写工具，由适配器将真实最终输出提交一次；手动 MCP
席位通过提交回合工具发布一次。两条路径调用同一应用操作，不再从 stdout 重复发言。
正文非空的最终 Agent 消息计入 30 次限制；服务器系统事件和本地用户输入不计入。
用户可在轮外补充要求；其身份由本地用户接口证明，MCP 不得伪装用户发言。

每次只有一个讨论 Turn。协作执行仍沿用已有 task participant/run 机制；首版
禁止两个实施席位同时写同一工作区，审查可只读进行，不构建新的并行文件合并系统。

默认最多 3 轮讨论、30 次 Agent 发言、30 分钟总时限；回合执行最多 5 分钟。
用户可设置更小限制。达到限制后暂停并报告原因；用户明确扩展后继续，
不能由 Agent 自动提高自己的预算。最多一次可恢复的传输重试，不重试认证失败。
Token 用量只有实际报告时才显示；缺少数据标为未知，轮数、调用数和时间仍可硬限制。

status 为 draft / active / paused / waiting_input / waiting_auth / concluded /
failed / cancelled；phase 为 discussion / planning / implementation / review / synthesis。
讨论模式按 discussion → synthesis → concluded 结束。
协作模式按 discussion → planning → implementation → review → synthesis 运行，
讨论形成方案时只推进到 planning，不进入 concluded；失败审查可在既有验证策略
和预算内回到 implementation，不能绕过升级门槛。只有原协调任务验证通过并完成后
才能 concluded。圆桌状态不得单独让协调任务变为完成；原任务状态与验证是权威。
讨论结束不伪造 worker 执行记录。
终态不可直接重启；后续工作建立有关联的新圆桌/任务并保留原历史。

暂停不继续安排新回合，已有运行在当前期限内结束并记录；停止尝试取消当前
实际执行，只终止本工具拥有的进程树。无法取消的外部运行显示取消请求未确认，
不能将其标为已经停止。超时后的晚到结果保留为过期尝试证据，不覆盖当前回合。

交付结论包含支持理由和保留的反对意见。多数意见不自动成为人工确认事实。
需要用户判断时调用现有 attention 流程；用户回复关闭 attention 不自动扩大权限。

## 运行时接入

公共领域层通过 `RoundtableParticipantPort` 接入运行时，约定 describe、preflight、
dispatch、observe、cancel 和 close。能力描述区分实际可自动运行、可手动加入、
可取消、是否报告用量、支持的工作区操作。

| 入口 | 首版行为 |
| --- | --- |
| Codex CLI | 明确启动新的受控会话，解析真实 JSONL 事件，记录实际应用/会话/run 与结果 |
| Claude Code CLI | 明确启动新的受控会话，解析真实结构化输出；401 等错误成为 waiting_auth/failed |
| Fuli MCP 客户端 | 主动加入、读取消息、接受自己席位的回合并报告；不承诺后台自动唤醒 |
| 远端 A2A | 后续独立适配器；首版接口保留扩展点，不提供未经测试的兼容承诺 |
| 没有可用接口的 AI 平台 | unavailable，给出所需接入条件，不显示假参与者 |

平台分支仅位于适配器注册边界；Codex 和 Claude 的启动/解析代码分别归属
`src/agents/codex/` 与 `src/agents/claude-code/`。公共工具不新增散落的平台判断。
任意平台的显示名称不能用作认证身份，现有 SourceApplication 的 other 表示未知平台。

自动适配器仅由用户明确启用的现有执行配置启动；不扫描账号凭据、不改用户全局
客户端配置。每次运行使用私有临时配置和限定项目/席位的 Fuli 接入，禁用无关 Hook
和生产 MCP 的自动继承。凭据读取既有明确配置，日志和消息不保存值。
启动命令用参数数组，禁止把提示词拼接为 shell 命令。

MCP 席位绑定取自服务端认证后的作用域，不信任正文里的 senderAgentId 或平台名称。
远端接入扩展现有有限工具 allowlist，绑定确切项目和席位；不暴露全功能本机工具集。
自动执行可由适配器进程回执证明；手动 MCP 的声明与运行时验证证据明确分开，
在无法验证进程身份的共享宿主下不宣称具有强运行时身份隔离。

一个 application 实例通过 Provider 的圆桌 driver 租约取得唯一调度所有权，
以有栅栏版本的 Turn 防止两个实例重复启动。应用重启使未完成尝试失效并记录
interrupted，旧结果不能推进新回合；检查本工具确实拥有的遗留进程后等待用户恢复。
首版不自动重启不确定的副作用。driver 租约和执行器租约均在 finally 中释放。

## Fuli 集成与模块责任

1. `src/roundtables/`：纯 JavaScript 的阶段、席位、回合、消息限制与终止规则。
2. 圆桌 application：复用 `coordinateProjectAgentTask`、临时范围、借调和任务验证；
   通过存储端口读写，保持 composition root 薄。
3. Provider 的独立 roundtable models/store/routes：Neo4j 私有日志、事务、授权、
   幂等和并发控制。沿用 Python Provider，不把存储塞进入口文件。
4. HTTP/MCP 适配：调用同一 application，维护工具 schema、注解、远端 allowlist
   和 interface parity catalog；所有界面写操作有对应 Agent 工具。
5. Vue 圆桌视图及上述运行时适配器：展示真实状态与增量结果，执行通过公共端口。

首版工具覆盖创建/列举/读取圆桌，加入/读取当前席位，接受/提交回合（同时发布最终消息），
开始/暂停/停止；执行配置授权仍走现有人类专属接口。
具体工具 schema 在实现计划阶段逐项固定，不能靠浏览器写入替代缺失工具。

复用已有员工身份、项目小组、任务参与者、worker 实际记录、verification 和租约，
只新增圆桌特有记录。现有 coordinator 只返回计划；本特性的自动 driver
必须真的调用 participant port，不能把计划、就绪预检或配置 run ID 算作执行。

## 实施顺序及依赖

设计确认后，在 `codex/agent-roundtable` 独立分支实施。
该分支基于 `0f16f00`（PR #2），需要其中临时项目能力；不混入原主工作区修改。

1. 领域规则、Provider 日志和席位/回合事务，补 focused tests。
2. 同一 application 的 HTTP/MCP/parity；两个独立 MCP 客户端证明消息与回合互通。
3. Codex、Claude 自动 CLI 适配及有界 driver；先故障/协议测试，再真实凭据验收。
4. Fuli 页面、双语说明、可复制加入指令和最终真实执行表。
5. 独立审查、完整相关检查及 PR；npm 发布、本机升级和远端 A2A 接入另行明确处理。

设计文档与研究不启动模型、不改生产图或客户端运行配置。
用户确认后实施完整首版，不把只完成共享消息阶段称为已完成自动圆桌。

## 验收与证据

- 两个独立 MCP 会话加入不同席位，A 发提案、B 引用并反驳、A 修订，第三方读取相同有序历史。
- 越权项目/席位拒绝；跨项目借调只给公开简报，不泄漏来源私有记忆。
- 并发接受回合只有一个获租约；重复提交不重复写，过期尝试不能替代当前结果。
- 达到轮数、消息数、时间和用户停止时停止新调用；断线重试、认证失败、进程卡死
  显式保留原因，并验证本工具拥有的进程和临时配置被清理。
- Codex 与 Claude 的真实运行交付“提案 → 反驳/审查 → 修订 → 结论”；另一个任务
  验证真实实施产物与审查结果。缺有效 Claude 凭据时真实跨平台验收记为 blocked，
  不用模拟服务替代，不宣称已通过。
- 单元、真实数据库、MCP 协议、CLI 结构化输出、真实模型分别记录证据等级。
- 页面空/等待/运行/失败/完成、400px 宽度、复制行为、loading 与恢复错误验证。
- 只有实际 worker 回执形成执行行，平台与模型取实际值，缺失用量显示未知。
- 首版不承诺原生现有聊天移交、云端 24/7、任意封闭 AI 平台、A2A 全规范兼容、
  私聊或跨组织协作。扩大这些范围需要独立设计与验收。

## 市场参考（一手资料，2026-10-09）

- [A2A](https://a2a-protocol.org/latest/specification/)：独立 Agent 的能力发现、消息、
  任务、产物和认证契约。不是自动操纵任意桌面应用的协议。
- [AutoGen 群聊](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/teams.html)
  及 [终止条件](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/tutorial/termination.html)：
  借鉴轮流/点名发言和组合停止条件。
- [Microsoft Agent Framework A2A](https://learn.microsoft.com/en-us/agent-framework/journey/agent-to-agent)：
  远端 Agent 显式包装与托管。AutoGen 已进入维护模式，因此不作为新功能底座。
- [LangChain handoff](https://docs.langchain.com/oss/python/langchain/multi-agent/handoffs)
  及 [LangGraph interrupt](https://docs.langchain.com/oss/python/langgraph/interrupts)：
  转交相关上下文、状态恢复和等待用户；副作用保持幂等。
- [CrewAI](https://docs.crewai.com/en/concepts/processes)：借鉴任务责任和预期产物；
  应用内多模型编排不等于现有跨平台 Agent 已互通。
