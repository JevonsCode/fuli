# FLA 自增长：给人看的输出，和自己沉淀工作流与脚本

两条规矩由 FULI 定好并下发，不靠单个模型自觉（Jevons 11-23）：

1. 给人看的东西要清晰明了，有交互的方便交互，能点击的不输入。
2. FLA 长期做某类事就自己沉淀工作流，重复性高的就自己沉淀脚本。

两条都写在公共层，不分客户端。客户端之间的差别（哪个客户端能渲染图、有没有原生选择
组件）由 FLA 在那一刻判断，规矩只说「客户端支持什么就用什么」。

## 一、给人看的输出

### 规矩放在哪

两处，一长一短：

- **短版在 MCP server instructions 里**，每个会话只发一次（`src/mcp/instructions.js`）：
  「People: after sourceMarker lead, conclusion+asks first, short; diagram/table if clearer;
  clickable choices not typing; receipt last.」——放在必需的来源标记之后、回执之前，和现有
  规则不冲突。只放在按需读取的规则里不够：客户端 hook 每轮都说「普通任务不要读
  `fuli://rules/task-entry`」，而这条恰恰是每个普通回复都要用的。chat 配置 1,327 → 1,460
  字节（+133）；full 配置在 Claude Code 2 KiB 上限，删掉两句工具自己的描述已经说过的话换出
  位置，仍是 2,048 字节。
- **全文在 `task_guidance.human_facing_output`**，随 `task_guidance` 那一个指针下发，普通入口
  每轮 0 字节，只有 `rules_version` 变。协作 worker 读不了资源、入口里是全文，但它只向
  负责人汇报，三条新规则都不发给它（`task-context-view.js`），所以 worker 的入口也不变长。
  同一任务的恢复读取（`read_task_preferences`）也不带这三条全文：它把整份结果（两个通道）
  放进 32 KiB，偏好和规矩共用这个预算，三条全文约 2.9 KB，会把本来一页装得下的偏好挤到
  第二页（`withoutLeadOnlyRules`，`task-knowledge-guidance.js`）。全文仍在规则资源里。

### 规矩说什么

- 先写结论和要人做的事，再写别的；只写重点。
- 结构能帮人看懂时才用列表或表，不为了好看而列。
- 关系、流程、前后对比用图更清楚时就画图，用客户端渲染得出来的形式（Mermaid、表格、
  链接到控制台的图）。
- 要人做选择时给能直接点的选项：会话里用客户端原生选择（`human_interaction`），人不在
  用 `request_agent_attention` 的 `options`（已支持 2–3 个），两样都没有才给编号选项。
  不让人打字说一个本可以点的答案。
- 链接给能点的完整链接，不给要人自己拼的路径或 ID。
- FLA 在圆桌里发给人看的总结，同一套标准。

### FULI 自己发给人的东西

同一把尺子量 FULI 自己的回执、待拍板请求、通知和更新说明。本轮改掉的、以及留下的，见
PR 描述里的清单。原则：给人看的地方不出现内部代号和英文类型名；一个请求的选项是人能
直接点的、彼此真的不同的几项。

## 二、自己沉淀工作流和脚本

### 现在断在哪

FULI 里零件都有，链条断了三处：

- **发现重复**有两套。图谱那套（`list_workflow_candidates` →
  `graph-provider/fuli_graph/workflow_candidates.py`）靠 `fuli_workflow_session_authority`
  的证据，而唯一写这个证据的 `record_workflow_transition_observation` 已在 11-11 退役
  （`src/agent-tools/retired-tools.js`），所以新装的机器上候选永远是空的（JS 一侧的
  `list_workflow_candidates` 和 `propose_agent_workflow` 的 `candidateId` 已在 #1085 删掉）。活着的那套是
  `src/fla-growth/tool-suggestions.js`：同一位 FLA 在同一项目的 3 个以上已完成任务里，
  计划步骤序列逐条一模一样（或某个启用的工作流在 3 个任务里按同一版本跑完）。
- **提示沉淀**只提示人，不提示 FLA。上面那套每小时跑一次，向人提一条待拍板问「要做成
  工具吗」；但那位 FLA 自己下次再做同类事时，入口里什么都没有。
- **沉淀出来的东西下次不被带上**。任务入口从不带工作流，这是故意的
  （`docs/agent-interface-architecture.md`）；可是也没有任何规则让模型去调
  `list_agent_workflows`，于是确认过的工作流很可能一次都不被读。
- **「做成脚本」这个选项背后没有东西**。`TOOL_CHOICES` 里有「做成脚本」，但 FULI 里没有
  脚本存储、没有脚本运行入口；只有 Agent 应用这一条真路。

### 做法

**判据**在活着的那套（`tool-suggestions.js`）上改，不复活退役的观察工具。步骤标题是 AI 每次
自己写的，逐字相同几乎从不出现，所以改成「同一类事」（`src/fla-growth/step-similarity.js`）：

- 一步拆成词（拉丁字母词、数字记作 #）和汉字两两相连的字对，去掉虚词；两步共有一半以上
  就算同一步（Jaccard ≥ 0.5）；
- 两份计划都至少 3 步，长的那份 60% 以上的步骤能和另一份配上（不管先后），就算同一类事；
- 同一位 FLA、同一项目，在它最近的已完成任务里（按页读到 500 个为止）有 3 个以上同一类事；
  或某个已确认的工作流按同一版本跑通了 3 次。

虚构数据上的表现（测试里逐条）：换说法（「Bump version to 1.4.2」对「Bump the version」）、
调换顺序、多一步都算同一类；另一件事（读 bug、复现、写回归测试）、只有两步、三步里只有
一步相同都不算。不调模型，不在入口上算，每小时在控制台那台电脑上跑一次。

**提示只在开一段对话时出现，人只被问一次。**

- 发现重复：在 `agent_growth_hints` 记一行（这类事的步骤、问人的请求和措辞、人的回答、入口
  显示过几次、为它沉淀了什么）。
- 问人：待决策里问一次「「X」这类事已做了 3 次以上，要沉淀下来吗？」，选项「只记下这串
  步骤 / 做成能跑的脚本 / 不用」，说明里写清每个选项让 FLA 做什么、人怎么确认（脚本：到
  Agents → 应用点「确认」，会打开终端，输入应用名）。这句说明会随人的回答一起转给 FLA。
  同样措辞的请求还开着时，之后每小时不再碰图谱服务；措辞变了先撤回旧的（只撤没人回答过的）
  再提新的，人已经回答或关掉的旧请求不再换措辞重问（每小时那次先读回答再问）。旧请求不是人
  关的、是系统关的（例如 FLA 提出工作流时自动撤回，或别处撤回），也一样不再重问：FULI 分不出
  是谁关的，宁可少问一次。0.29 测试版那种「做成脚本 / 做成 Agent App」的旧请求，没回答的撤回
  一次，人已经选过的照用（两个都算「做成能跑的脚本」，「不用」就是不用），不再问；一条旧回答
  只用在一个重复上（重启后也一样，看哪个重复已经记着这条请求），其余相似的重复照常问。
- 告诉 FLA：它在这个项目**开一段新对话**时，入口多一个 `fla_growth.repeated`（约 258 字符），
  同一段对话后面的消息不再带，一个重复最多带两段对话；人回答了就换成人的决定（选脚本：交
  Agent 应用；选只记步骤：入口带上那串步骤的原文，让 FLA 原样提出工作流），再最多带两段对话；人选「不用」就
  不再出现。
- 沉淀了就停：FLA 提出的工作流只要和这个重复是同一类事，就把它记为已沉淀（不相关的提案
  不算）；人拒绝那个提案，重复就回来。FLA 提出后，还开着的那条待决策自动撤回，人只在 FLA
  页上确认一次；人先前已选「只记下这串步骤」的，只有**新建**的工作流（第一个版本，之前没有
  生效版本）、而且步骤和人选的那串**一一对应**（条数相同、顺序相同、每条相同，只忽略首尾空白、
  多余空格和大小写，不做模糊匹配）时，才直接按人的选择确认，不用再点，返回值写明「按你在
  待决策里的选择确认」。多了步骤（比如加上 push tag、deploy to production）、改了一步（run
  unit tests 换成 skip unit tests）、换了顺序，或者是改动已有工作流，都不自动确认：照常等人在
  FLA 页确认（改动时页上新旧步骤并排），返回值的 `note` 写明没有自动确认和原因。数据格式不变，历史里的决定仍记为人做的。人选
  「做成能跑的脚本」后 FLA 交了 Agent 应用，也算已沉淀：算谁的、哪个项目的，看提交时任务令牌
  所属的 FLA 和项目，不信调用方自己传的 agentId，也不跨项目；传了 agentId 却和令牌所属的 FLA
  不一致，提交本身就被拒（#1085 的 `callingAppOwner`），也就不记。现在交任何一个应用，会把这位
  FLA 在这个项目里所有选了「做成能跑的脚本」的重复一起记为已沉淀：应用和重复之间没有现成的对应
  关系（应用清单里没有步骤，重复的提示也没有可回传的标识），要做到只清对得上的那一个得加字段，
  这一轮没做。
- 入口不付迁移的代价：入口先只读，有提示才写一行；库还是旧格式时入口什么都不带，迁移由
  每小时那一次或控制台来做（`store.current`）。

**下次真的被带上。** 开一段对话的那一轮，入口在 `fla_growth.workflows` 里列这位 FLA 在这个
项目里**已确认**的工作流（最多 3 个，名字和用途的第一句，最长 120 字；最多约 888 字符），
步骤按需 `read_agent_workflow`。待确认的提案不列，不会被说成「在用」。用完
`record_agent_workflow_run`；走不通记 `stopped` / `failed` 并写原因。控制台工作流卡片显示
「用过 N 次，跑通 M 次」，按运行记录数，没跑过就不显示。

**沉淀成什么、放哪：**

- 步骤 → 工作流，用现有的 `propose_agent_workflow`。保留原有的口径：提出来是
  `proposed`，人在控制台确认才 `active`，`read_agent_workflow` 和
  `record_agent_workflow_run` 都只认 `active`（`src/agent-workflows/port.js`）。
- 反复执行的命令或操作 → 这位 FLA 名下的 Agent 应用（`submit_agent_app_version`，
  `runtime.entry`、不常驻）。**不新造脚本存储**：Agent 应用已经是「FLA 名下、带说明、
  有版本、能跑、留运行记录」的那一件东西，安全边界也已经定死（见下）。
- 工作台：这位 FLA 的工作流（含确认、不要、停用按钮和运行次数）在它的 FLA 页上；脚本
  （Agent 应用）在 Agents → 应用总览。本轮没有新做 widget，两处的数据都已有接口
  （`GET /api/agent-workflows`、`GET /api/work-surfaces`），由 FLA 页的负责人决定放法。

**脚本的安全边界**（全部沿用现有机制，不放宽）：

- 存在哪：`<dataDir>/agent-apps/packages/<appId>/<version>/`，版本不可变，按摘要定身份。
- 谁能运行：只有本机的人在终端 `fuli app approve <appId> <version>` 里输入应用名确认过
  的那个摘要。控制台点一下不算人确认（`src/agent-apps/run-gate.js`）。
- 运行前人看得到内容：确认的是具体版本的摘要，包文件在确认前就落盘可读。
- 不自动执行别的电脑或别的 FLA 的脚本：运行闸门每次启动都重验，跨电脑的决定一律被
  `refuseRemoteDecision` 拒掉（`src/http/request-policy.js`）；格式更新待确认时的只读会话
  连任务都不记，更不会运行。
- 不把密钥写进脚本：应用能拿到的工具是白名单里的五个，环境变量被清空到
  `FULI_APP_*`（`src/agent-apps/trusted-runner.js`、`host-tools/catalog.js`）。
- 本版本没有系统级沙箱，这一点 `docs/agent-apps.md` 已经写明，本轮不改也不淡化。

**留不留由人定**：工作流沿用「提出 → 人确认」；应用沿用「提交 → 人在终端确认」。都不
改口径。控制台上看得到新沉淀了什么、用过几次；没用上的不显示成在用，没跑过的不显示
结果。发现重复但 FLA 没去沉淀，只是下次再提示一次，FULI 不替它建一个。

## 三、「我已经说过了」是沉淀信号

Jevons 11-24：用户说「我已经…了，为什么你不…」「上次就说过」「不是讲过了吗」「怎么又…」，
说明这件事本该被记住。和「记住」「以后都」同一处识别（任务入口，
`src/graphiti/task-repeat-signal.js`，与 `task-remember.js` 并排），不调模型，只看人自己的
原话（去掉宿主注入的提醒和粘贴的报告）。

先去掉不是这个人自己说的话：宿主注入的块、引号（"…" “…” 「…」 『…』）和代码里的内容、
日志行（时间戳或 ERROR/WARN/INFO 开头）、「日志：/工单：/报告：/反馈：」这类标签后面、
「X 说：/问我：/写道：」和 "X wrote:/said:" 后面（X 不是「我/你」）。再跳过谈论这些词
而不是在说的句子（如果、假如、帮我写、匹配、正则、regex、write a test）。

只看句子的骨架，不列动词表（前两轮往正则里加动词和句式，评审每次换一批真实说法仍然漏）。
一条消息里，同一句或相邻两句同时有两半，就算候选：

- 前半，说话人自己之前做过或说过：「我」（不是「跟我/让我」）后面不远处有已经、都、明明、
  早就、刚、之前、上次、前面、…过、说了/讲了/告诉你了、不是；或者省略主语、从分句开头就是
  「（早就/之前…）跟你/给你/让你/告诉你…过/了」「不是说/不是让你…」；「又」只在同一分句里
  前面有「你」（中间最多隔几个字）或是「又把/又给我」时才算。英文：I already / I told you /
  I said / I asked you / I mentioned、as I said、didn't I、主语是 you 的 again。
- 后半，责问或指出没照做：为什么/为啥/怎么/咋/干嘛（「你」可省略，中间可隔几个字，但不能是
  「你的」、英文词或「他/老板/PM…」这类第三方）+ 不/没/还/又；或不带疑问词的「你还/你又/
  你还是/你老是…」「还是不/还是没」。英文：why don't/didn't/are/is … you/it、you still、
  yet you、but you still/didn't、you … again。
- 「不/没/还/又」后面是什么动词、中文还是英文，一概不看。
- 前半特别明确时（「我」或省略主语的分句开头 + 已经/之前/前面/明明/昨天/上次/上周… + 说过/
  交代/强调/约定/提醒/让你…），后半放宽：同一句或相邻句里有对「你」的为什么/为啥/怎么（不是
  「你怎么看」）或一个「又」就够（「我前面明确说过只改 src 目录，你为啥去改 test」「我昨天专门
  交代了 PR 描述要写中文，今天又是英文」「又把 .env 提交上去了，之前强调过的」）。只在这种前半
  下放宽，不全局放宽。

少数固定说法本身就是两半：「我已经说过了」「我说过别…」「我跟你说过」（后面不是「的」）、
「早就跟你讲过」「不是跟你说过（…吗）」「都说了别…」「说好的…呢」「上次不是说好了」
「上次就说过」「（我）不是让你…吗」「说了多少遍/三遍/八百遍」（前面要是「我」或分句开头，「他已经说了好几次了」
不算）、「你又…/你老是…」（「你又不是人」「你又没错」不算）、「又忘了」「上次你就是这么…」
「第三次了，别…」「又来了，还是…」；英文 "I told you"、"I said no"、"how many times"、
"you keep forgetting"、"we talked about this"、句首 "Again,"。「我…吗？」是人在问自己，
跳过，除非句子里有「跟你/让你」或下一句就是责问（「我已经说过不要用 any 了吗？你怎么还用」）。

一定不成为候选（测试里逐条）：说话人是第三方（「PM 说：…」，说话人和「说」之间有空格也算；
「老板：…」；「老板已经说过三遍了」「他已经跟你说过两遍了」「他为什么还不改」）、引用块、
代码块、日志、带标签的粘贴（「日志：/反馈：…」）、条件句和请求句（如果…、帮我写…）、只有一半
的话（「为什么这里不用 Redis？」「我已经提交了代码，你看一下」「你怎么还没回复」）、报故障的
「怎么又报错了？」「怎么又卡住了」「测试又红了」（单独的「又」不算前半）。

**取舍：命中只是候选，由读入口的 AI 判断。** 骨架一样、意思不同的话也会成为候选，例如「我已经
看过你的方案了，你为什么不用 Redis？」「我已经吃过了，为什么你不吃」；测试里单独列成「候选但
预期 AI 忽略」一组。宁可多给 AI 一段 512 字符的提示让它判断，也不漏掉人最常说的原话；误报不会
让这一轮多花一次 checkpoint（见下）。例外是单独的「又」：报故障是最常发的话，所以省略了「你」、
只有一个「又」的说法（「咋又用 npm 了」）不算，换来「怎么又报错了」这类不再成为候选。

命中时：入口带 `remember_guidance`（512 字符，上一轮 513，再上一轮 787；只在命中的那一轮），
开头就是「他可能是在说之前交代过、你没照做；先判断，不是就当没看到，什么都不做」。**命中不改变
这一轮的收尾方式**：`checkpoint_required` 照旧（有 Stop hook 的客户端仍然自动收尾，测试
`a candidate the Agent does nothing about closes as usual`）；只有 AI 判断确实是重复、用
`checkpoint_task_knowledge remember` 存了待确认项，才走 checkpoint。规则全文在
`task_guidance.repeat_signal`，要点：

- 其实不是在抱怨之前说过的事，就当普通消息，不记、不问；
- FULI 里已有同样的内容，就不重复存，一句话说明这次为什么没生效（没下发 / 范围不对 /
  下发了但没照做），最后一种写进 checkpoint 的 `workLog`；
- 没有，就这一轮用 `checkpoint_task_knowledge` 的 `remember` 记下，原话作 `quote`；拿不准
  是这个项目还是所有地方，用 `scope: unsure`，不去问人；
- 回复里一句话说「先记成一条待你确认的」和用在哪，不能说成「已记住」或「已生效」
  （存下来的是待确认，`task-remember.js`）；
