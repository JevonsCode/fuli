# FULI 0.27.9

0.27.9 发在 `latest` 渠道。两件事：设置页默认用「左侧分类」布局；另一台电脑派来的活，现在认得项目自己仓库的那份检出，认不出时会说清是哪种认不出。没有数据格式变化。

0.27.9 is on the `latest` channel. Two things: the settings page opens with the topics on the left, and work sent from another computer now takes a checkout of the project's own repository for the project's, and says which kind of "not found" it is when it does not. No data format change.

## 更新内容 / What's new

设置页有两种布局，之前默认是顶上一排标签。用了几天，左边一列分类更顺手，于是它成了默认；喜欢标签的，开关还在原地，切过去就一直记着。

另一件：你的项目文件夹明明就在那，FULI 却说「没有仓库」。它其实是没把那个仓库认成这个项目的，却懒得说清楚。现在它会按项目登记的仓库地址去认，认不出时也老实说是「有仓库，但没认成这个项目的」。

The settings page has two layouts, and tabs on top used to be the default. After a few days the column on the left proved handier, so it is the default now. If you prefer the tabs, the switch is where it was, and your choice is kept.

The other one: your project folder was right there, and FULI said "no repository". It had not taken that repository for this project's, and did not bother to say so. Now it goes by the repository address the project records, and when it still cannot tell, it says so: "a repository, but not taken for this project's".

## 改了什么

- **设置页默认「左侧分类」**：两种布局都保留，开关位置不变。选过「顶部标签」的人照旧；窄窗口仍然显示顶部标签。
- **派来的活认得项目自己的仓库**：共享的文件夹（或其中以项目命名的子文件夹）是项目登记的仓库的一份检出时，就在那里做，即使 FULI 没法把这个文件夹唯一对到这个项目（比如两个项目登记了同一个仓库）。临时项目和已归档项目不算。
- **新的失败原因**：文件夹里有仓库、但 FULI 没把它认成这个项目的，写的是「有仓库，但没认成这个项目的」，不再写「没有仓库」。这种失败不计入对方的次数。

## In English

### Changed

- **The settings page opens with the topics on the left.** Both layouts stay and the switch does not move. A person who chose the tabs keeps them; a narrow window still shows the tabs.
- **Work sent over finds the project's own repository.** When the shared folder (or the child folder named after the project) is a checkout of a repository the project records, the work is done there, also where FULI cannot name one single project for that folder (two projects recording the same repository, for example). Temporary and archived projects do not count.
- **A new failure reason.** A folder that holds a repository FULI does not take for the project's is reported as that, no longer as "no repository". Such a failure is not counted against the requester.

## 已知限制 / Known limits

- 第二项修复针对的是一台 Mac 上的实际失败（文件夹里有项目的仓库，却回「没有仓库」）。那台 Mac 上为什么认不出还没有查实；这次改动覆盖了最可能的两种原因，**修复后的版本还没有在那台 Mac 上跑过**。
- 同一个仓库在本机有两份检出时，活会在共享的那一份里做。
- 0.27.8 的 PATH 修复同样还没有在那台 Mac 上从访达启动验证过。
- 两台真电脑之间还没有一件活完整跑完。其余限制同 0.27.8。

- The second fix answers a real failure on one Mac (the folder held the project's repository, and the answer was "no repository"). Why that Mac did not recognise it is not established; this change covers the two most likely causes, and **the fixed version has not run on that Mac yet**.
- Where one repository has two checkouts on a computer, the work is done in the shared one.
- The PATH fix of 0.27.8 has not been checked on that Mac from a Finder start either.
- No piece of work has run to the end between two real computers yet. The other limits are those of 0.27.8.
