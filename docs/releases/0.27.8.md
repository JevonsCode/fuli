# FULI 0.27.8

0.27.8 发在 `latest` 渠道。只修一件事：在 Mac 上从访达或程序坞启动的 FULI，找不到装在用户目录下的 Claude Code 和 Codex，于是叫不醒任何助手。没有数据格式变化。

0.27.8 is on the `latest` channel. It fixes one thing: a FULI started from Finder or the Dock on a Mac could not find Claude Code or Codex installed under the home folder, so it could wake no assistant. No data format change.

## 更新内容 / What's new

你的终端知道 `claude` 在哪，FULI 却不知道：Mac 上双击图标启动的应用，拿到的是一份很短的 PATH，里面没有你的用户目录。于是另一台电脑来问问题，FULI 环顾四周，说「这里没有能用的客户端」。现在它找不到时会去问一声你的登录环境。

Your terminal knows where `claude` is; FULI did not. An app started by double-clicking on a Mac gets a short PATH without your home folder in it. So when another computer asked a question, FULI looked around and said there was no client here. Now, when it cannot find one, it asks your login environment.

## 修复

- **Mac 上叫不醒助手**：别的电脑来提问时回「没有客户端」，派来的活回「没有能受限运行的客户端」。原因是 FULI 只在自己的 PATH 里找 `claude` 和 `codex`，而从访达启动的应用 PATH 只有四个系统目录。现在找不到时会问一次登录 shell 的 PATH，在那里找，并带着这些目录启动客户端，这样客户端自己要用的程序（比如 node）也找得到。
- 这次询问最多 4 秒，结果记 5 分钟。命令本来就在 PATH 里的电脑不会多启动任何东西；Windows 不受影响。

## In English

### Fixed

- **No assistant could be woken on a Mac.** A question from another computer was answered "no client", and work sent over "no client that can run it restricted". FULI looked for `claude` and `codex` on its own PATH only, and an app started from Finder has a PATH of four system folders. When it finds nothing it now asks the login shell for its PATH once, looks there, and starts the client with those folders added, so the programs the client starts itself (node, for example) are found too.
- The question takes four seconds at most and its answer is kept five minutes. A computer where the commands are already on the PATH starts nothing extra; Windows is not affected.

## 已知限制 / Known limits

- 这个修复依据的是一台 Mac 上的实际情况（后台服务的 PATH 只有四个系统目录，两个命令行都在用户目录下的 `.local/bin`），并有自动测试；**修复后的版本还没有在那台 Mac 上跑过**。
- 用 fish 作登录 shell 时按 sh 来问，可能拿不到 fish 里才设置的目录。
- 两台真电脑之间还没有一件活完整跑完。其余限制同 0.27.7。

- The fix rests on what one Mac actually showed (the service's PATH was four system folders, both command lines under `.local/bin` in the home folder) and on automated tests; **the fixed version has not run on that Mac yet**.
- With fish as the login shell the question is asked as sh, which may miss folders set only in fish.
- No piece of work has run to the end between two real computers yet. The other limits are those of 0.27.7.
