# FULI 0.27.17

0.27.17 发在 `latest` 渠道。测试版里的「运行机」带着 **Beta** 标签进了正式版；每段对话都能查到是哪个客户端、哪个会话写的；开任务快了将近一半。圆桌数据和图谱各自动升级一次，不用你确认；升级后不能直接退回 0.27.16（见「数据格式」）。

0.27.17 is on the `latest` channel. Runners, from the beta, join the stable release with a **Beta** label; every part of a conversation can be traced to the client and session that wrote it; task entry is nearly twice as fast. The roundtable data and the graph each upgrade themselves once, with nothing to confirm; after the upgrade you cannot go straight back to 0.27.16 (see Data format).

## 更新内容 / What's new

0.29.0-beta.1 到 beta.8 里试过的东西，这一版都带上了。还在测试的入口标了 Beta：用得了，但做法和样子还可能变。

Everything tried in 0.29.0-beta.1 to beta.8 is in this release. Entries still in testing carry a Beta label: they work, but how they work and look may still change.

## 改了什么

- **运行机（Beta）**：另一台电脑可以当「运行机」，上面的 Codex、Cursor 等客户端都用这台电脑的 FULI，知识和记忆只存一份。在主机上运行 `fuli runner invite`，把打印出的那一行在另一台电脑上运行；不想用了就 `fuli runner leave`。
  - 运行机通过 MCP 和圆桌发起的请求，在主机上一律只读；被撤销就立刻停用，还没送到的记录留着。
  - 主机不在时，运行机约 5 秒内应答，任务记录先排队，连上后补交、只记一次。
  - 在运行机上打开复利，看到的就是主机的控制台，能做的和你在主机上一样；只有运行机和局域网配对、主机自己的客户端，只能在主机上改。「客户端接入」里是运行机自己的客户端。运行机不会被意外改成一套空的 FULI。
  - 没配对运行机的电脑什么都不多做。
- **Beta 标签**：运行机的配对通知、局域网圆桌和运行机自己的页面上，有统一的小 Beta 标签，鼠标移上去会说明它的意思。
- **对话能溯源**：每段对话记下写过它的客户端、原生会话、模型、目录和分支；读对话记录时，每条消息都写明是谁写的。同一位 FLA 最近在别的客户端干过活，开任务时会提一句（只说明最近有动静，不代表那边还开着）。
- **开任务更快**：开任务时的知识召回不再为每次搜索读一遍整张图谱。在一台主机上实测，Codex 开一次任务从 15.7 秒降到 7.7–8.8 秒。
- **客户端卡片列全六项**：MCP、自动进入与收尾、Skills、全局说明、权限白名单、/fla 菜单。装好的打勾，要更新的提醒，客户端不支持的打叉，鼠标移上去说明少了它会怎样。
- **手动添加的客户端也能装 Skill**：「添加客户端」多了一个可选的 Skill 文件夹。
- **点名会话的圆桌消息只给那个会话**：圆桌消息点名了某位 FLA 的一个原生会话时，只有那个客户端和会话（或 FULI 实际送到的会话）看得到、答得了；同一位 FLA 在别处不能抢先答，害得被点名的会话被告知「已经答过」。圆桌记录里写清点名的会话、实际送到哪、谁答的。
- **更新提示的小红点跟着「检查更新」走**：关掉「接收测试版」或点「检查更新」，顶栏的小点马上跟着变；控制台开着时每小时再查一次。

## In English

### New

- **Runners (Beta).** Another computer can be a runner: its Codex, Cursor and other clients use this computer's FULI, with one copy of knowledge and memory. Run `fuli runner invite` on the host and the printed line on the other computer; `fuli runner leave` ends it.
  - A runner's MCP and roundtable asks stay read-only on the host; a revoked runner stops at once and keeps what it had not sent.
  - With the host away a runner answers in about 5 s and queues checkpoints, delivered once later.
  - Opening FULI on a runner shows the host's console, which does what you could do at the host, except that runners, LAN pairing and the host's own clients change only on the host. Its 客户端接入 lists the runner's own clients. A runner is never turned into an empty FULI of its own.
  - A computer without a runner does nothing extra.
- **Beta labels.** The runner pairing notice, the LAN roundtable and the runner's own page carry one small Beta label; hover it for what it means.
- **Conversations can be traced.** Each conversation keeps the client, native session, model, folder and branch that wrote it, and reading its history names the writer of every message. When the same FLA recently worked in another client, task entry says so (recent activity, not proof that session is still open).
- **Faster task entry.** Task entry's recall no longer reads the whole graph for each search. Measured on one host: a Codex task entry went from 15.7 s to 7.7–8.8 s.
- **Client tiles list all six parts**: MCP, auto start and close, Skills, instructions, allowlist and the /fla menu, with a check, a warning or a cross; hover a cross to see what is lost.
- **Skills for clients added by hand.** 「添加客户端」 takes an optional Skills folder.

### Fixed

- **A roundtable ask that names a session goes to that session.** When an ask names one native session of an FLA, only that client and session, or the one FULI delivered it to, sees and answers it; the same FLA elsewhere can no longer answer first and leave the named session told it was answered. The thread shows the named session, where the ask went and who answered.
- **The update dot follows 「检查更新」.** Turning 接收测试版 off or checking for updates moves the dot in the header at once; an open console checks again every hour.

## 已知限制 / Known limits

- **配对的运行机算你自己的电脑**：在它上面打开的控制台能做你在主机上能做的事，它报给主机的会话也按本机会话处理。只和你信任的电脑配对，不用了就在主机上撤销（`fuli runner revoke`）。
- 运行机还在 Beta：Windows 上的运行机还没在真的第二台电脑上试过；从运行机唤醒的 Claude 不加载你的钩子，偶尔可能接不上任务（不会以更大的权限运行）。
- 新开一个客户端会话时，FLA 还不会自己接回另一个客户端里的对话：它会看到提示，接回仍要它调用接续。
- 正在用 0.29.0-beta.8 的电脑版本号比 0.27.17 高，不会收到这次更新；溯源和小红点的修复要等下一个测试版。
- **Mac 上每次更新 FULI 后，系统已存的文件夹许可就对不上新版本了**；根上的原因是 Mac 版还没有稳定的签名身份。
- 其余限制同 0.27.16。

- **A paired runner counts as your own computer**: the console opened on it does what you could do at the host, and the sessions it reports are treated as the host's own. Pair only computers you trust, and revoke one on the host (`fuli runner revoke`) when you stop using it.
- Runners are still Beta: Windows runners have not been tried on a real second computer, and a Claude woken from a runner loads none of your hooks, so it may occasionally fail to pick a task up (it never runs with more rights).
- A new client session does not yet resume another client's conversation by itself: the FLA sees the hint and still has to resume it.
- A computer on 0.29.0-beta.8 has a higher version than 0.27.17 and is not offered this update; tracing and the update-dot fix reach it with the next beta.
- **On a Mac, after every update of FULI the folder permission the system stored no longer matches the new version**; the root cause is that the Mac build has no stable signing identity yet.
- The other limits are those of 0.27.16.

## 数据格式 / Data format

- **圆桌数据**在第一次启动时从第 11 版升到第 13 版（记下由哪台运行机发起、是否来自另一台电脑，以及消息点名的会话），自动完成，升级前先备份。之后 0.27.16 读不了它，退回要用那份备份。0.29.0 的测试版是第 12 版，下一个带这次修复的测试版会再升一步。
- **图谱**从格式 21 升到 22：`graph/22-conversation-provenance` 新增每段对话的会话记录（客户端、会话、模型、目录、分支、首末时间）和它的索引，不改任何已有记录，自动完成，不用确认。图谱没有自动备份：升级后退回 0.27.16，旧版本不认格式 22 的图谱，要升回来或用你自己在更新前做的备份。
- **运行机的两份存储**（`runner/host.sqlite`、`runner/runner.sqlite`）只在用运行机时创建；用过测试版的会从 beta 的格式自动升级。

- **The roundtable data** goes from format 11 to 13 on first start (which runner sent an ask, whether it came from another computer, and the session an ask named), by itself, with a backup first. 0.27.16 cannot read it afterwards, so going back needs that backup. The 0.29.0 betas are at format 12; the next beta with this fix moves one more step.
- **The graph** goes from format 21 to 22: `graph/22-conversation-provenance` adds each conversation's session records (client, session, model, folder, branch, first and last seen) and their indexes, changes no record, completes by itself and asks for no confirmation. The graph has no automatic backup: after the upgrade, going back to 0.27.16 leaves an older version that does not accept a graph at format 22, so upgrade again or use a backup you made before updating.
- **The two runner stores** (`runner/host.sqlite`, `runner/runner.sqlite`) are created only when you use runners; ones a beta made upgrade from its format by themselves.
