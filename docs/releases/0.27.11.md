# FULI 0.27.11

0.27.11 发在 `latest` 渠道。修一件事：撤回的活在那台电脑上没清干净时，FULI 不再说「已删除」，会写明原因，并且自己再试。没有数据格式变化。

0.27.11 is on the `latest` channel. It fixes one thing: when a request that was taken back is not fully cleared on that computer, FULI no longer says "removed"; it names the cause and tries again by itself. No data format change.

## 更新内容 / What's new

0.27.10 的撤回第一次在两台真电脑之间跑了：活是撤回了，但那台电脑清理副本时卡了一下，十分钟后才清掉。这十分钟里卡片却写着「副本和分支已删除」。这一版让它说实话：没清掉就写没清掉、为什么，然后每分钟自己再试，不用等人打开页面。

The first real withdrawal between two computers on 0.27.10 worked, but clearing the copy on that computer stalled and only went through ten minutes later. For those ten minutes the card said "its copy and branch were removed". This version makes it tell the truth: not cleared, why, and it tries again every minute without anyone opening the page.

## 改了什么

- **卡片说实话**：撤回的活，副本或分支还没删掉时，卡片写「还没删掉，原因见下面的经过」；删掉了才写「已删除」。
- **失败写明原因**：清理失败时，经过里会多一句原因：Git 迟迟没有回应、没能启动 Git、Git 报错、有个文件夹不是原来那个了、要删的文件夹不在该在的位置、有文件删不掉（被占用或没有权限）。只有那台电脑的主人看得到，不带 Git 原文和路径。
- **服务自己重试**：一件已结束的活清理失败后，FULI 大约每分钟自己再试一次，最多试一天，一次只跑一轮；清理里的每一步 Git 都限 15 秒，不会被一个不回应的 Git 一直拖住。以前要等有人打开列表或卡片才会再试。
- 给发起方助手的提示不再把「已删除」说成既成事实。

## In English

### Fixed

- **The card tells the truth.** For a request that was taken back, the card says the copy or branch is not removed yet while that is so, and "removed" only once it is.
- **A failed removal names its cause** in the request's history: Git did not answer in time, Git could not be started, Git reported an error, a folder is not the plain folder it was, a folder to delete is not where it should be, or some files could not be deleted (in use, or no permission). Only that computer's owner sees it; it carries none of Git's text and no path.
- **The service retries by itself.** After a failed removal of a request that has ended, FULI tries again about every minute, one pass at a time, for up to a day; every Git step of a removal is stopped after 15 seconds, so a Git that does not answer cannot hold it. Before, it waited for someone to open the list or the card.
- The guidance the requester's assistant gets no longer states the removal as done.

## 已知限制 / Known limits

- 0.27.10 那次清理为什么卡住没有查实（那台 Mac 上 Git 在项目文件夹里 15 秒没有回应，十分钟后正常）。这一版之后再出现，经过里会写明是哪一种原因。
- 主人自己点「丢弃 / 留下」时清理失败，仍然只提示一次，不会自动重试（和以前一样）。
- 控制台里还没有「撤回」按钮，现在只有助手能替你撤。
- 其余限制同 0.27.10。

- Why the removal stalled on 0.27.10 was not established (on that Mac, Git did not answer in the project folder for 15 seconds, and was fine ten minutes later). From this version on, the history names the cause when it happens again.
- A removal that fails after the owner's own Keep or Discard is still reported once and not retried (as before).
- The console has no "take back" button yet; for now an assistant does it for you.
- The other limits are those of 0.27.10.

## 数据格式 / Data format

没有变化。

No change.
