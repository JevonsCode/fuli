# FULI 0.27.14

0.27.14 发在 `latest` 渠道。大半是修复，另有三件新东西：账单里的两个数字点得开了，客户端列表的最后多了一个「添加客户端」，**项目招人前默认不再先问你（已有的项目也一样，见下）**。图谱格式和模型用量记录库各自动升级一次，都不用你确认。

0.27.14 is on the `latest` channel. Mostly fixes, with three new things: the two numbers in the statement open into their rows, the client grid ends with 「添加客户端」, and **a project no longer asks you before a hire by default (existing projects too, see below)**. The graph format and the model usage record each upgrade themselves once, with nothing to confirm.

## 更新内容 / What's new

这一版的大半是在 Mac 上用出来的：账单弹窗一打开，「上一周」套着一圈粗黑框；顶栏的模型图标隔一会儿红一次，刷新就好；笔记本换了个网络回来，另一台电脑再也找不到它。

Most of this version came from using FULI on a Mac: the statement dialog opened with a thick black frame around 「上一周」; the top bar's model button turned red now and then and a refresh cleared it; a laptop came back from another network and the other computer could not find it again.

## 改了什么

- **账单里的两个数字可以点开**：「带上习惯的对话」和「新学到/确认的记录」各自列出这一周对应的那几行。
- **弹窗打开时不再给第一个按钮画框**：第一个控件是输入框时焦点仍然落在它上面；是按钮时落在弹窗内容上，按一下 Tab 就到第一个按钮，键盘照常能用。
- **手动添加的客户端和其他客户端一样接入**：「设置 › 客户端」的列表最后是「添加客户端」；加进来的客户端由 FULI 写入接入配置，之后跟着一起更新。配置文件必须在你的用户目录里，不能是已有客户端的那个文件（填错了弹窗会直接说要什么样的文件）；添加这一步只能由你本人在页面上做，助手不能代做。移除时 FULI 会把自己写进去的那一项一并拿掉。
- **Jefa 在任务入口来不及回答，不再算它的失败**：任务入口只给看板匹配 3 秒，不少模型答一次就要两三秒。以前每次被掐断都记成 Jefa 的任务失败，顶栏就红了。现在调用方自己缩短时间造成的超时不算；在它自己的时间内超时、或其他失败，仍然算。
- **项目默认不再「招人前先问」**：Bole 需要新助手时直接招，不再每次等你点确认。**已有的项目也一起改了，包括你以前特意打开过询问的**；想让它先问，到项目的设置里把「新 Agent 先询问」重新打开。只改队伍、不提这个开关的保存，不会动它。已经在等你确认的招聘照旧等你。
- **Bole 招人前先看有没有闲着的**：同一个项目里已经有同职业、手上没活、能力够的助手时，直接把活交给他，不再新招。你关了「自动复用」，或这次招人写了具体要求，就照旧新招。
- **从话题长出来的新项目，开始时只有负责人一个**，不再先配一个固定班子。
- **四个固定角色（Jefa、Bole、Tonborg、Astro）规则一致**：Tonborg 也不能被归档或停用了；Jefa 的职责说明改成它实际做的事（拆解目标、维护看板与进展）。
- **局域网圆桌**：电脑的地址暂时不在（比如换了网络）时，协调端每 30 秒看一次，地址回来就自己恢复，不用关掉再打开（那样会撤销所有配对）。你关掉圆桌之后，正在进行中的启动不会再把它打开。

## In English

### New

- **The two numbers in the statement open.** "Conversations that carried your habits" and "records learned or confirmed" each list their rows for that week.
- **A client added by hand connects like the others.** The grid under Settings › 客户端 ends with 「添加客户端」; FULI writes the connection entry for a client added there and keeps it updated. The configuration file must be inside your home folder and must not be a listed client's own file (the dialog says what the file has to be when it is refused); adding one is done by you on the page and cannot be done by an assistant. Removing the client also removes the entry FULI wrote.
- **A project no longer asks before a hire by default.** Bole hires when a new assistant is needed instead of waiting for your confirmation each time. **Existing projects change too, including one where you had turned asking on deliberately**; to have it ask, turn 「新 Agent 先询问」 on again in the project's settings. A save that only changes the team and does not mention the switch leaves it alone. Hires already waiting for you still wait.
- **Bole looks for someone free before hiring.** An assistant already on the project with the same occupation, nothing under way and the needed capabilities takes the task. With reuse switched off, or when the hire states its own requirements, Bole hires as before.
- **A project grown from a topic starts with its lead alone.**

### Fixed

- **A dialog no longer draws a frame around its first button on opening.** When the first control is a field the focus still goes to it; when it is a button the focus goes to the dialog's content, and one Tab reaches the button.
- **Jefa running out of time at task entry is not its failure.** Task entry gives the board match 3 seconds and many models need two or three to answer. Each cut-off was counted as Jefa's task failing, which turned the top bar red. A timeout under a limit the caller tightened no longer counts; a timeout within the role's own limit, and any other failure, still do.
- **The four fixed roles follow one set of rules.** Tonborg can no longer be archived or switched off; Jefa's description says what it does.
- **LAN roundtable.** While the computer's address is away (another network, for one) the coordinator looks every 30 seconds and returns by itself once the address is back, with no off and on (which revokes every pairing). After you turn the roundtable off, a start that was under way no longer turns it back on.

## 已知限制 / Known limits

- **Mac 上每次更新 FULI 后，系统已存的文件夹许可就对不上新版本了**，派来的活、清理和唤醒助手会等不到 Git。根上的原因是 Mac 版还没有稳定的签名身份，这一版没有解决。
- 局域网圆桌「地址回来就自己恢复」和「关掉就是关掉」只有自动化测试，还没在两台真电脑之间看到。
- Jefa 那一项是在一台 Mac 上遇到的，修复只有自动化测试；任务入口的 3 秒本身没有改。
- 不再先问之后，关掉「自动扩充团队」的项目里长期助手的数量没有上限（32 人的上限属于自动扩充）；招人时也不再顺带问新助手用哪些起步包，要到助手页上设置。
- 其余限制同 0.27.13。

- **On a Mac, after every update of FULI the folder permission the system stored no longer matches the new version**; requests, cleanup and waking an assistant then wait for a Git that does not answer. The root cause is that the Mac build has no stable signing identity yet; this version does not solve it.
- The LAN roundtable returning by itself, and staying off once turned off, are covered by automated tests only and have not been seen between two real computers.
- The Jefa item was met on one Mac and its fix is covered by automated tests only; the 3 seconds at task entry are unchanged.
- With asking off, a project whose automatic team growth is also off has no cap on durable assistants (the cap of 32 belongs to team growth); and a hire no longer asks which starter kit the new assistant uses, which is set on the assistant's page instead.
- The other limits are those of 0.27.13.

## 数据格式 / Data format

图谱从格式 20 升到 21。`graph/21-confirm-before-hiring` 只多一个可以存的字段（项目招人前要不要先问），不改任何记录，自动完成，不用确认；以前存的那个值留在原处，不再读取。图谱没有自动备份：升级后退回 0.27.13，旧版本不认格式 21 的图谱，要升回来或用你自己在更新前做的备份。

模型用量记录库在第一次启动时自动升级（3 → 4，记下每次调用是不是被调用方缩短了时间）。升级前会自动备份；升级后退回 0.27.13 需要用备份才能打开这个库。

The graph goes from format 20 to 21. `graph/21-confirm-before-hiring` only adds one field that can be stored (whether a project asks before a hire), changes no record, completes by itself and asks for no confirmation; the value stored earlier stays where it is and is no longer read. The graph has no automatic backup: after the upgrade, going back to 0.27.13 leaves an older version that does not accept a graph at format 21, so upgrade again or use a backup you made before updating.

The model usage record upgrades itself on first start (3 → 4, whether the caller of each attempt tightened the time limit). A backup is taken first; going back to 0.27.13 needs that backup to open it.
