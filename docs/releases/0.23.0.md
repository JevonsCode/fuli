# FULI 0.23.0（草稿；当前公开预览版 0.23.0-beta.4）

0.23 让不用终端的人也能装好、用好、升级 FULI：FULI 会自己体检，能修的自己修，修不了的用一句话告诉你；Windows 安装包的托盘程序换成了 FULI 桌面客户端（Beta），窗口里直接就是控制台。每个 FLA 有了自己的工作台：自己的看板和自己的工作流。下文是相对当前稳定版 [0.22.1](0.22.1.md) 的变化。新增两个本地存储，从 0.22.1 升级不需要确认迁移。
0.23 lets people who never open a terminal install, use and update FULI: FULI checks itself, fixes what it can and says in one sentence what needs you; the Windows package's tray app is now the FULI desktop client (Beta), whose window is the console itself. Every FLA gets its own workbench: its own board and its own workflows. Changes are listed against the current stable release, 0.22.1. Two new local stores; upgrading from 0.22.1 needs no confirmed migration.

## 体检：FULI 自己发现、自己修（D-76）

更新、安装或重新接入之后哪里不对，以前要你自己发现、再去终端重新 setup。现在 FULI 会自己检查这几件事：

- 某个已接入的客户端（Claude Code、Codex 等）的 FULI 连接过期了；
- 数据格式有一步迁移在等你确认，或者有数据暂时用不了；
- 打开着的会话还在用旧版 FULI；
- 上次更新还有没做完的事（例如新版装好了，但客户端还没重新连接）。

能自动处理的（重新连接你以前接入过的客户端，连接前先备份它的配置）点「自动修复」就行；需要你决定的，告诉你去哪里处理。控制台顶部会显示「有 N 件事需要你」，展开可以看到每一件和对应的按钮。

接口：`GET /api/system/doctor` 返回检查结果；`POST /api/system/doctor/repair` 只执行能自动修复的项，只接受本机请求，在 Agent 接口目录里标为 `local_user_only`。

**已知限制**：图谱服务没在运行时，图谱里等你确认的迁移步骤不会出现在体检结果里；Codex 的 Hook 信任状态没有信号，不检查；`fuli status` 还不显示版本是否过期。

## FULI 桌面客户端（Windows 安装包，Beta）

- Windows 安装包的托盘程序换成 FULI 桌面客户端（Flutter）。控制台能连上时，客户端窗口就是控制台本身（内嵌 WebView2），不用再在浏览器里打开；体检提示、修复、更新和数据格式确认都在控制台里。只有控制台连不上时（没启动、没安装、不响应），窗口才显示状态页：一句话说 FULI 现在怎样，每件需要处理的事一张卡片，配一个按钮。控制台以外的链接用默认浏览器打开。电脑上没有 WebView2 时，客户端保留状态页，用浏览器打开控制台。
- 客户端目前是 Beta：窗口标题和托盘提示写着「FULI Beta」。应用图标是圆角方形底；托盘图标是 FULI 标志加绿色、琥珀色或红色圆点；情况变差时发一条系统通知。外观和控制台一致（颜色、字号、间距由控制台主题生成）。
- 桌面和开始菜单的 Fuli 快捷方式打开它；旧的 FuliTray 托盘不再提供。
- 每个 Windows 用户只运行一个客户端，再次打开会显示已有窗口。安装后的客户端默认开机启动（只显示托盘图标），可以在托盘菜单「开机时启动」关闭。
- Update-Fuli、Rollback-Fuli 和控制台的一键更新会先关闭正在运行的客户端，完成后重新打开它；Uninstall-Fuli 会关闭客户端，并删除开机启动项。客户端正在启动、停止或换端口时，会先做完再关闭。
- 托盘菜单保留「换一个端口」；因 Windows 保留端口而启动失败时，客户端会提示使用它。
- 从 0.22 的旧托盘一键更新到这个版本时，旧托盘会退出，更新后打开的是新的桌面客户端。

**没有验证的部分**：客户端的自动测试和 Windows / macOS 构建在 CI 上通过；内嵌控制台窗口在一台 Windows 11 电脑上实际打开过；托盘、系统通知和开机启动还没有在真实桌面上完整验证。macOS 版客户端还不在发布包里（只是 CI 构建产物，未签名）；macOS 和 npm 安装照常在浏览器里使用控制台。

## FLA 自己的工作台：看板和工作流（D-78）

- 有任务或工作流的 FLA，首页第一个标签就是「工作台」；什么都没有的 FLA 不显示空工作台。
- 看板就是派给这个 FLA 的任务：都在一个项目里时用该项目自己的列，跨项目时用内置五列。任务状态跟着 Agent 的实际运行走，所以这个看板只读，点卡片看任务详情。
- 工作流：FLA 经常重复做的事，可以由它提议成自己的工作流（来自 FULI 已学到的重复模式，或它自己整理的步骤）。你在它的首页「确认」后才生效，也可以「不采用」或「停用」；每次修改都是新版本，旧版本保留。工作流不会自动执行，也不会注入上下文：Agent 先看索引（名称、用途、步数、大致 Token 数），需要时再读全文，并记录每次运行。
- 工作台只在打开这个标签时加载，离开就卸载，没有常驻进程。

## `#FLA` 叫人更直接（rec#58）

- `#FLA 姓名` 现在也能叫内置角色 Bole、Jefa、Tonborg（当前文件夹的项目里）和 Astro（全局），和 `@Bole` 走同样的检查，不扩大权限。
- `#FLA` 在消息开头或行首才算点名；句中只有紧跟「请 / 让 / 帮我 / 麻烦 / 交给」（please / ask / let）时才算，而且只接受准确的名字，不会弹出选人列表。引号和代码里的 `#FLA` 都是普通文字。已知例外：「让」后面紧跟准确名字的普通句子仍会点名。
- 叫不到时说明具体原因和怎么处理（例如「Bole 不负责这个项目，在控制台『管理负责项目』里加上」），不会悄悄换成别人。
- 控制台里 Bole、Tonborg 的负责项目现在可以保存（以前会报 `system_managed_employee`）；Astro 是全局助手，不分配项目。

## 回执链接和客户端接入（D-80）

- **`fuli://` 链接**：桌面客户端为当前 Windows 用户注册 `fuli://`。点这种链接时，客户端用 FULI 当前的端口在浏览器打开控制台对应页面；`fuli://status` 打开客户端自己的窗口。链接里没有端口，换端口后旧链接照样能用。`fuli://` 只打开页面，不做任何修改；其他主机、端口和路径穿越一律拒绝。客户端已经在运行时，链接交给正在运行的那一个。macOS 客户端在 Info.plist 里声明了这个协议，但 macOS 客户端还不在发布包里。
- **回执用哪种链接**：Windows 安装版上，本安装的客户端注册了 `fuli://` 之后（最多一分钟检查一次），回执链接写成 `fuli://…`；没有客户端、npm 安装和 macOS 照旧用 `http://127.0.0.1:<端口>/…`。
- **「关闭提醒」写明位置**：有的客户端（例如 Claude Desktop）会去掉指向本机地址的链接，只留文字。回执里的提醒现在写成「关闭提醒：设置 → 数据格式迁移」，链接点不了也知道去哪里。
- **固定的接入入口**：Windows 安装版的安装目录里多了 `FuliNode.exe`。它每次启动时读 `installation.json`，运行当前版本。Claude Code、Codex、Cursor 和 OpenCode 的 MCP 和 Hook 改为通过它启动 FULI，配置里不再写 `versions<id>` 路径，更新、回退之后不用重新接入。已有的旧配置会被体检标为过期，点「自动修复」或下次更新时改成新的写法。OpenCode 插件在加载时读取当前版本。
- **Antigravity**：作为支持的客户端出现在「设置 → 客户端」。应用和 `agy` 命令行共用 `~/.gemini/config/mcp_config.json`，FULI 只改其中的 `fuli` 一项，其他服务原样保留。只接 MCP，没有 Hook；来源名是 `antigravity`。

**没有验证的部分**：在真实的 Windows 桌面上点 `fuli://` 链接、客户端注册协议、更新和回退后的协议跟随，都还没试过；Claude Desktop、Codex、Cursor 会不会把 `fuli://` 显示成可以点的链接也还不知道。`FuliNode.exe` 在测试里实际编译运行过（参数、输入输出、退出码、版本切换），但还没在真实客户端会话里跑过。Antigravity 只用合成数据测过，没有在真实的 Antigravity 里试过。回退到 beta.3 之前的版本后，`fuli://` 链接要等较新的客户端重新注册才能用，客户端配置也会回到旧的写法，直到下次更新。

## 其他变化

- 知识检索（`search_current_project_knowledge`、`search_knowledge_graph`）新增 `view: "index"`：每条只返回标题和大致 Token 数；再用 `ids` 读选中的几条全文。默认的完整结果不变。
- 会话折叠不再按关键词挑「决定 / 纠正」句子（盲测里约 96% 是噪音），改为保留 Claude Code、Codex 自己压缩对话时写的摘要，恢复会话时按需带上。
- FULI 开始使用共享组件 [agent-session-launcher](https://github.com/JevonsCode/agent-session-launcher) 和 [agent-installer](https://github.com/JevonsCode/agent-installer)（这一版只读）：Windows 安装包内置这两个程序，其他安装方式在第一次需要时下载（固定版本和 SHA-256）；「打开会话」链接先由启动器判断能否打开，ID 含特殊字符的会话不再显示这个链接；安装器只在后台核对客户端接入状态，不改任何客户端配置，也不改变体检结果。
- 修复：某些 Windows 更新之后，系统报告的端口状态异常，FULI 误以为图谱数据库没启动，导致无法启动，更新失败时也无法回滚到旧版。
- 控制台里所有开关统一为同一种开关组件，外观和操作方式一致。
- 依赖安全更新：`@hono/node-server` 2.1.5、`vue-i18n` 11.4.16；测试工具链里的 `minimatch` 11.0.3、`glob` 14.0.3。

In English:

- **Health check (D-76)**: FULI checks for stale client connections, migrations waiting for you or blocked data, open sessions on an older FULI, and work an update left undone. It reconnects clients you had connected (backing up their configuration first) with one click and tells you where to go for the rest; the console shows "N things need you" at the top. `GET /api/system/doctor` reports; `POST /api/system/doctor/repair` runs only automatic fixes, accepts only local requests and is `local_user_only` in the Agent interface catalog. Known limits: a graph's pending steps are not reported while the graph service is down, Codex hook trust is not checked, and `fuli status` does not report an outdated version yet.
- **FULI desktop client (Windows package, Beta)**: the tray app is now the FULI desktop client (Flutter). Whenever the console answers, the window is the console itself (embedded WebView2), so there is no browser tab to open; health findings, repair, update and data-format confirmation are all in the console. Only when there is no console to show (not started, not installed, not answering) does the window show a status page: one sentence on whether FULI works and a card with one button per thing that needs you. Links outside the console open in the default browser; without WebView2 the client keeps the status page and opens the console in the browser. The window title and tray tooltip read "FULI Beta"; the app icon is a rounded square; the tray icon has a green, amber or red dot, with a system notification when things get worse; it takes its look from the console theme. The Fuli shortcuts open it; FuliTray is no longer shipped. One client per Windows user; launch at login is on by default (tray only) and can be turned off in the tray menu. Update, rollback and the console's one-click update close and reopen it; uninstall closes it and removes its launch-at-login entry. Use another port stays in the tray menu. A one-click update from the 0.22 tray closes the old tray and opens the new client. The embedded console was opened on one Windows 11 computer; tray, notifications and launch at login are not fully verified on a real desktop yet. The macOS client is not in the release (unsigned CI build only).
- **An FLA's own workbench (D-78)**: an FLA with tasks or workflows opens on a Workbench tab; one with neither shows none. Its board is the tasks assigned to it (one project's own columns, or the built-in five across projects), read-only because task status follows the Agent's runs. Its workflows are proposed by the FLA (from repeated patterns FULI learned, or its own steps) and take effect only after you confirm them on its page; you can also decline or retire them. Every change is a new version and older ones are kept. Workflows never run by themselves and are never injected into context: the Agent reads an index (name, purpose, step count, approximate tokens), then the full steps when needed, and records each run. The tab loads only when opened; nothing runs in the background.
- **`#FLA` calls (rec#58)**: `#FLA <name>` also reaches the built-in roles Bole, Jefa, Tonborg (in the current folder's project) and Astro (global), with the same checks as `@Bole` and no wider access. `#FLA` counts at the start of a message or line; mid-sentence only right after a request word (请/让/帮我/麻烦/交给, please/ask/let), with an exact name and never a picker. Quoted or code `#FLA` is plain text. Known exception: an ordinary sentence where 让 is directly followed by an exact name still calls that Agent. When a call cannot go through, FULI says why and how to fix it, and never switches to someone else. Bole's and Tonborg's projects can now be saved in the console; Astro, the global assistant, takes no projects.
- **Receipt links and client setup (D-80)**: the desktop client registers `fuli://` for the current Windows user; a `fuli://` link opens the matching console page in the browser on whatever port FULI uses now, and `fuli://status` opens the client window. Links carry no port, so they survive a port change. `fuli://` only opens pages and refuses other hosts, ports and path tricks; a running client receives the link. On an installed Windows copy, once this installation's client has registered the scheme (checked at most once a minute), receipt links are written as `fuli://…`; npm installs, macOS and copies without the client keep `http://127.0.0.1:<port>/…`. Some clients (for example Claude Desktop) drop links to local addresses, so the reminder now reads "关闭提醒：设置 → 数据格式迁移". The installed Windows copy adds `FuliNode.exe` at the installation root, which runs whichever version `installation.json` names; Claude Code, Codex, Cursor and OpenCode MCP entries and hooks start FULI through it, so update and rollback no longer leave client configs pointing at an old version. Older configs show as outdated in the health check and are rewritten by Fix automatically or the next update. Antigravity (the app and the `agy` CLI share `~/.gemini/config/mcp_config.json`) is a supported client: MCP only, source `antigravity`, other servers kept. Not verified yet: clicking `fuli://` on a real desktop, scheme registration across update and rollback, whether Claude Desktop, Codex and Cursor render `fuli://` as clickable, `FuliNode.exe` in real client sessions (it was compiled and run in tests), and real Antigravity. After a rollback to a version before beta.3, `fuli://` waits for a newer client and client configs go back to version paths until the next update.
- **Other**: knowledge search gains `view: "index"` (titles and approximate tokens only) and `ids` to read chosen records; default full results are unchanged. Conversation folding keeps the summary Claude Code or Codex writes when it compacts instead of keyword-picked lines (about 96% noise in a blind test). FULI starts using the shared components agent-session-launcher and agent-installer, read-only in this release: the Windows package bundles both, other installs download them on first need (pinned version and SHA-256); the launcher decides whether an "open session" link is offered, and sessions whose IDs contain unusual characters no longer get one; the installer only checks client setup in the background and changes no client configuration or health result. Fixed: after some Windows updates the system reported port states wrongly, so FULI thought its graph database had not started, could not start, and a failed update could not roll back. Every console switch is the same component. Dependency security updates: `@hono/node-server` 2.1.5, `vue-i18n` 11.4.16; `minimatch` 11.0.3 and `glob` 14.0.3 in the test toolchain.

## 数据格式

新增两个本地存储：`agent-workflows.sqlite`（FLA 的工作流）和 `session-clients/`（每个会话在哪个客户端里）。都在第一次使用时创建，从 0.22.1 升级不会出现需要你确认的迁移步骤；还没确认 `graph/12-builtin-occupations` 的，照旧在「设置 → 数据格式迁移」确认。

Two new local stores, `agent-workflows.sqlite` (FLA workflows) and `session-clients/` (which client each session ran in), both created on first use; upgrading from 0.22.1 adds no migration to confirm.

## 安装和升级

需要 Node.js >= 24.12。

- **Windows 托盘版（按用户安装）**：在控制台点「更新到 v0.23.0-beta.3」，或者下载这个版本的 `fuli-windows-tray-0.23.0-beta.3.zip`（核对同名 `.sha256`），解压后运行 `Update-Fuli.cmd`。
- **npm**：

```sh
fuli stop
npm install --global fuli-context@beta
fuli setup --yes --connected-only
```
