# FULI 0.23.0（草稿；当前公开预览版 0.23.0-beta.1）

0.23 让不用终端的人也能装好、用好、升级 FULI：FULI 会自己体检，能修的自己修，修不了的用一句话告诉你；Windows 安装包的托盘程序换成了 FULI 桌面客户端。下文是相对当前稳定版 [0.22.1](0.22.1.md) 的变化。数据格式没有变化，从 0.22.1 升级不需要确认迁移。
0.23 lets people who never open a terminal install, use and update FULI: FULI checks itself, fixes what it can and says in one sentence what needs you; the Windows package's tray app is now the FULI desktop client. Changes are listed against the current stable release, 0.22.1. No data format changes; upgrading from 0.22.1 needs no confirmed migration.

## 各预览版之间的变化

**beta.1** 是 0.23 的第一个预览版，内容见下文。

## 体检：FULI 自己发现、自己修（D-76）

更新、安装或重新接入之后哪里不对，以前要你自己发现、再去终端重新 setup。现在 FULI 会自己检查这几件事：

- 某个已接入的客户端（Claude Code、Codex 等）的 FULI 连接过期了；
- 数据格式有一步迁移在等你确认，或者有数据暂时用不了；
- 打开着的会话还在用旧版 FULI；
- 上次更新还有没做完的事（例如新版装好了，但客户端还没重新连接）。

能自动处理的（重新连接你以前接入过的客户端，连接前先备份它的配置）点「自动修复」就行；需要你决定的，告诉你去哪里处理。控制台顶部会显示「有 N 件事需要你」，展开可以看到每一件和对应的按钮。

接口：`GET /api/system/doctor` 返回检查结果；`POST /api/system/doctor/repair` 只执行能自动修复的项，只接受本机请求，在 Agent 接口目录里标为 `local_user_only`。

**已知限制**：图谱服务没在运行时，图谱里等你确认的迁移步骤不会出现在体检结果里；Codex 的 Hook 信任状态没有信号，不检查；`fuli status` 还不显示版本是否过期。

## FULI 桌面客户端（Windows 安装包）

- Windows 安装包的托盘程序换成 FULI 桌面客户端（Flutter）：一个窗口用一句话说 FULI 现在是否正常；每件需要处理的事一张卡片，配一个按钮。托盘图标是 FULI 标志加绿色、琥珀色或红色圆点；情况变差时发一条系统通知。外观和控制台一致（颜色、字号、间距由控制台主题生成）。
- 桌面和开始菜单的 Fuli 快捷方式打开它；旧的 FuliTray 托盘不再提供。
- 每个 Windows 用户只运行一个客户端，再次打开会显示已有窗口。安装后的客户端默认开机启动（只显示托盘图标），可以在托盘菜单「开机时启动」关闭。
- Update-Fuli、Rollback-Fuli 和控制台的一键更新会先关闭正在运行的客户端，完成后重新打开它；Uninstall-Fuli 会关闭客户端，并删除开机启动项。客户端正在启动、停止或换端口时，会先做完再关闭。
- 托盘菜单保留「换一个端口」；因 Windows 保留端口而启动失败时，客户端会提示使用它。
- 从 0.22 的旧托盘一键更新到这个版本时，旧托盘会退出，更新后打开的是新的桌面客户端。

**没有验证的部分**：客户端的自动测试和 Windows / macOS 构建在 CI 上通过；托盘、系统通知、开机启动和窗口行为还没有在真实桌面上验证过。macOS 版客户端还不在发布包里（只是 CI 构建产物，未签名）；macOS 和 npm 安装照常使用控制台，体检提示条在控制台里同样可用。

## 其他变化

- 控制台里所有开关统一为同一种开关组件，外观和操作方式一致。

In English:

- **Health check (D-76)**: FULI checks for stale client connections, migrations waiting for you or blocked data, open sessions on an older FULI, and work an update left undone. It reconnects clients you had connected (backing up their configuration first) with one click and tells you where to go for the rest; the console shows "N things need you" at the top. `GET /api/system/doctor` reports; `POST /api/system/doctor/repair` runs only automatic fixes, accepts only local requests and is `local_user_only` in the Agent interface catalog. Known limits: a graph's pending steps are not reported while the graph service is down, Codex hook trust is not checked, and `fuli status` does not report an outdated version yet.
- **FULI desktop client (Windows package)**: the tray app is now the FULI desktop client (Flutter): one sentence on whether FULI works, a card with one button per thing that needs you, a tray icon with a green, amber or red dot, and a system notification when things get worse; it takes its look from the console theme. The Fuli shortcuts open it; FuliTray is no longer shipped. One client per Windows user; launch at login is on by default (tray only) and can be turned off in the tray menu. Update, rollback and the console's one-click update close and reopen it; uninstall closes it and removes its launch-at-login entry. Use another port stays in the tray menu. A one-click update from the 0.22 tray closes the old tray and opens the new client. Not verified on a real desktop yet: tray, notifications, launch at login and window behaviour. The macOS client is not in the release (unsigned CI build only).
- **Other**: every console switch is the same component.

## 数据格式

没有变化。从 0.22.1 升级不会出现需要你确认的迁移步骤；还没确认 `graph/12-builtin-occupations` 的，照旧在「设置 → 数据格式迁移」确认。

No data format changes; upgrading from 0.22.1 adds no migration to confirm.

## 安装和升级

需要 Node.js >= 24.12。

- **Windows 托盘版（按用户安装）**：在控制台点「更新到 v0.23.0-beta.1」，或者下载这个版本的 `fuli-windows-tray-0.23.0-beta.1.zip`（核对同名 `.sha256`），解压后运行 `Update-Fuli.cmd`。
- **npm**：

```sh
fuli stop
npm install --global fuli-context@beta
fuli setup --yes --connected-only
fuli --version
```

升级前照常备份（`fuli graph export --output <目录>`，并复制数据目录）。想回到 0.22.1：预览版升级过的数据只能用升级前的备份恢复；Windows 托盘版可以用已安装版本目录里的 `Rollback-Fuli.cmd` 回到更新前的版本（只切换程序，不回退数据）。
