# FULI 0.21.0（草稿；当前公开预览版 0.21.0-beta.1）

0.21 在 0.20.1 之上增加长期职责、模型设置历史，以及一批入口 token、可靠性和边界方面的修复。数据格式是兼容新增（见文末），从 0.20.x 升级不需要手动迁移。

## 长期职责（standing assignments，rec#29）

- 你可以对 Agent 说一次「以后这类工作交给某个专门的项目」。Agent 会用一句话复述计划，你确认后，FULI 新建或复用对应的项目、为它配组长，并记下你给的关键词。
- 之后在任何仓库、会话或客户端里，经过 FULI 任务入口、出现这些关键词的任务，会归到该项目，交给它的组长处理。前提是：这条职责仍然有效，对应的项目可以使用，并且你没有为这次任务另外指定负责人。职责记录读不出来、项目不可用，或者被你的显式选择覆盖时，按原来的方式归属。入口和回执各用一句话说明这次的归属，你可以当场纠正。
- 两条职责的关键词同时命中时，FULI 会问你，不会自己猜。你自己点名的项目永远优先。
- `find_agents` 现在可以按组长负责的工作来找，不只是按名字。
- 退役、换人、修改关键词也走同样的流程：先预览，再确认一次。

## 模型设置历史（rec#11 D-42）

内置 Agent 的模型、连接方式和「只给建议」开关，每次改动都会记录：是哪个内置 Agent 的哪项设置、经由哪个入口改的、改前改后的值（这不是对操作者身份的认证）。密钥只记为「已更改」，不保存值。如果有一段改动没有记录到，会明确标出「有改动未被记录」。

## 入口和 token

- **Claude Code 每轮提问时的入口按内联上限裁剪**（rec#47 F1b，D-54）：UserPromptSubmit 时的入口一旦超出约 9,000 字符，就按下面的顺序裁掉可选内容：
  1. 先缩短知识召回；
  2. 再缩短最近对话；
  3. 最后才减少偏好。
  
  hard 约束、边界、收尾字段和冲突永远保留。被省略的偏好会给出条数，并提示可以用 `read_task_preferences` 按需读取。如果光是必须保留的部分就已经超过上限，或者渲染层把超大内容拦了下来，入口仍可能超限甚至被阻断。SessionStart 和重置时的恢复入口不在这次裁剪范围内。只有成功送出、帧有效的入口，才能确认送达；确认之后，下一轮只发变化的部分。在合成数据上，30 条偏好时：裁剪前每轮 19,616 字符；裁剪后第一轮 8,658 字符，第二轮 2,191 字符。实际能省多少 token，还要在客户端上复测。Codex 和本来就不超限的入口保持不变。
- **编码任务附带相关知识的标题索引**（rec#51，D-59）：修改类的请求如果在当前项目里命中了知识，入口会附上最多 5 个条目的 id 和标题，以及这次有界搜索的命中数，不放正文。模型需要用到某一条时，再按需读取。没有命中时，入口和原来一字不差。判断「是否为修改请求」用的是启发式规则，不是严格的意图分类。在只有 MCP、没有 Hook 的客户端里，模型如果从来不调用入口工具，就拿不到这个索引。
- **会话开始只需一次 Provider 请求**（rec#44，D-53）：开始会话原本要依次发 3 次 Provider 请求，现在合并成一次，并放在同一个事务里完成。超时后如果交给下一次 Hook 继续处理，会报 `deferred`（等下一次符合条件的 Hook 重试），不再报 unsaved；这不保证以后一定能保存成功。在合成测试中，每次请求延迟 260 ms 时，改前总耗时 752 ms 并且 unsaved，改后 282 ms 并且 saved。

## 收尾调用和工具

- **所有经过会话检查的工具都可以带上当前的 `taskContextToken`**（D-62）。以前只有部分工具能带。同一客户端里有其他会话停用了 FULI 时，带着当前 token 的调用会正常执行；拒绝的规则没有变。
- **可以预期的输入错误改报 `invalid_input`**（rec#48）：错误信息只写参数名和正确的传法，不回显你传入的值。FULI 自己填写的值缺失时，报 internal_error。
- **WSL 客户端访问 Windows 上的 FULI**（rec#48）：`/mnt/<盘符>/…` 会先规范化再转成 Windows 路径。无法转换的 POSIX 路径和 WSL 共享路径会报 `project_path_unsupported`。

## Tonborg 和内置 Agent

- **注入格式预检**（rec#26，D-56）：候选文本命中已知的注入格式时，模型的批准会被拦下，转给你处理。同一批次里只要有一个候选命中，这一批的批准都不会生效。这只是一层很窄的补充检查，**不算注入防护**：在一组 40 条合成盲测样本上，召回 6/20，误报 1/20。D-24 门禁不变。
- **内置 Agent 的建议集中显示在一处**（rec#8）：「设置 → 模型与用量 → 建议记录」现在也包括 Tonborg 留给你确认的知识审核。点进去可以跳到对应的知识条目，在那里处理。
- **控制台的判断记录和建议日志接口**（D-60）：现在会拒绝 LAN 请求，并在执行前由服务端向 Provider 确认证明。**已知限制**：证明是服务端自己附上的，所以本机进程（包括能执行 shell 的 Agent）仍然可以通过本机 HTTP 读到完整历史。FULI 是本地工具，控制台不做登录（D-70，取消了 D-61 的会话认证计划）。

## 可靠性

- `fuli setup` 等待控制台和 Provider 就绪，改为真正的墙钟截止时间：控制台 60 s，Provider 120 s。超时时会说明哪些组件已经在运行、数据仍然保留，以及如何重试或执行 `fuli stop`。
- 只有真正检索过，才使用「已检索，未命中」标记。自动记录关闭时，Agent 提交的修改不会保存；提示文字现在和实际行为一致。
- 跨设备协调端每台设备的最后在线时间，最多每 15 s 写一次，在线状态因此可能比实际晚 75–90 s。系统时钟回拨时，未来的时间一律视为不可信。
- Windows 上的文件身份统一用精确值比较（rec#49）。
- 两个过大的源文件按职责拆分，行为不变。

## 移除定时任务

「Agent → 定时任务」页面、`/api/task-schedules` 接口和 Agent 工具 `manage_project_agent_schedule` 已移除。定时任务只会按间隔新建一张项目任务卡，之后没有任何东西去执行它，用处不大，还容易让人误会。项目任务本身（指派、开工、停止、重试）不受影响。

## 数据格式

新增一个独立的本地存储 `model-settings-history.sqlite`（格式 1），用于模型设置历史，属于兼容新增，第一次改动设置时才会创建。用过定时任务的数据目录里留下的 `task-schedules.sqlite` 及其格式备份原样保留：FULI 不再读取、迁移、清理或删除它，`fuli migrate status` 也不再列出它（包括它以前等你确认的 `task-schedules/3-run-recovery`）。不需要它时可以自己删掉。其他存储没有变化。`fuli migrate status` 不会出现需要你确认的步骤。

In English: 0.21 removes task schedules (the 定时任务 page, `/api/task-schedules` and `manage_project_agent_schedule`): they only created a project task card at an interval that nothing then ran. A leftover `task-schedules.sqlite` and its format backups stay untouched and are no longer read, migrated, pruned or listed. 0.21 adds standing work assignments and a model settings history, trims optional content from Claude Code's prompt-time entry toward its inline limit (mandatory content and the SessionStart restore are not bounded; only a successfully delivered frame is confirmable), adds a title-only knowledge index for coding tasks, begins a conversation in one Provider request, lets every gated tool carry the current task token, types caller input errors, and fixes WSL paths on Windows. Tonborg gains a narrow injection-pattern pre-check (6/20 recall on a 40-sample synthetic blind set; not injection protection) and its suggestions appear in the console list. Console judgment history routes refuse LAN requests, but local HTTP callers are trusted by design; FULI is a local tool and the console has no login (D-70). One new compatible local store, `model-settings-history.sqlite`.

## 安装和升级

需要 Node.js >= 24.12。

```sh
fuli stop
npm install --global fuli-context@beta
fuli setup --yes --connected-only
fuli --version
```

从 0.20.x 升级不需要额外步骤，升级前照常先备份（`fuli graph export --output <目录>`，并复制数据目录）。
