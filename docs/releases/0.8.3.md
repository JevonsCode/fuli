# Fuli 0.8.3

## Persistent Agent identity

- Task entry resolves an explicit leading Agent name or stable encoded identity inside the
  current project. Ambiguous names, unknown identities and conflicting selections stop
  resolution instead of silently restoring a different Agent's memory.
- Implicit task ownership excludes unrelated HR and project-management peers. Deliberate
  role selection and matching management work remain supported.
- Task and conversation receipts identify the actual owner, link to the Agent profile and
  provide a continuation instruction. Collaboration receipts reflect actual employee calls.
- Agent pages can copy a project-scoped continuation instruction for another integrated
  client, with a manual-copy fallback when clipboard access is unavailable.

## Context and preferences

- Compact task context preserves taste categories and domains; delegated role context keeps
  the Agent's character and the user's expectations.
- Conversation receipts respect capture-disabled responses. A metadata read failure cannot
  turn an already successful conversation save into a reported save failure.
- Private visible-conversation journals, working memory and confirmed reusable knowledge are
  documented as separate layers. The default inactivity window remains seven days, with
  bounded recall and on-demand evidence retrieval.

## Product website and maintenance

- Introduce a static Chinese product website with a scroll-driven relationship diagram,
  responsive layouts, motion controls, reduced-motion support and local installation guidance.
- Publish only the dedicated `site/` directory through GitHub Pages. Personal project data,
  test logs and local reports are not website assets.
- Reconcile PR #1 with the newer test-tool gate already shipped on main, preserving the
  canonical environment snapshot and stronger regression contracts.

## Compatibility

Cross-client continuity requires an installed Fuli integration, a reachable shared personal
database and the correct project/Agent identity. Capture coverage and native mention menus
remain client-specific. Protocol and isolated database tests do not prove a complete real
model conversation in every host. The separately packaged team server remains in development.
