# FULI 0.29.0

## 0.29.0-beta.5

0.29.0-beta.5 发在 `beta` 渠道。修复：beta.4 之后运行机上的 Codex 开任务时仍拿不到任务凭证（`native_session_required`）——Codex 只把对话编号交给钩子，不交给 MCP 服务。没有数据格式变化。

0.29.0-beta.5 is on the `beta` channel. Fixed: after beta.4, Codex on a runner still got no task token at task entry (`native_session_required`): Codex names its conversation only to its hooks, never to MCP servers. No data format change.

- 运行机把客户端的提问钩子转给主机：主机按本机钩子的方式、为客户端自己的会话和它所在的文件夹开任务，发任务凭证；对话记录留在运行机上。主机连不上时，钩子照旧提示模型通过 FULI 的 MCP 工具开任务。
- A runner forwards its clients' prompt hook to the host, which enters the task as a local hook would, for the client's own session and the folder it is in, and issues a task token; the transcript stays on the runner. While the host is away, the hook still tells the model to enter the task through FULI's MCP tools.

## 0.29.0-beta.4

0.29.0-beta.4 发在 `beta` 渠道。修复：运行机上的 Codex 开任务时拿不到任务凭证（`native_session_required`），收尾记录因此存不上。没有数据格式变化。

0.29.0-beta.4 is on the `beta` channel. Fixed: Codex on a runner got no task token at task entry (`native_session_required`), so its checkpoint could not be saved. No data format change.

- 运行机把客户端自己的会话（Codex 的对话）原样告诉主机，主机按本机客户端的方式认它，开任务就会发任务凭证。
- The runner tells the host when a session is the client's own (a Codex conversation), and the host treats it as it treats a local client's, so task entry issues a task token.

## 0.29.0-beta.3

0.29.0-beta.3 发在 `beta` 渠道。运行机能打开主机的复利了，也不会再被 FULI.app 或 `fuli setup` 改成一套空的本地 FULI。没有数据格式变化。

0.29.0-beta.3 is on the `beta` channel. A runner opens its host's FULI, and FULI.app or `fuli setup` no longer turn it into an empty local FULI. No data format change.

### 改了什么

- **在运行机上打开复利，看到的是主机的**：`fuli start`、`fuli open` 和 FULI.app 在运行机上打开本机 `127.0.0.1:2727`，页面、操作和实时更新都经配对的加密通道到主机；主机给的回执链接在运行机上也能点开。主机连不上时，页面说明这一点并显示还有几条记录在排队。
- **运行机不会被意外改成独立 FULI**：FULI.app 在运行机上只启动这个入口，不再运行 `fuli setup`；`fuli setup`（以及 `fuli update` 里的那一步）在运行机上只更新客户端接入。
- **安全边界**：入口只在本机回环地址、以自己的名字应答，拒绝其他网站页面发来的请求；运行机能做的不超过你在主机控制台上本人能做的，邀请运行机和局域网配对只能在主机本机操作。

### What's new

- **A runner opens its host's FULI.** `fuli start`, `fuli open` and FULI.app open `127.0.0.1:2727` on the runner; pages, actions and live updates go to the host over the paired, encrypted channel, so the host's receipt links open there too. While the host is away, a page says so with how many records wait.
- **A runner stays a runner.** FULI.app on a runner starts only this entry and never runs `fuli setup`; `fuli setup` (and the step `fuli update` runs) on a runner updates its clients only.
- **Boundaries.** The entry answers only on loopback under its own name and refuses other sites' pages; a runner does no more than you could at the host's own console, and inviting runners and LAN pairing stay on the host itself.

## 0.29.0-beta.2

0.29.0-beta.2 发在 `beta` 渠道。它修好了 beta.1 的运行机：权限收紧、断线和撤销处理得当、Windows 上能正常关闭；也带上了稳定版 0.27.16 的全部改动。圆桌数据会自动升级一次（见「数据格式」），运行机的两份存储从 beta.1 自动升级。

0.29.0-beta.2 is on the `beta` channel. It fixes beta.1's runners: tighter permissions, sound handling of dropped connections and revocation, a clean close on Windows; it also carries everything in stable 0.27.16. The roundtable data upgrades itself once (see Data format), and both runner stores upgrade from beta.1 by themselves.

### 改了什么

- **运行机能做的事收紧了**：运行机发起的请求，在主机上唤醒的 AI 一律只读、只加载 FULI 的工具，不能指定主机上的工作目录，也不能代你改控制台设置；被它唤醒的 AI 再去叫别的助手，同样只读。在 Windows 上，这类请求只唤醒 Claude Code（不唤醒 Codex），并且不加载你的设置和钩子。
- **记录只记一次**：网络断了重试，同一条收尾记录也只记一次；连接断开时已经发出去的写操作不再自动重试，会告诉你「结果不确定，先查一下」。
- **撤销就是撤销**：运行机知道自己被撤销后，立刻删掉缓存和离线令牌，不再重试；还没送到的记录保留下来，重新配对回同一台主机会接着送，配对到别的主机前会先问你（`--force`）。
- **退出配对**：新增 `fuli runner leave`；还有没送到的记录时会先报数量。
- **配对会告诉你**：有电脑配对成功时，控制台的「最近你可能需要知道的事」里会出现一条，写着撤销用的命令。
- **主机不在时应答更快**：运行机同时试所有已知地址，约 5 秒内回应（beta.1 要 11 秒以上，可能超过客户端的启动等待）。
- **没配对运行机的电脑不受影响**：不再多加载模块、不建存储、不定时查询。
- **Windows 上关得干净**：存储、连接、计时器全部释放，更新和卸载不会被占用的文件挡住。
- OpenCode 和 DeepSeek Harness 在运行机上不再出错；每个客户端的钩子都会提醒先走 FULI 的任务入口。

## In English (beta.2)

### Fixed

- **What a runner can do is held tight.** A runner's ask wakes an AI on the host read-only with FULI's tools only; it cannot name a host working folder or change console settings for you, and an AI it wakes stays read-only when it asks another assistant. On Windows such asks wake Claude Code only (never Codex), without your settings or hooks.
- **Once, even on a retry.** A checkpoint is applied once however often it is re-sent; a write already sent when a connection drops is not repeated, and you are told its outcome is unknown.
- **Revoked means revoked.** A runner that learns it was revoked deletes its cache and offline tokens and stops retrying; unsent checkpoints are kept, delivered on re-joining the same host, and joining another host asks first (`--force`).
- **Leaving.** New `fuli runner leave`, which first counts what is still unsent.
- **Pairing tells you.** A pairing shows in 「最近你可能需要知道的事」 with the command to revoke it.
- **Faster while the host is away.** A runner tries every known address at once and answers in about 5 s (beta.1 took over 11 s, past some clients' start-up wait).
- **No cost without a runner.** A computer without one loads, creates and polls nothing extra.
- **A clean close on Windows.** Stores, connections and timers are released, so updates and uninstall are not blocked by open files.
- OpenCode and DeepSeek Harness no longer fail on a runner; every client's hook points the model at FULI's task entry.

### 已知限制 / Known limits

- Windows 上的运行机还没在真的第二台电脑上试过。被撤销、地址变化等情况只在自动化测试里跑过。
- 从运行机唤醒的 Claude 不加载你的钩子，偶尔可能接不上任务而失败（不会以更大的权限运行）。
- beta.1 时已经送到主机但回应丢了的个别记录，升级后可能再记一次。
- Windows runners have not been tried on a real second computer; revocation and address changes ran in automated tests only.
- A Claude woken from a runner loads none of your hooks and may occasionally fail to pick the task up (it never runs with more rights).
- A rare beta.1 checkpoint the host applied but whose answer was lost may be applied again after the upgrade.

### 数据格式 / Data format

- **每台电脑的圆桌数据**在第一次启动时从第 11 版升级到第 12 版（记下由哪台运行机发起、是否来自另一台电脑）。升级前会先备份；之后旧版 FULI（包括 0.27.16）读不了这份数据，退回要用备份。
- **运行机的两份存储**从 beta.1 自动升级：主机端 1 → 3（beta.1 的去重记录不保留），运行机端 1 → 2。
- 稳定版 0.27.16 新增的 `agent-introductions.sqlite` 也在这一版里。
- **The roundtable data on every computer** upgrades from format 11 to 12 on first start (which runner sent an ask, and whether it came from another computer). A backup is taken first; an older FULI, 0.27.16 included, can no longer open it, so going back needs that backup.
- **Both runner stores** upgrade from beta.1 by themselves: host 1 → 3 (beta.1's replay records are not kept), runner 1 → 2.
- The `agent-introductions.sqlite` store new in stable 0.27.16 is in this version too.

## 0.29.0-beta.1

0.29.0-beta.1 发在 `beta` 渠道。新增「运行机」：另一台电脑上的 Agent 客户端都用这台电脑的 FULI。新增两份本地存储（`runner/host.sqlite`、`runner/runner.sqlite`），已有数据不变。

0.29.0-beta.1 is on the `beta` channel. New: runners, another computer whose Agent clients use this computer's FULI. Two new local stores (`runner/host.sqlite`, `runner/runner.sqlite`); existing data is unchanged.

### 改了什么

- **运行机（Beta）**：在主机上运行 `fuli runner invite`，把打印出的一行在另一台电脑上运行（`fuli runner join …`，10 分钟内有效，只能用一次）。两台电脑互相固定对方的证书（双向 TLS 1.3），运行机上的 Codex、Cursor 和其他 MCP 客户端随即按 `fuli setup` 的方式接好，它们的 FULI 工具都由主机回答。知识、习惯、FLA 和记忆只存在主机上。
- **目录不同也认得项目**：运行机把所在目录的仓库信息（来源地址，不带任何凭据）告诉主机，主机按本机同样的规则认项目、登记新仓库，不读运行机的硬盘。
- **主机暂时连不上**：任务进入用这个目录上次的偏好（标明是离线结果），`checkpoint_task_knowledge` 先排队，其他只读工具给上次的结果，别的操作明确说需要主机。连上后按顺序补交，主机记住每一条，重复送达只算一次。`fuli runner status` 查看，`fuli runner sync` 立即补交。
- **地址变了也找得回来**：主机跟着自己的局域网地址变化监听，并用 mDNS 公布证书指纹；运行机先试上次的地址，再按指纹找。
- **管理**：主机上 `fuli runner list` 列出运行机和最后在哪里见到，`fuli runner revoke` 立即收回访问。邀请运行机只能由你本人在主机上做。

### 这一版的限制

- 两台电脑要能直接连通（同一网络或一根线），不经过任何中继。
- 运行机上不跑生命周期 hook，客户端靠 FULI 的 MCP 工具自己进入任务。

## In English

### New

- **Runners (Beta).** On the host run `fuli runner invite`, then run the printed line on the other computer (`fuli runner join …`, valid once, for 10 minutes). The two computers pin each other's certificates (mutual TLS 1.3); the runner's Codex, Cursor and other MCP clients are set up as `fuli setup` would, and their FULI tools are answered by the host. Knowledge, preferences, FLAs and memory stay on the host only.
- **Projects match whatever the folder is called.** A runner tells the host its folder's repository facts (the origin address, never a credential); the host matches and registers projects by its own rules without reading the runner's disk.
- **While the host is away.** Task entry returns the folder's last preferences, marked offline; `checkpoint_task_knowledge` queues; other read-only tools return their last answer; anything else says it needs the host. The queue is delivered in order once the host answers; the host remembers every entry, so one delivered twice counts once. `fuli runner status` shows it, `fuli runner sync` delivers now.
- **Found again after an address change.** The host follows its LAN addresses and announces its certificate fingerprint over mDNS; a runner tries the last address, then looks the fingerprint up.
- **Managing runners.** `fuli runner list` on the host shows each runner and where it was last seen; `fuli runner revoke` ends its access at once. Only you can invite a runner, on the host.

### Limits of this beta

- Both computers must reach each other directly (one network or a cable); nothing is relayed.
- Lifecycle hooks do not run on a runner; its clients enter tasks through FULI's MCP tools.
