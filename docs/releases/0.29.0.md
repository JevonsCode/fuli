# FULI 0.29.0

## 0.29.0-beta.10

Astro 模型设置里的临时会话项目收在可展开的一行。新配置勾选全部可选项目，保存后再打开，会恢复你选的项目，包括全部清空。中英文使用同一份选择，非项目内容有独立开关。

展开后可凭短号、日期和已有标题找到单个项目。FULI 能用原会话记录核实创建它的客户端时，也会显示这个来源。[项目选择改动](https://github.com/JevonsCode/fuli/pull/1051) · [原会话来源](https://github.com/JevonsCode/fuli/pull/1053)

这版也带上了稳定线的对话来源和进度修复。Jefa 可以查询有权访问的项目中每条对话的负责人和最近进展，对话小结可以回到记录任务结果的检查点。

Dreaming 会显示正在整理的项目和整理结果，可以从详情去授权再回来。「补检索词」会显示已写入和剩余的数量，失败后可以重试。[Astro 改动](https://github.com/JevonsCode/fuli/pull/1052)

Windows 更新期间，已连接的 MCP 客户端可以继续使用可用的进程，等新程序就绪后再切换。[连接修复](https://github.com/JevonsCode/fuli/pull/1050)

在宿主电脑控制台长按「设置」三秒可复制本机故障报告。已配对运行机可以查看公开版本，更新操作和详细报告须在宿主电脑打开。报告权限被收回时，旧预览会清除，普通项目的离线缓存仍可用。[故障报告](https://github.com/JevonsCode/fuli/pull/1049) · [宿主访问权限](https://github.com/JevonsCode/fuli/pull/1054)

运行机可以用自己的模型替 Tonborg 选执行端，主机不在也能选。在运行机上配好它自己的 `model-backends.json`（`roles.tonborg` 只放行 `executor_routing`），用 `fuli models set-key` 存密钥，再在 `runner/executors.json` 列出这台电脑的执行端和模型即可。在运行机上配好本机模型，就算同意把选型需要的内容发给它：请求本身、通过本机预检的执行端和模型、该项目缓存的偏好、这台运行机之前的选型和结果。执行完用 `report_routing_outcome` 报一次结果；选型和结果经发件箱各补交主机一次，记入 Tonborg 的判断记录，结果算运行机的报告，不算你本人的投票。知识审核、验收和写知识仍只在主机。这样设置的运行机会多一个 `runner/routing.sqlite`。[本机选型](https://github.com/JevonsCode/fuli/pull/1056)

运行机的 MCP 会话和连接不再按运行机或按地址限额，主机保留总数兜底（所有运行机合计 64 个会话、256 个连接）。运行机上的 FULI 进程退出、断线重连或升级换版本时，会先关掉它在主机上的旧会话。主机拒绝开新会话时，运行机回 `host_refused` 并写明主机给的原因，不再当成主机不在线；`fuli runner status` 会显示这台运行机占了几个会话。主机不在时进入的任务，主机回来后再接续对话，会提示先重新进入任务。[会话生命周期](https://github.com/JevonsCode/fuli/pull/1057)

beta.9 在公司网络里绕开 VPN 找到主机的修复，现在也合进了主线，这版继续带着。[VPN 修复](https://github.com/JevonsCode/fuli/pull/1058)

从 beta.8 或 beta.9 升级时，圆桌数据从格式 12 自动升到 13，升级前会备份。图谱从 21 升到 22 并建立会话来源索引。如需退回旧 Beta，圆桌可用升级前的备份，图谱需用自行保留的更新前备份。[数据格式说明](https://github.com/JevonsCode/fuli/blob/346892a3bc4b9f59c42f382674942b6a17098d22/docs/releases/0.27.17.md)

Astro groups temporary conversation projects in one expandable row. New configurations select all available projects. Reopening a saved configuration restores your choices, including an empty selection, in either language. Content outside projects has its own switch.

Expanded entries show a short ID, any recorded date or title, and the originating client when a saved session confirms it.

This beta also includes the stable channel's conversation history and progress fixes. Jefa can report the owner and latest progress of each conversation in the projects it can access. Task results in summaries link to their source checkpoint.

Dreaming shows the project being processed and the results. Its details let you grant project access and return to the same view. Retrieval term generation shows how many entries are complete and how many remain, with a retry when a run fails.

During a Windows update, connected MCP clients can keep using the working process until the new installation is ready.

Hold Settings on the host for three seconds to preview and copy its issue report. Paired runners can see the public version. Open the host console for updates and detailed reports. Losing access clears the old preview. Ordinary project data remains available offline.

When updating from beta.8 or beta.9, FULI backs up the roundtable store, then upgrades it from format 12 to 13. The graph moves from format 21 to 22 and adds the conversation source index. Returning to either earlier beta requires the prior roundtable backup and your own pre-update graph backup.

A runner can choose executors with its own Tonborg model, with or without the host. Give the runner its own `model-backends.json` (`roles.tonborg` allowed `executor_routing` only), save its key with `fuli models set-key`, and list that computer's executors and models in `runner/executors.json`. Setting the model up there is the person's approval to send it what a choice needs: the request, the executors and models that pass the local preflight, the project's cached preferences and the runner's earlier choices with their outcomes. `report_routing_outcome` reports once how a choice did; choices and outcomes reach the host's Tonborg ledger once through the outbox, an outcome as the runner's report, never the person's vote. Knowledge review, acceptance and knowledge writes stay on the host. Such a runner adds `runner/routing.sqlite`.

No runner or address has its own cap on MCP sessions or connections; the host keeps totals as a backstop (64 sessions and 256 connections for all runners). A runner's FULI process ends its host session when it exits, reconnects or moves to a newly installed version. A session the host refuses answers `host_refused` with the host's reason instead of offline answers, and `fuli runner status` shows the sessions a runner holds. A task entered while the host was away asks to be entered again before a conversation is resumed.

beta.9's fix that lets a runner reach its host past an office VPN is now on the main line and stays in this build.

0.29.0-beta.9 发在 `beta` 渠道。修复：在公司网络里，运行机找不到主机。两台电脑在不同子网，而且公司 VPN 把对方的网段接管进隧道。没有数据格式变化。

0.29.0-beta.9 is on the `beta` channel. Fixed: on an office network a runner could not find its host, the two computers being in different subnets with a VPN claiming the other's subnet. No data format change.

- 运行机连主机时，除了走系统默认路由，也会从每块实体网卡（Wi-Fi、网线）的地址去试，哪条通就一直用哪条，所以公司 VPN 不再挡路。
- 主机会把自己当前的地址告诉运行机，运行机最多记 16 个，家里和公司的地址都会记住，下次换网络先试这些。
- 到了一个新网络又找不到主机时，在运行机上运行一次 `fuli runner add-address 主机的地址`（主机上的 `fuli runner list` 会显示地址），之后它就记住了。
- A runner tries each of the host's addresses both by the default route and from each physical adapter's own address (Wi-Fi, cable), and keeps the route that answers, so an office VPN no longer stands in the way.
- The host tells the runner its current addresses, and the runner keeps up to 16, so home and office are both tried after a network change.
- On a new network where the host cannot be found, run `fuli runner add-address ADDRESS` once on the runner (the host's `fuli runner list` shows its addresses); it is kept from then on.

## 0.29.0-beta.7

0.29.0-beta.7 发在 `beta` 渠道。运行机的「客户端接入」显示运行机自己的客户端，每轮结束也会在主机上收尾；手动添加的客户端也能装上 FULI 的 Skill；开任务快了将近一半。没有数据格式变化。

0.29.0-beta.7 is on the `beta` channel. A runner's 客户端接入 shows the runner's own clients and its turns are closed on the host; a client added by hand gets FULI's Skills too; task entry is nearly twice as fast. No data format change.

### 改了什么

- **运行机的客户端页是它自己的**：在运行机上打开「客户端接入」，列出、接入、重启的都是这台电脑上的 Codex、Cursor 等客户端，不再显示主机的；从运行机也改不了主机的客户端。
- **运行机每轮结束在主机上收尾**：客户端一轮结束时，运行机把它转给主机，主机检查这次的收尾记录并结束任务，和本机客户端一样。对话原文留在运行机上。
- **手动添加的客户端也有 Skill**：「添加客户端」多了一个可选的 Skill 文件夹；填了之后，FULI 的 Skill 会装进去，并随 FULI 更新。
- **开任务更快**：开任务时的知识召回不再为每次搜索读取整张图谱。主机上实测一次 Codex 开任务从 15.7 秒降到 7.7–8.8 秒。

### What's new

- **A runner's client page is its own.** On a runner, 客户端接入 lists, connects and restarts this computer's Codex, Cursor and other clients, not the host's; a runner can no longer change the host's clients.
- **A runner's turns are closed on the host.** At the end of a client's turn the runner forwards it to the host, which checks the checkpoint and closes the task as for a local client. The conversation's text stays on the runner.
- **Skills for clients added by hand.** 「添加客户端」 takes an optional Skills folder; FULI installs its Skills there and keeps them updated.
- **Faster task entry.** Task entry's recall no longer reads the whole graph for each search. Measured on the host: a Codex task entry went from 15.7 s to 7.7–8.8 s.

## 0.29.0-beta.3

0.29.0-beta.3 发在 `beta` 渠道。运行机能打开主机的复利了，也不会再被 FULI.app 或 `fuli setup` 改成一套空的本地 FULI。没有数据格式变化。

0.29.0-beta.3 is on the `beta` channel. A runner opens its host's FULI, and FULI.app or `fuli setup` no longer turn it into an empty local FULI. No data format change.

### 改了什么

- **在运行机上打开复利，看到的是主机的**：`fuli start`、`fuli open` 和 FULI.app 在运行机上打开本机 `127.0.0.1:2727`，页面、操作和实时更新都经配对的加密通道到主机；主机给的回执链接在运行机上也能点开。主机连不上时，页面说明这一点并显示还有几条记录在排队。
- **运行机不会被意外改成独立 FULI**：FULI.app 在运行机上只启动这个入口，不再运行 `fuli setup`；`fuli setup`（以及 `fuli update` 里的那一步）在运行机上只更新客户端接入。
- **安全边界**：入口只在本机回环地址、以自己的名字应答，拒绝其他网站页面发来的请求；运行机能做的不超过你在主机控制台上本人能做的，邀请运行机和局域网配对只能在主机本机操作。

### What's new

- **A runner opens its host's FULI.** `fuli start`, `fuli open` and FULI.app open `127.0.0.1:2727` on the runner; pages, actions and live updates go to the host over the paired, encrypted channel, so the host's receipt links open there too. While the host is away, a page says so with how many records wait.
- **A runner stays a runner.** FULI.app on a runner starts only this entry and never runs `fuli setup`; `fuli setup` (and the step `fuli update` runs) on a runner updates its clients only.
- **Boundaries.** The entry answers only on loopback under its own name and refuses other sites' pages; a runner does no more than you could at the host's own console, and inviting runners and LAN pairing stay on the host itself.

## 0.29.0-beta.2

0.29.0-beta.2 发在 `beta` 渠道。它修好了 beta.1 的运行机：权限收紧、断线和撤销处理得当、Windows 上能正常关闭；也带上了稳定版 0.27.16 的全部改动。圆桌数据会自动升级一次（见「数据格式」），运行机的两份存储从 beta.1 自动升级。

0.29.0-beta.2 is on the `beta` channel. It fixes beta.1's runners: tighter permissions, sound handling of dropped connections and revocation, a clean close on Windows; it also carries everything in stable 0.27.16. The roundtable data upgrades itself once (see Data format), and both runner stores upgrade from beta.1 by themselves.

### 改了什么

- **运行机能做的事收紧了**：运行机发起的请求，在主机上唤醒的 AI 一律只读、只加载 FULI 的工具，不能指定主机上的工作目录，也不能代你改控制台设置；被它唤醒的 AI 再去叫别的助手，同样只读。在 Windows 上，这类请求只唤醒 Claude Code（不唤醒 Codex），并且不加载你的设置和钩子。
- **记录只记一次**：网络断了重试，同一条收尾记录也只记一次；连接断开时已经发出去的写操作不再自动重试，会告诉你「结果不确定，先查一下」。
- **撤销就是撤销**：运行机知道自己被撤销后，立刻删掉缓存和离线令牌，不再重试；还没送到的记录保留下来，重新配对回同一台主机会接着送，配对到别的主机前会先问你（`--force`）。
- **退出配对**：新增 `fuli runner leave`；还有没送到的记录时会先报数量。
- **配对会告诉你**：有电脑配对成功时，控制台的「最近你可能需要知道的事」里会出现一条，写着撤销用的命令。
- **主机不在时应答更快**：运行机同时试所有已知地址，约 5 秒内回应（beta.1 要 11 秒以上，可能超过客户端的启动等待）。
- **没配对运行机的电脑不受影响**：不再多加载模块、不建存储、不定时查询。
- **Windows 上关得干净**：存储、连接、计时器全部释放，更新和卸载不会被占用的文件挡住。
- OpenCode 和 DeepSeek Harness 在运行机上不再出错；每个客户端的钩子都会提醒先走 FULI 的任务入口。

## In English (beta.2)

### Fixed

- **What a runner can do is held tight.** A runner's ask wakes an AI on the host read-only with FULI's tools only; it cannot name a host working folder or change console settings for you, and an AI it wakes stays read-only when it asks another assistant. On Windows such asks wake Claude Code only (never Codex), without your settings or hooks.
- **Once, even on a retry.** A checkpoint is applied once however often it is re-sent; a write already sent when a connection drops is not repeated, and you are told its outcome is unknown.
- **Revoked means revoked.** A runner that learns it was revoked deletes its cache and offline tokens and stops retrying; unsent checkpoints are kept, delivered on re-joining the same host, and joining another host asks first (`--force`).
- **Leaving.** New `fuli runner leave`, which first counts what is still unsent.
- **Pairing tells you.** A pairing shows in 「最近你可能需要知道的事」 with the command to revoke it.
- **Faster while the host is away.** A runner tries every known address at once and answers in about 5 s (beta.1 took over 11 s, past some clients' start-up wait).
- **No cost without a runner.** A computer without one loads, creates and polls nothing extra.
- **A clean close on Windows.** Stores, connections and timers are released, so updates and uninstall are not blocked by open files.
- OpenCode and DeepSeek Harness no longer fail on a runner; every client's hook points the model at FULI's task entry.

### 已知限制 / Known limits

- Windows 上的运行机还没在真的第二台电脑上试过。被撤销、地址变化等情况只在自动化测试里跑过。
- 从运行机唤醒的 Claude 不加载你的钩子，偶尔可能接不上任务而失败（不会以更大的权限运行）。
- beta.1 时已经送到主机但回应丢了的个别记录，升级后可能再记一次。
- Windows runners have not been tried on a real second computer; revocation and address changes ran in automated tests only.
- A Claude woken from a runner loads none of your hooks and may occasionally fail to pick the task up (it never runs with more rights).
- A rare beta.1 checkpoint the host applied but whose answer was lost may be applied again after the upgrade.

### 数据格式 / Data format

- **每台电脑的圆桌数据**在第一次启动时从第 11 版升级到第 12 版（记下由哪台运行机发起、是否来自另一台电脑）。升级前会先备份；之后旧版 FULI（包括 0.27.16）读不了这份数据，退回要用备份。
- **运行机的两份存储**从 beta.1 自动升级：主机端 1 → 3（beta.1 的去重记录不保留），运行机端 1 → 2。
- 稳定版 0.27.16 新增的 `agent-introductions.sqlite` 也在这一版里。
- **The roundtable data on every computer** upgrades from format 11 to 12 on first start (which runner sent an ask, and whether it came from another computer). A backup is taken first; an older FULI, 0.27.16 included, can no longer open it, so going back needs that backup.
- **Both runner stores** upgrade from beta.1 by themselves: host 1 → 3 (beta.1's replay records are not kept), runner 1 → 2.
- The `agent-introductions.sqlite` store new in stable 0.27.16 is in this version too.

## 0.29.0-beta.1

### 改了什么

- **运行机（Beta）**：在主机上运行 `fuli runner invite`，把打印出的一行在另一台电脑上运行（`fuli runner join …`，10 分钟内有效，只能用一次）。两台电脑互相固定对方的证书（双向 TLS 1.3），运行机上的 Codex、Cursor 和其他 MCP 客户端随即按 `fuli setup` 的方式接好，它们的 FULI 工具都由主机回答。知识、习惯、FLA 和记忆只存在主机上。
- **目录不同也认得项目**：运行机把所在目录的仓库信息（来源地址，不带任何凭据）告诉主机，主机按本机同样的规则认项目、登记新仓库，不读运行机的硬盘。
- **主机暂时连不上**：任务进入用这个目录上次的偏好（标明是离线结果），`checkpoint_task_knowledge` 先排队，其他只读工具给上次的结果，别的操作明确说需要主机。连上后按顺序补交，主机记住每一条，重复送达只算一次。`fuli runner status` 查看，`fuli runner sync` 立即补交。
- **地址变了也找得回来**：主机跟着自己的局域网地址变化监听，并用 mDNS 公布证书指纹；运行机先试上次的地址，再按指纹找。
- **管理**：主机上 `fuli runner list` 列出运行机和最后在哪里见到，`fuli runner revoke` 立即收回访问。邀请运行机只能由你本人在主机上做。

### 这一版的限制

- 两台电脑要能直接连通（同一网络或一根线），不经过任何中继。
- 运行机上不跑生命周期 hook，客户端靠 FULI 的 MCP 工具自己进入任务。

## In English

### New

- **Runners (Beta).** On the host run `fuli runner invite`, then run the printed line on the other computer (`fuli runner join …`, valid once, for 10 minutes). The two computers pin each other's certificates (mutual TLS 1.3); the runner's Codex, Cursor and other MCP clients are set up as `fuli setup` would, and their FULI tools are answered by the host. Knowledge, preferences, FLAs and memory stay on the host only.
- **Projects match whatever the folder is called.** A runner tells the host its folder's repository facts (the origin address, never a credential); the host matches and registers projects by its own rules without reading the runner's disk.
- **While the host is away.** Task entry returns the folder's last preferences, marked offline; `checkpoint_task_knowledge` queues; other read-only tools return their last answer; anything else says it needs the host. The queue is delivered in order once the host answers; the host remembers every entry, so one delivered twice counts once. `fuli runner status` shows it, `fuli runner sync` delivers now.
- **Found again after an address change.** The host follows its LAN addresses and announces its certificate fingerprint over mDNS; a runner tries the last address, then looks the fingerprint up.
- **Managing runners.** `fuli runner list` on the host shows each runner and where it was last seen; `fuli runner revoke` ends its access at once. Only you can invite a runner, on the host.

### Limits of this beta

- Both computers must reach each other directly (one network or a cable); nothing is relayed.
- Lifecycle hooks do not run on a runner; its clients enter tasks through FULI's MCP tools.
