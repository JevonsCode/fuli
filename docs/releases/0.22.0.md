# FULI 0.22.0（草稿；当前公开预览版 0.22.0-beta.1）

0.22 是 main 分支上的下一版（rec#11 D-66：0.21.x 从 `release/0.21` 分支发布）。它包含 0.21.0-beta.2 之后合入 main、还没有进入 0.21.x 的改动：控制台不再让你去终端、去掉控制台登录、Jefa 看板内置、Tonborg 的搜索和默认判断方式、按名字继续 Agent、OpenCode 插件，以及一批界面整理。数据格式见文末，其中有需要你确认的步骤。

## 控制台里点一下就行，不用去终端

控制台里原来让你「在终端运行……」的提示，现在都换成了按钮，或者直接说明 FULI 会自己处理什么：

- **删除恢复**：控制台遇到删除恢复未完成时，会自己重新核对一次（和控制台启动时做的核对相同，不会重发删除），最多每 15 s 一次。提示文字不再给出命令。
- **数据格式页**：「重新核对」按钮再执行一次清理并说明结果。新增**整库恢复**：选一个本地存储的格式备份，页面先列出会丢掉什么（版本、各表行数、备份之后记录的迁移），你勾选「我知道……全部修改都会丢失」后点「停止 FULI 并恢复」。恢复由一个独立进程完成：停掉 FULI、按页面上显示的那份备份恢复（恢复前再核对一次摘要，并先做一份安全备份），再启动 FULI。图谱仍然只能在终端用图谱导出恢复。
- **模型密钥**：内置 Agent 的模型设置里有一个只写的「API 密钥」输入框，存到和 `fuli models set-key` 相同的位置（Windows 用 DPAPI，其他系统是只有本人可读的文件）。页面只知道哪些引用已经有密钥，读不到值。
- **客户端接入**：每个客户端旁边有「更新接入」/「重新接入」，执行和 `fuli setup` 相同的客户端安装。
- **更新**：更新提示上的「更新到 vX」按钮，会在独立进程里执行和 `fuli update --yes` 相同的更新，新版本启动后页面自动刷新。失败时只显示第一行原因，并重新启动 FULI。Windows 按用户安装的版本由它自己的安装程序更新，提示里会这样写，不提供这个按钮。

新加的这几个控制台修改接口只接受本机请求，在 Agent 接口目录里标为 `local_user_only`。

**没有验证的部分**：一键更新和控制台整库恢复只用假的 worker 和运行时做过单元测试和接口测试，没有对真实的 npm 发布或正在运行的控制台做过端到端测试。只给 CLI 或 Agent 看的提示（例如 `fuli migrate` 的输出）仍然写着命令。

## 控制台不做登录（rec#11 D-70）

0.21 发布后曾在 main 上加过一个控制台登录（按次启动的会话、一次性代码、`/auth/console` 登录页），现在整个撤掉了：FULI 是本机工具，没有登录。0.21 说明里「调用方侧的会话认证计划在 0.22 做（D-61）」这一项取消。D-60 的行为不变：判断记录和建议日志接口拒绝 LAN 请求，本机进程仍然可以通过本机 HTTP 读到完整历史。

## Jefa 看板内置；移除「聘请 Agent」

- **Jefa 的任务看板直接随 FULI 安装**，不用再 `fl employee install`。看板数据存在新的本地存储 `employees/data/jefa/board.sqlite`，和已有的 `management.sqlite` 分开。任务只记当前状态加一张不可修改的修订表，不会被删除。Agent 可以读看板、建任务、改任务（版本冲突时整批拒绝）、回答状态问题和准备会话标题；把任务标成「完成」只能由你来做。
- 如果你以前在 `employees/packages/jefa` 装过 Jefa 包，它仍然会替代内置版；装坏了的包不再让 Jefa 不可用，内置看板照常工作。
- 你可以按项目开启分享链接，链接只展示你标成公开摘要的任务（只有标题、状态和优先级）。控制台目前还没有设置「公开」的入口，所以分享页暂时显示「暂无可公开的任务」。
- 「聘请 Agent」按钮从项目 Agent 管理页和 Agent 目录移除。「管理负责项目」还在。MCP 的 `recruit_employee` 和 Bole 的招募不变，自定义 Agent 包现在只能通过 `recruit_employee` 聘请。

## Tonborg

- **判断记录可以搜索全部历史**：搜索在判断库里进行，覆盖标题、目标、结论、证据、客户端、模型、项目 id 和项目名，以及最近一次反馈和回执的理由。列表一次加载 30 条，滚到底自动加载下一页（也有「加载更多记录」按钮），只渲染屏幕附近的卡片。「需要人工」筛选改在服务端执行，所以分页不会漏。结果标签（例如「需要确认」）不能被搜索，用「需要人工」标签页代替。
- **默认判断方式和单个项目的设置**：设置里的「自主程度」改叫「Tonborg 的默认判断方式」，只管默认值。Tonborg 工作台有一个可以折叠的「各项目单独的判断方式」列表，项目页也有一张小卡片，可以为这个项目单独设置，或者「恢复默认」。
- **为什么选了「自主处理」还要你确认**：这不是错误。自主处理下，只有 Tonborg 自己配置的、可信的模型给出批准，并且把握不低于 0.85，才会自动执行；由当前会话代答的判断永远不会自动执行。现在每张等你处理的卡片都会用一句话说明原因，例如「Tonborg 把握不足（0.5），交给你确认」或「这次由会话代 Tonborg 判断……交给你确认」。0.20.0 之前判断的记录没有保存审核细节，只能按 0.85 的规则推断原因。

## 按名字继续一位 Agent（@FLA，rec#54）

在任何目录里，提示开头写 `@Jamie Ash 继续刚才的任务`，就由你的这位 Agent（FLA）在它自己的项目里接着做；写 `@FLA` 或 `#FLA` 会给出最多 4 个选项（名字、项目、职业），回复编号即可。规则：

- 只有完整的名字，或者恰好只属于一位可用 FLA 的一个完整名字单词（至少 2 个字符），才会直接继续。部分匹配（`@Ja`、`@src`）不会继续、不弹选项，这一轮按原来的方式处理，入口只多一行提示「想找 FLA？用 #FLA Ja 选择」。
- 邮箱、`@Override` 这类注解、`@scope/pkg`、文件名、不在开头的 `@名字` 都不算。
- 绑定会保留在这个会话里，`@FLA 结束` 解除。目标 FLA 不可用时（已解雇、停用、不允许这个客户端、不在那个项目……），入口直接说明原因，不会换一位 FLA 顶替。
- 已知的残留：一个普通词恰好是某位 FLA 名字里的一个单词时（例如 FLA 叫「Mock Li」时的 `@Mock 怎么用`），会被当成点名。
- 没有 `@` / `#FLA` 的提示，入口内容不变。第一次点名的那一轮入口多约 575 字节，之后每轮多约 48 字节（合成数据上测得）。

## OpenCode 插件（rec#11 D-63/D-64）

- OpenCode 2.x 现在通过一个插件接入 FULI 的任务入口和收尾，不再依赖模型自己调用入口工具（之前 OpenCode + DeepSeek 在 33 次运行里只调用了 1 次）。插件不改你的提示原文；FULI 慢、挂掉或出错时，这一轮最多多一行「Fuli context is unavailable」，不会卡住 OpenCode。
- OpenCode 有了自己的来源 `opencode`，不再和 Gemini CLI、Qwen Code 等共用 `other`。已经保存的、写了 `other` 但没写 `opencode` 的客户端列表和采集开关，读取时也覆盖 OpenCode，存储内容不改写。
- OpenCode 1.x 只接入 MCP；版本读不出来时不装新插件。FULI 不会覆盖或删除不是它写的插件文件。`fuli setup` 也会把 FULI 的 Skills 装进 OpenCode 的 `skills/` 目录。
- **升级需要做一步**：以前以 `other` 接入的 OpenCode MCP 条目会显示为过期，重新运行 `fuli setup` 并重启 OpenCode 后才会改成 `opencode`。
- **没有做的**：OpenCode 的对话还不会自动导入 FULI 的会话记录（OpenCode 不写转录文件）。装在 WSL 里的 OpenCode，需要在 WSL 里运行 `fuli setup`。
- 在隔离的 FULI 和 OpenCode 2.1.4 上实测过：入口送达、收尾触发，连续两个提示的顺序也正确。

## 移除定时任务

「Agent → 定时任务」页面、`/api/task-schedules` 接口和 Agent 工具 `manage_project_agent_schedule` 已移除。定时任务只会按间隔新建一张项目任务卡，之后没有任何东西去执行它。项目任务本身（指派、开工、停止、重试）不受影响。

## 其他修复

- 「不要提交、推送或建分支」这类带逗号的否定列表，以及句中的关系词 where，不再误触发发布或位置类的知识召回（rec#52）。
- 远程知识连接返回缺字段的数据时，报 `connector_response_invalid`，不再报成调用方的 `invalid_input`（rec#48）。

## 数据格式

- 新增独立的本地存储 `employees/data/jefa/board.sqlite`（Jefa 看板，格式 1），属于兼容新增，第一次使用看板时创建。
- 用过定时任务的数据目录里留下的 `task-schedules.sqlite` 及其格式备份原样保留：FULI 不再读取、迁移、清理或删除它，`fuli migrate status` 也不再列出它（包括它以前等你确认的 `task-schedules/3-run-recovery`）。不需要时可以自己删掉。
- 其他存储和图谱（格式 11）没有变化。`fuli migrate status` 不会出现需要你确认的步骤。

In English: 0.22 is the next release from main (0.21.x ships from `release/0.21`, D-66). The console no longer sends the person to a terminal: deletion recovery re-checks itself, and whole-store restore, model keys, client reconnects and updates are buttons (the update and restore were tested with fake workers only, not end to end). The console login added on main after 0.21 is removed; FULI is a local tool with no login (D-70), and the D-61 plan is dropped. Jefa's board ships inside FULI with its own store, `employees/data/jefa/board.sqlite`, and the Hire Agent button is gone. Tonborg's records can be searched across all history and load page by page; the default judgment can be overridden per project, and every card waiting for the person says why. `@Name` or `#FLA` continues one of the person's own Agents by name from any folder. OpenCode 2.x gets a plugin for FULI's entry and close and its own `opencode` source (rerun `fuli setup` and restart OpenCode; OpenCode conversations are not captured yet). Task schedules are removed; a leftover `task-schedules.sqlite` is left untouched. No migration needs confirmation.

## 安装和升级

需要 Node.js >= 24.12。

```sh
fuli stop
npm install --global fuli-context@beta
fuli setup --yes --connected-only
fuli --version
```

升级前照常先备份（`fuli graph export --output <目录>`，并复制数据目录）。也可以用网站上的一行安装命令，见 https://xn--8ovp9s.xn--m8txu.com/fuli/next/ 。
