# FULI 0.27.13

0.27.13 发在 `latest` 渠道。修的是「模型与用量」页和顶栏模型图标说法不一致，以及这一页在一种真实数据上会停止更新。没有数据格式变化。

0.27.13 is on the `latest` channel. It fixes the model page and the top bar's model button disagreeing, and the model page no longer stops updating on one kind of real data. No data format change.

## 更新内容 / What's new

有人在「模型与用量」页点了「测试连接」，模型明明答了，顶栏的模型图标却还亮着红，写着「1 项没回应」。查下来不是一处，是四处。

Someone pressed 「测试连接」 on the model page, the model answered, and the top bar's model button stayed red with "1 not answering". It turned out to be four things, not one.

## 改了什么

- **顶栏和页面说的是同一份状态**：以前顶栏图标自己每分钟读一次，页面是另一份；页面上测试或保存之后，顶栏要等到下一次读才变。现在两处共用一份，任何一边读到新的，两边同时变。
- **一行里的「测试连接」会测到出问题的那个用途**：以前它借第一个在用的用途去测。可某个用途自己的任务失败过（比如等太久），只有它自己再答一次才算好，所以连接显示正常，它还是红的。现在先测自己任务失败的用途，没有才测第一个。
- **「查看详情」里的「测试连接」测完，卡片会跟着变**：以前弹窗里有结果，但卡片、连接那一行和顶栏都停在测试前。
- **顶栏的说法和页面一致**：分清「没回应」（连接的问题）和「任务失败」（某个用途自己的任务没做成），各自计数。
- **模型页不再因为一种记录停止更新**：Dreaming 没有新内容可读时留下的记录没有模型回执，页面读到它会出错，之后整页不再更新，「建议记录」也不显示。现在这类记录读得了，也不再列进「建议记录」（它没问过模型）。
- 编辑模型的表单按打开时的设置保存，中途别处改过设置，仍然会被拦下来提示。

## In English

### Fixed

- **The top bar and the page show one state.** The top bar's button used to read on its own once a minute; a test or a save on the page reached it only at its next read. Both now show one copy, and a read by either reaches both.
- **A row's 「测试连接」 tests the use that has the problem.** It used to test through the first use that is on. A use whose own task had failed (a timeout, for one) is cleared only by its own answer, so the row said connected and that use stayed red. It now tests the uses whose own task failed first.
- **A test inside 「查看详情」 turns the card.** The dialog showed the result while the card, the connection row and the top bar stayed as before.
- **The top bar uses the page's words.** It tells "not answering" (the connection) from "task failed" (a use's own task), with a count of each.
- **The model page no longer stops updating on one kind of record.** A Dreaming run with nothing new to read is recorded without a model receipt; reading it threw, after which the page stopped updating and 「建议记录」 did not show. Such records are read now and are no row of 「建议记录」, since no model was asked.
- The form that edits a model saves against the settings it was opened on, so a change made elsewhere meanwhile is still refused with a notice.

## 已知限制 / Known limits

- **Mac 上每次更新 FULI 后，系统已存的文件夹许可就对不上新版本了**，派来的活、清理和唤醒助手会等不到 Git。「系统设置」里可能仍显示为已打开。我们遇到过一次重新允许后仍然不行的情况，可靠的做法还在验证；根上的原因是 Mac 版还没有稳定的签名身份。
- 0.27.11 的「清理失败记原因、服务自己重试」还没在两台真电脑之间跑到（被上面这件事挡住了）。
- 其余限制同 0.27.12。

- **On a Mac, after every update of FULI the folder permission the system stored no longer matches the new version**; requests, cleanup and waking an assistant then wait for a Git that does not answer. System Settings may still show it as on. We met one case where allowing it again did not help, and a reliable way is still being checked; the root cause is that the Mac build has no stable signing identity yet.
- The "failed cleanup names its cause and is retried" of 0.27.11 has not run between two real computers yet (blocked by the above).
- The other limits are those of 0.27.12.
