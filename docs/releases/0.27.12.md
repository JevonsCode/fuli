# FULI 0.27.12

0.27.12 发在 `latest` 渠道。修一件事：另一台电脑派来的活，在 Git 没回应或读不了项目文件夹时，不再被说成「这个文件夹不是 Git 仓库」。没有数据格式变化。

0.27.12 is on the `latest` channel. It fixes one thing: when Git does not answer, or cannot read the project folder, for work another computer asked for, FULI no longer says the folder is not a Git repository. No data format change.

## 更新内容 / What's new

两台电脑都更新到 0.27.11 后，三件真实的活在 Mac 上都报「不是仓库」，可那个文件夹明明是仓库。查下来是 Mac 更新 FULI 后，系统要你重新允许它访问「文稿」里的文件夹；没人点，Git 等了 15 秒被掐掉，而 FULI 把「没等到回答」读成了「不是仓库」。这一版让它照实说：是 Git 没回应，并提示在 Mac 上多半是这个原因。

After both computers were on 0.27.11, three real requests ended "not a repository" on the Mac, in a folder that is one. After an update, macOS asks again whether FULI may read folders in Documents; nobody answered, Git was stopped after 15 seconds, and FULI read "no answer" as "no repository". This version says what happened: Git did not answer, and on a Mac that is usually why.

## 改了什么

- **不再误报「不是仓库」**：只有 Git 自己说不是仓库（或文件夹已经不在了）才这么报。Git 没回应、被系统拒绝或出了别的错，这件活以「Git 出错」结束，原因只给这台电脑的主人看：没回应，或 Git 的原话（去掉本机路径）。
- **卡片上的提示**：Git 没回应时，主人的卡片写明这件活没法做，并提示在 Mac 上 FULI 更新后系统常要你重新允许它访问这个文件夹。
- 发起的那一方读到的是「没做成」，不带原因，因为原因可能透露那台电脑的情况；它的助手会告诉你请那台电脑的主人看一下。

## In English

### Fixed

- **No more false "not a repository".** Only Git's own answer that the folder is in no repository (or a folder that is gone) reads that way. A Git that did not answer, was refused by the system or failed otherwise ends the request as a Git failure, with the cause for this computer's owner only: no answer in time, or Git's own line without local paths.
- **A hint on the card.** When Git did not answer, the owner's card says the work could not be done and that on a Mac an update of FULI often needs folder access allowed again.
- The requester reads "failed" with no reason, since the cause may describe the other computer; its assistant tells you that computer's owner has to look.

## 已知限制 / Known limits

- **Mac 上每次更新 FULI 后，都要重新允许一次它访问「文稿」「桌面」「下载」里的项目文件夹**，否则派来的活、清理和唤醒助手都会等不到 Git。原因是 Mac 版还没有稳定的签名身份。这一版只是把它说清楚，没有解决。
- 0.27.11 的「清理失败记原因、服务自己重试」还没在两台真电脑之间跑到（被上面这件事挡住了）。
- 其余限制同 0.27.11。

- **On a Mac, after every update of FULI, its access to project folders in Documents, Desktop or Downloads has to be allowed again**; until then requests, cleanup and waking an assistant wait for a Git that does not answer. The Mac build has no stable signing identity yet. This version says so clearly; it does not solve it.
- The "failed cleanup names its cause and is retried" of 0.27.11 has not run between two real computers yet (blocked by the above).
- The other limits are those of 0.27.11.

## 数据格式 / Data format

没有变化。

No change.
