# FULI 0.25.0

0.25.0 是 0.23.0 之后的下一个稳定版，发在 `latest` 渠道（没有 0.24，也没有 0.25 的预览版）。从 0.23.0 升级不需要你确认任何迁移：数据格式的变化在升级时自动完成，会改已有存储的那一步先做备份，见文末「数据格式」和「安装和升级」。
0.25.0 is the next stable release after 0.23.0, on the `latest` channel (there is no 0.24 and no 0.25 preview). Upgrading from 0.23.0 needs no confirmed migration: every data format change runs automatically, and the one step that changes an existing store makes a backup first. See "Data format" and "Install and upgrade" below.

0.25 让 FULI 越用越省：说过一次的事它记住，下一次任务少花 token；桌面安装包成了主要的安装方式，Windows 和 Mac 双击就装；Tonborg 拿不准的事交给你自己的 AI 讲给你听；控制台里的事也能让 AI 来做。下文是相对上一个稳定版 [0.23.0](0.23.0.md) 的变化。
0.25 makes FULI cheaper the longer you use it: what you said once is remembered, so later tasks spend fewer tokens. The desktop installers become the main way to install, a double-click on Windows and Mac. Your own AI explains what Tonborg is unsure about, and it can run the console for you. Changes are listed against the previous stable release, 0.23.0.

## 更新内容 / What's new

这一版 FULI 学会了省钱：你说过一次的事它就记住了，用得越久，AI 花的 token 越少。有了桌面安装包，Windows 和 Mac 双击就能装，从此和终端互不打扰。Tonborg 拿不准的事，点一下「?」就能让你的 AI 一条条讲给你听，你答一句它就记下。控制台里的事也能交给 AI 操作，页面顺手从头到脚打磨了一遍。更新完重启一下你的 AI 客户端，它们也该喝杯咖啡了 ☕

FULI learned to save money: say it once and it remembers, so your AI spends fewer tokens over time. Desktop installers: double-click to install on Windows and Mac, no terminal required. When Tonborg is unsure, click 「?」 and your AI walks you through each item; one answer records it. Your AI can now run the console for you, and every page got a polish. Restart your AI clients after updating. They deserve a coffee too ☕

## 越用越省：记得住，带得少（rec#88）

- **测出来的结果**：官网 [/report/](https://xn--8ovp9s.xn--m8txu.com/fuli/report/) 用九个连续会话测了一轮：每完成一个任务，开着 FULI 用的 token 是不开的 0.81 倍（中位数 327k 对 405k），完成 70/72 个任务，不开时 56/72。省下的主要来自只在之前会话里说过、代码里没有的事。
- **任务入口只带要用的**：每个任务开头不再重复「一切正常」的状态、当前范围、固定说明和重复的项目 ID；新项目的入口只说谁在负责、怎么查；同一会话的后续任务只补变化。还没存任何东西的项目，后续提问不会再被拿去搜。
- **召回更准**：提到某个对象时，保留点名那条知识的那句话；召回的每条只说一次；只是顺带提到的待确认条目只给标题；要求检查通过的任务会拿到之前记下的检查命令。
- **自己结束的任务也留下发现**：Claude Code 的 Stop hook 自己结束任务时（没有模型 checkpoint），会把这一轮真正验证过的事留下来，等你确认，例如「先跑 `npm run fixtures` 再跑 `npm test`」、最后跑通的项目脚本、你明确说过的规则。不调用模型。
- **不再把 AI 的回复当知识**：以前 Stop hook 会把 AI 回复里的一句话存成待确认经验，连 FULI 自己的标记和回执一起；现在回复一律不存，任何保存前先去掉 FULI 的标记。已经存进去的，在「待决策」里归成一组，可以一次不要，也能撤回。
- **重复的知识合并成一条**：同一件事存了两遍（同样的话、一条完全包含另一条且后说、或同名同数字且语义向量几乎一样）会合并成一条当前知识，其余退为历史。规则偏严：宁可漏合，也不错合。
- hook 学习时会跳过客户端自带的说明和引用的报告。

## 桌面客户端是主要的安装方式

- **Mac 安装包**：打开 dmg 是一张图：把 FULI 拖进「应用程序」，下半部分三张图说明第一次打开未签名应用要怎么点。从「应用程序」第一次打开时，FULI 会自己推出安装盘；直接在安装盘里打开时，提示一键「移到『应用程序』」。窗口大小按 Finder 的边框算好，整张图一次看全。
- **Windows 安装包**：`FULI-Setup` 换成图文向导；第一次安装可以选装到哪里（默认 `%LOCALAPPDATA%\Programs\Fuli`，不要管理员权限），更新时沿用原来的位置。客户端顶栏的按钮让到窗口按钮下面，不再被挡住。
- **和 npm 版共存**：先用 npm 装过 FULI、再装桌面客户端时，客户端接管服务：只运行一份 FULI，已接入的 AI 客户端改指向客户端自带的那份，npm 那份可以一键卸掉，`fl` / `fuli` 命令也能放进 PATH。控制台会提示电脑上还有一份 npm 版。
- **会话会把 FULI 叫起来**：关掉桌面客户端后，打开着的和新开的 AI 会话会自动启动已安装的 FULI，FULI 自己退出了也会拉回来；你主动停掉的，不会被会话重新启动。FULI 卡在半关闭状态时，会话能发现，`fuli start` / `fuli restart` 也能把它收拾掉再启动。
- **更新后的提示**：更新完，控制台右下角浮出一次「更新到 0.x.y 了」，「查看详情」里是这一版的几句更新内容和 GitHub 发布页链接；跳过了几个版本会说中间还有几个。每个版本只出现一次，新装不出现。
- **在客户端打开**：在浏览器里开着控制台、电脑上又装了桌面客户端时，顶栏第一个按钮是「在客户端打开」，在客户端窗口里打开同一页。
- **回执链接回到 http**：Claude Desktop 会显示 `fuli://` 链接但点了没反应，所以回执里的链接一律用 `http://127.0.0.1:<端口>/…`，在每个聊天客户端里都点得开。FULI 更新换了端口后，链接会找到真正的端口。`fuli://` 协议注册和客户端自己的链接不变。

## 待决策：一张清单，Tonborg 帮你看

- **一张「待决策」清单**：顶栏的待决策和「知识整理」都打开同一页，只列等你的事，按原因分组：Tonborg 想问你的、待确认的知识、Agent 在问你的。每组有一个整组操作（全按猜的办、全部确认），「全部确认」分批进行并显示真实进度。列表很长时也流畅，右侧目录带数量。系统自己推出来的项目结构不再列出来让你确认。
- **交给 Tonborg 确认**：打开后，Tonborg 替你确认知识；它拿不准的才问你，问题用你的语言，已经决定过的不再问，答过的问题不再重复。每个问题给的选项是为这一条写的，而不是固定的三个按钮。
- **让你的 AI 讲给你听**：「Tonborg 拿不准，要你定」旁边有个「?」。点一下，FULI 用一句话在你已接入的客户端里开一个新会话，你的 AI 以 Tonborg 的身份一条条讲：这是什么、为什么这么猜、留下或不要会怎样；你答一句，它带着你的原话记下。不在项目里也能用；超过 5 条会先问你先听几条。
- **新会话在每个客户端里都能开**：Codex、Claude Code、Claude Desktop、Cursor 等能用链接开新会话的用链接，其余的在新终端窗口里启动它的命令行，都不行时给你复制。

## 控制台：AI 能替你做，页面重新打磨

- **让 AI 来做**：控制台每个区域的「?」里有一句可以复制给 AI 的话，或者直接交给 AI 的按钮；支持 WebMCP 的浏览器里，页面还会向你的 AI 提供打开页面、搜索知识、读和配置模型、测试连接等工具。模型密钥只在本机由你自己输入。
- **模型有了自己的页面**：`/models` 取代「设置 › 模型」（旧地址会跳过去）。模型名可以从接口列出的模型里选，也能自己输入；「千问」不再单独存，成了地址建议之一。给推理模型留出思考的余量，截断时说清原因。Dreaming 卡片显示每个项目有几个新会话，可以原地运行或从头再读一遍。内置 Agent 的模型设置默认允许 AI 代你修改，可在「设置 › AI 权限」关掉。
- **顶栏**：模型按钮和托盘各有自己的悬浮面板；电源按钮偶尔闪一下故障效果，关着时是素的，模型出错时变红；待决策有事时会轻轻晃一下，满了是一碗冒尖的米饭。顶栏的刷新只刷新当前页。某个客户端要更新时，「设置」上有红点。
- **工作台**：新增「最近你可能需要知道的事」；每个列表显示七条，「更多」进入它自己的页面，带搜索、筛选和分页。
- **统一的样子**：每个 FLA 的头像是同一个组件，到处都能右键；页面目录挪到右边缘，像一把尺子，当前项只换文字颜色；页面切换时直接全宽出现；小控件里的文字真正居中；按钮和链接不会被选中成文字；英文和客户端 460pt 的窄窗口下排版不再错位；「一键接入」时每个客户端的状态即时刷新。

## FLA 会成长

- **起步包**：每种职业的 FLA 有一个起步包插件，引用开源项目里许可证宽松的检查清单（固定版本，带许可证原文），推荐对应的 Skills 和 MCP 服务，用不用由你选，每次选择都留着。
- **记住纠正，变成验收**：你纠正 FLA 时，它会分清是这次任务的一次性要求，还是以后都要遵守的规则；能检查的规则会变成验收项或回归例子。任务结果和「学会了」的每条经验都标明验证状态：人确认、自动验证通过、AI 评估通过、尚未验证。
- **重复的步骤问你要不要做成工具**：同一个 FLA 在同一项目里 3 次以上做完全一样的步骤时，在待决策里问你：做成脚本、做成 Agent App，还是不用。从经验整理出的 Skill 一开始就带着工作地图（输入、输出、依赖、分支、验收、问题）。
- **任务复盘**：团队任务完成后，Astro 写一份简短复盘，可复用的经验进入你的待确认队列，不会自动生效。
- **在外面解决的阻塞**：在新的 AI 会话里解决了 FULI 任务的阻塞，任务负责人从别的会话汇报进展时会解除它；证据不够时显示「可能已解决」，由你确认。

## 客户端和 `#FLA`

- **`/fla` 选人**：在 AI 客户端的斜杠菜单里输入 `/fla`，列出你的 FLA（名字、项目、职责），选一个就和 `#FLA 姓名` 一样。默认打开，可在「设置 › 客户端」关掉；Codex 应用里以提示文件出现。
- **只用 `#FLA` 点名**：`@` 留给客户端的附件和文件路径，`@名字` 不再当成点名，开头带附件的消息不会再报「指定 FLA 不存在」。
- OpenCode 在 WSL 里运行、FULI 在 Windows 上时，能打开它自己的目录了。

## 其他变化

- 记一下时没列出的 `workKind` 不再让偏好保存失败。
- 清理：删掉没接上的服务端代码和组件，所有 SQLite 多步写入走同一个事务入口；删掉过时的文档和无关的示例。
- 官网重做：从头到尾的滚动故事、FLA 头像、安装章节用真实客户端截图、模型指南和 token 报告；README 改为图文版，中英文各一份。

## In English

- **Cheaper the longer you use it (rec#88)**: the [/report/](https://xn--8ovp9s.xn--m8txu.com/fuli/report/) run of nine sessions measured 0.81× the tokens per finished task with FULI (median 327k vs 405k), with 70/72 tasks done against 56/72 without it; the saving comes mostly from facts said only in an earlier session. A task entry leaves out routine state, the current scope filter, repeated rules pointers and repeated project IDs; a fresh project's entry keeps who leads and how to read; later tasks in a session send only what changed; a project that stores nothing is not searched on follow-ups. Recall keeps the clause that names a kept fact, says each item once, sends a pending item named only in passing as a title, and hands kept check commands to a task that must pass its checks. When the Claude Code Stop hook closes a task by itself, it keeps what the turn verified (a script that only passed after another ran first, the project scripts that ran clean, rules you stated), pending your review, with no model call. The Agent's reply is never kept and FULI markup is stripped before any capture; replies kept by mistake earlier are grouped in 待决策 to drop together, undoably. Duplicate knowledge (same words, a longer copy said later that covers the shorter one, or the same names and numbers with near-identical meaning vectors) merges into one current item, the rest becoming history; the rules prefer a missed merge to a wrong one. Hook learning skips client notes and quoted reports.
- **The desktop client is the main install**: the macOS dmg is one picture (drag FULI to Applications, plus three pictures for the first unsigned open), sized to fit under Finder's chrome; the first open from Applications ejects the installer, and an open from the disk image offers one-click Move to Applications. Windows `FULI-Setup` is a picture-led wizard that lets a first install choose its folder (default `%LOCALAPPDATA%\Programs\Fuli`, no administrator); updates reuse it. The Windows client's top bar sits below the caption buttons. When FULI was installed with npm first, the desktop client takes over: one FULI runs, connected clients are repointed to the app's copy, the npm copy can be removed in one click, and `fl` / `fuli` can go on your PATH. Open client sessions start the installed FULI and bring it back when it stops by itself, but never after you stopped it; a console stuck half-closed is detected by sessions and cleared by `fuli start` / `fuli restart`. After an update the console shows once what is new, with 查看详情 and a link to the release; skipped versions are counted, and a fresh install shows nothing. A browser console offers 在客户端打开 / Open in app when the desktop client is installed. Receipt links are `http://127.0.0.1:<port>/…` again, because Claude Desktop shows `fuli://` links but does nothing when they are clicked; links follow the console's real port after an update. `fuli://` registration and the client's own links are unchanged.
- **One 待决策 list, with Tonborg**: the top bar's 待决策 and 知识整理 open one page listing only what waits for you, grouped as Tonborg's questions, knowledge to confirm and Agent requests, each with a group action; 全部确认 confirms in batches with real progress; long lists stay smooth and the outline shows counts; system-derived project structure is no longer listed. 交给 Tonborg 确认 lets Tonborg confirm knowledge for you and ask only what it is unsure about, in your language, never again once answered or decided, with choices written for each item. The 「?」 beside its unsure items opens a new session in a connected client where your own AI, as Tonborg, explains each item and records your answers in your words; it works outside a project and asks how many to hear first above five. New sessions open in every connected client: through its prompt link when it has one (Codex, Claude Code, Claude Desktop, Cursor and others), else its CLI in a new terminal, else a copy button.
- **Console**: every area's 「?」 has a sentence to copy to your AI or a button that hands it over, and in browsers with WebMCP the page offers your AI tools to open pages, search knowledge, read and configure models and test connections; model keys are still typed only by you on this computer. Models get their own page, `/models` (the old address redirects): pick the model from what the endpoint lists or type one, 千问 becomes an address suggestion, reasoning models get room to think and truncation says why, and the Dreaming card shows new sessions per project and runs in place or from the start. Built-in Agents' model settings are delegable by default (Settings › AI permissions turns that off). The model button and the tray get hover panels; the power button glitches now and then, stays plain when off and turns red when a model fails; 待决策 wiggles when something waits and is a heaped bowl of rice when full; refresh reloads the page in view; Settings gets a red dot when a client needs an update. The workbench adds 最近你可能需要知道的事, and each list shows seven with 更多 opening its own page with search, filters and paging. One avatar component for every FLA, right-clickable everywhere; the outline is a ruler at the right edge whose active item only changes colour; pages appear at full width; small controls centre their labels; controls are not text-selectable; English and the client's 460pt width lay out cleanly; 一键接入 refreshes each client as it connects.
- **FLAs grow**: each occupation gets a starter-kit plugin quoting permissively licensed open-source checklists at a pinned commit (license text included) and recommending Skills and MCP servers, which you choose to use, every answer kept. A correction is kept either as a one-off requirement of this task or as a lasting rule, and a checkable rule becomes an acceptance item or regression example; task outcomes and learned experiences show 人确认 / 自动验证通过 / AI 评估通过 / 尚未验证. When one FLA repeats the same steps in three or more tasks of a project, 待决策 asks whether to make a script, an Agent App, or nothing; a Skill drafted from kept experiences starts with its work map. Astro writes a short retrospective of finished team tasks, whose lessons wait for your confirmation. A block solved in another session clears when the task's lead reports from it, or shows as probably resolved for you to confirm.
- **Clients and `#FLA`**: `/fla` in a client's slash menu lists your FLAs (name, project, role) and picking one is the same as `#FLA <name>`; it is on by default, Settings › Clients turns it off, and the Codex app gets it as prompt files. - **Other**: the roundtable reports delivery honestly (not delivered, in a desktop conversation, unconfirmed) with the reason, shows bare member IDs and explains a foreign token. The website is rebuilt as a scroll story with FLA portraits, the real client in the install chapter, the model guide and the token report; the README is illustrated, in English and Chinese.

## 数据格式

图谱从格式 18（0.23.0）升到 19。`graph/19-blocker-resolution-evidence` 只扩展可以存的字段（谁解除了阻塞：Agent 或你确认的，以及「可能已解决」的证据），不改任何记录，自动完成。

Agent 工作流存储 `agent-workflows.sqlite` 升到格式 2：`agent-workflows/2-work-map` 给版本表加一个可以为空的 `work_map` 列，先用 SQLite 在线备份，再自动完成；之前的版本保持为空。

偏好会话记录升到第 4 版，旧版本的记录照常读取，不需要迁移。

新增的本地存储都在第一次使用时创建，不需要确认：`occupation-kit-choices.sqlite`（每个 FLA 用了起步包里的哪些 Skills 和 MCP，每次选择都保留）、`occupation-plugins.json`（已应用的起步包清单和更新记录）、`console-autostart.json`（你是否主动停了 FULI、会话何时启动过它）、`desktop-app-adoption.json`（桌面客户端已接管过哪些 npm 安装）、`cli-path.json`（是否把客户端的 `fl` / `fuli` 放进 PATH）、`whats-new.json`（上次显示过更新提示的版本）和 `session-prompts/session-prompt-sentences.json`（最近会话提问的句子哈希，用于任务入口召回，不存原文）。

模型密钥现在绑定保存时的接口地址（协议、主机、端口），只给这个地址用。升级后第一次打开时，旧密钥会绑定到用它的那个连接的地址；没有连接在用，或者几个连接在不同地址共用同一个密钥的，要在模型页为对应地址重新保存一次。

升级后的图谱和 `agent-workflows.sqlite` 0.23.0 打不开，退回需要升级前的备份。

The graph moves from format 18 (0.23.0) to 19. `graph/19-blocker-resolution-evidence` only extends the stored fields (a block an Agent resolved or you confirmed, and the probably-resolved evidence), changes no record and runs automatically.

`agent-workflows.sqlite` moves to format 2: `agent-workflows/2-work-map` adds a nullable `work_map` column to the version table, automatically after an online SQLite backup; earlier versions keep it empty.

Preference-session records move to version 4; older records are read as they are, with no migration.

New local stores are created on first use with nothing to confirm: `occupation-kit-choices.sqlite` (which starter-kit Skills and MCP servers each FLA uses, every answer kept), `occupation-plugins.json` (the applied starter-kit manifest and its updates), `console-autostart.json` (whether you stopped FULI and when sessions started it), `desktop-app-adoption.json` (npm copies the desktop client took over), `cli-path.json` (whether the client's `fl` / `fuli` are on your PATH), `whats-new.json` (the last version whose notice was shown) and `session-prompts/session-prompt-sentences.json` (sentence hashes of recent prompts for the entry recall, no text).

Model keys are now tied to the endpoint (scheme, host, port) they were saved for and read only for it. On the first open after the upgrade, an older key is tied to the address of the connection that uses it; a key no connection uses, or one shared by connections at different addresses, must be saved again on the model page for its endpoint.

0.23.0 cannot open the upgraded graph or `agent-workflows.sqlite`, so going back needs the backup from before the upgrade.

## 安装和升级

需要 Node.js >= 24.12（桌面客户端已内置）。

- **Windows**：在控制台「设置 › 版本」点「更新到 v0.25.0」一键更新；或下载 `FULI-Setup-0.25.0.exe`（核对同名 `.sha256`）双击，已装过的会直接更新，数据保留。也可以下载 `fuli-windows-tray-0.25.0.zip`（核对同名 `.sha256`），解压后运行 `Update-Fuli.cmd`。安装包暂未签名，SmartScreen 会提示一次。
- **macOS（FULI.app，Apple 芯片）**：在「设置 › 版本」点「更新到 v0.25.0」一键更新。第一次安装：下载 `fuli-macos-arm64-0.25.0.dmg`（核对同名 `.sha256`），把 FULI 拖进「应用程序」再打开。
- **npm**（虚拟机、云和服务器）：

```sh
fuli stop
npm install --global fuli-context@latest
fuli setup --yes --connected-only
fuli --version
```

升级前照常备份（`fuli graph export --output <目录>`，并复制数据目录）。升级后重启一下已接入的 AI 客户端，让它们用上新版的 MCP 和 hook。想回到 0.23.0：升级过的数据只能用升级前的备份恢复；Windows 安装版可以用安装目录里的 `Rollback-Fuli.cmd` 回到更新前的版本（只切换程序，不回退数据）。
