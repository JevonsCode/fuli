# FULI 0.8.0

## Project teams and continuity

- Keep one project team lead as the default conversation owner, with user-selected durable members. HR and project managers retain their peer roles.
- Grow teams as HR recruits: the first durable hire becomes the lead and later hires join the team. Users can disable automatic enrollment and change team membership.
- Preserve user choices with version-checked updates, exclude temporary workers from fixed teams, and expose unavailable members for removal.
- Let a newly recruited lead adopt the current unassigned task, including blocked work, without replacing an existing owner.
- Save employee work results independently of optional knowledge capture and memory updates. Restore recent work across clients and show it in employee details.
- Preserve incomplete and failed outcomes. Repeated checkpoints remain idempotent; conflicting retries are rejected.

## Personal profile and pending actions

- Read all profile graph pages instead of treating the first page as the complete personal profile.
- Classify writing taste separately from judgment preferences and preserve session, turn, and time evidence.
- Calculate writing-profile progress from actual evidence, including older supported provenance formats.
- Open an employee's concrete pending requests from the raised-hand control, with the requested action and an explicit response flow.

## Maintenance

- Separate team enrollment, first-task adoption, and work-history reading into focused Provider modules while retaining shared client orchestration.
- Remove verified unused UI computations, imports, and a CLI parameter.
- Keep MCP startup instructions within the client limit, support larger preference collections, and explicitly warn when context delivery is incomplete.
- Harden asynchronous UI reads and saves against stale responses and duplicate expansion events.

## Upgrade

Update the npm package and its managed Provider together, then reconnect active client sessions so they discover the new tools and schemas. Existing memories remain versioned in Neo4j; old task contexts remain readable. Fixed-team membership does not grant additional tools, data, model, or publication permissions.

See [employee continuity](../project-agent-memory.md) for the data model, lifecycle, and test boundaries.
