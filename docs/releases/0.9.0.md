# Fuli 0.9.0

This stable release integrates v0.9.0-beta.2 with the pending local console and lifecycle compatibility work.

## Changes

- Every task entry supplies a required, directly renderable FULI Agent identity line. Shared MCP instructions, lifecycle guidance and operating Skills require it in every final reply, including greetings and capture-disabled tasks. Unauthorized or unavailable roles return a neutral identity; an earlier task's owner must never be reused.
- MCP and Hook serialization preserve the complete identity receipt when other context exceeds its budget. A budget too small for the receipt fails explicitly. The common MCP instructions remain within the host's 2 KiB limit.
- A unified console design brings Agent cards, current-work summaries, keyboard-accessible profile tabs, scoped attention drafts, compact settings and reusable loading states. Deep links containing dotted Agent identifiers work after refresh. The public website and its original logo are retained.
- Current-task lookups have bounded timeouts. Codex's first entry can proceed without restoring or importing Agent history if the Provider endpoint is unavailable; established ownership guards remain fail-closed.
- Native runtime startup verifies the transcript contract, rejects implicit Provider downgrades including native revisions, and cleans up only processes it started when startup fails.
- Roundtable workers leave task entry, memory checkpoints and final user replies to the outer host. Codex uses a per-process developer-instruction boundary without changing the user's configuration.
- Roundtable protocol, persistence, invitations, explicit execution permissions, review and result history from beta.2 are retained. Experimental adapters retain their existing qualification labels.

Run the database integration suites separately: some fixtures deliberately reset synthetic data or re-bootstrap a principal. Concurrent suites against one database invalidate each other's credentials and are not a supported test setup.

## Limits

A required receipt is a Fuli protocol contract delivered to the host; Fuli does not intercept arbitrary text generated by every external client. A receipt does not prove that an independent model worker ran or that memory was saved.

The core package's stable release does not promote experimental Pi/Ollama, external A2A, xAI, or cross-computer execution into universally verified integrations. Credentials, reachable services and authorized artifact access are still required. See the [Roundtable validation history](../roundtable-beta-validation.md) for prior evidence and adapter boundaries.

## Upgrade

```sh
npm install -g fuli-context@0.9.0
fuli setup --yes
```

Reconnect MCP or open a new client session to load the updated entry and reply contracts. Existing knowledge and Agent memory remain in the configured local data store.
