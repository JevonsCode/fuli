# FULI 0.20.0（草稿；当前公开预览版 0.20.0-beta.10）

- 会话不再自动建项目、自动招人：没有归属的会话交给固定助理接待，Jefa 在收尾时分诊，同一话题反复出现（累计 3 个会话、跨至少 2 天）时，Astro 先问你要不要成立项目、招人长期维护（beta.6 起，之前是自动立项）；同意后这些会话归入新项目，选「暂不」则再多 3 个会话才再问。
- 项目必须有简介；Agent 必须有职业，Bole 按职业招聘，组长只负责拆活、派活和收口。
- 新增项目间取记忆权重（有关系 / 常往来 / 密切），项目关系图和项目页可直接看到；权重不授予权限。
- 圆桌可以按项目找到对方组长，完成限定请求后把结果交回原组长。
- 任务入口大幅缩小（约 −66%），共享规则改为按需读取；新增 Token 门禁，入口或工具说明变大会被测试拦下。
- Windows 已安装版本可以用 Update-Fuli 预览并升级，保留数据和旧版本，失败自动回退。
- 新控制台外壳：六个入口（星图、Agents、对话、项目、记忆、设置），侧边栏可展开，窄屏用底部 Tab；统一的按钮、下拉、开关等共享组件。
- 按住 Alt（Mac 上是 Option）或点顶栏的 ⓘ，再点任意状态或名词，就能看到解释。
- 知识和偏好显示权重百分比（待确认 10–69%、Agent 确认 70–95%、你确认 100%），不再用二元的确认状态。
- 日常审核交给 Tonborg；真正需要你判断的，在会话里用宿主原生的选择题问你。
- Agent 举手等你决定时，可以通知本机的 DingDong（设置 → 通知）。
- 圆桌新增 Agent 私聊、群组和互相发现（包括跨电脑），只管通信、不计权重。
- 项目列表默认隐藏临时项目，一键可以显示。
- 内置助理改名 Astro，有了自己的头像。
- 更省 Token：默认工具说明缩小约 25%，每个任务的入口减半；Hook 已经下发上下文、又没有内容可记的任务，由 Stop Hook 自动收尾，省掉一次模型往返。
- 更省 Token（rc.3）：Codex 默认用精简的 chat 工具档（工具说明 30 KB → 7.8 KB），少用的工具通过 fuli_call 按需调用；采集 Skill 从 33 KB 拆成 7 KB 核心加按需读取的参考；自动带上的旧上下文最多 4 KB，搜索结果按 8 KB 分页、可以继续读完；升级后还在运行的旧 MCP 进程会提示重启客户端。Codex 拿到的说明只提默认已列出的工具，不再每个任务先多花一次模型往返去找工具。
- 记忆的四个页面（知识、偏好、品味、知识整理）用同一套布局；偏好详情就地展开。
- 对话：圆桌和问过你用同一种左右布局；圆桌能看到 Agent 之间的私聊和群聊，座位圆环换成成员标签。
- 职业目录：内置更多职业，自定义职业必须写清楚要做的事，点职业就能看到职责；四个内置角色的职业不能改。
- Agents 页：筛选行可以按最近工作或名字排序，搜索收成一个图标；团队管理只保留一个「编排」入口。
- 不再有「待审核」页：日常审核交给 Tonborg，发布到公开项目的决定放在「公开项目 → 待发布」，有内容时才出现。
- 设置可以搜索；AI 客户端能解释每个设置的作用和影响，并给出直接打开该设置的链接（设备设置仍由你来改）。
- 工作台有四种设计可在设计实验室里切换，其中「星图」把项目画成星球、Agent 绕着转，等你的会闪、在干活的会呼吸；设计实验室还能试配色、卡片、密度、圆角和运行光环。
- 设置 → 客户端接入能发现本机已装的 Agent 客户端（新增 Gemini CLI、OpenCode、Qwen Code、Kiro），点一下就接入，接入后重启客户端即可。
- 更省 Token（rc.4）：没有可记内容的任务不再单独调一次收尾（下一次入口自动收尾）；Claude Code 不再常驻加载全部 FULI 工具说明，用到时才加载。
- 会话很长时不再卡住：转录交接失败只跳过导入，偏好和任务上下文照常送达；后台通知不再触发交接；新对话不会带出别的对话的收尾记录。
- Agent 主页把 AI 自己跑的测试、输入建议标成「AI 内部」，不再和你的任务混在一起。
- 更多页面用上统一的按钮样式。
- 3D 工作台（rc.5）：工作台新增「办公室」和「星系」两种 3D 设计，星系里项目之间按取记忆的多少画出光束；窄屏下镜头不会再卡住。
- 子组长（rc.5）：项目变大后可以在组长下面设子组长，组员向直属子组长汇报；把组员改成子组长时会自动从组员名单移出。
- 「问过你」改名「待决策」，各分区页显示目标页面的标题。
- 导出数据时会等正在退出的控制台真正停下，不再误报失败。
- Windows 卸载与回退（rc.6）：已安装目录里新增 Uninstall-Fuli（停服务、断开 Agent 客户端、删除快捷方式和全部版本，数据目录保留）和 Rollback-Fuli（回到更新前保留的旧版本，只切换程序、不回退数据）；两者都可以先 `--preview`。
- 更省 Token（rc.6）：入口的自动召回在没有已确认知识命中时，会带上 Agent 记下但还没确认的相关知识（标明「未确认」），「沿用之前的做法」类任务不用再多两次模型往返去检索。
- 长偏好完整送达（rc.6）：偏好很多时，Codex 按页读完全部偏好（每页不超过 32 KB，同一快照），不会因为工具结果被截断而只看到一部分。
- 圆桌推送（rc.6）：Agent 可以用 `agent_chat` 的 `wait` 等消息，有新消息立刻返回，不用定时去扫；控制台实时收到聊天更新；私聊或 `@` 点名会唤醒不在等待的 Agent。
- Jefa 看板（rc.6）：各项目读到就先显示，等了 8 秒会说明在等什么，30 秒结束本轮，已读到的保留、失败的标出来，可以手动重读。
- 安装脚本支持 `FULI_NPM_PACKAGE_SPEC`，正式发布前可以用候选包走一遍新用户安装。
- 记忆不再丢（rc.7）：checkpoint 记下的偏好、项目事实和经验改为按内容区分，之前后一个任务的新内容会和旧内容撞在一起被丢掉；你说「记住…」时会写进 FULI，不只写进客户端自己的记忆文件。
- 任务（rc.7）：可以只指派不开工（backlog）；可以定时创建任务，连续失败会自动暂停；每次执行（run）都会记录结果，临时故障在确定没发出指令时才自动重试；可以停止正在执行的任务、把失败的任务重新提交、查看执行记录。
- 工作台（rc.7）：先显示等你处理的事，再显示失败原因和进行中的工作；每类数据单独加载、单独报错；手机默认列表视图。
- 入口召回（rc.7）：「沿用之前的…」类问题能直接带上相关的未确认知识，提示里引用的参数不再干扰；从上次进度回答时标注「接续上次进度」。
- Windows 卸载（rc.7）：卸载后程序目录会真正删除；安装路径大小写不同也能识别。Astro 页面样式修复。
- 待决策（beta.3）：你在「待决策」里的回复会送到发起请求的 Agent。正在等的会话会被立刻唤醒；不在线的 Agent 下次进入任务时会看到。要你亲手做的事可以回复「我已完成」。
- 任务（beta.3）：任务详情里可以看运行记录、停止某一次运行，也可以把失败或取消的任务重新提交。重新提交时由你选择怎么开工；如果之前的结果不明，要你先确认。新增「定时任务」页，可以新建、暂停和恢复。
- 对话（beta.3）：手机上先看列表，点进去看详情，返回时回到原来的位置。问答和群聊分开加载，一边读不到不影响另一边。群聊可以继续加载更多会话和后续消息。
- 偏好详情（beta.3）：展开后按「摘要 → 依据 → 原始记录」显示；内容读取完整之前不能修改。Astro 里没有标题的会话显示为「未命名会话 #编号」。
- 稳定性（beta.3）：
  - 旧的执行迟到上报时，不再覆盖新的执行状态。
  - 停止操作能找到任何一次执行。
  - 状态冲突会返回明确的错误，不再是笼统的服务错误。
  - 定时任务恢复后会真正重置熔断计数。
  - Windows 上读取记录文件时不再跟随符号链接。
  - Codex ACP 冷启动较慢时不再超时。
  - Codex 用短路径记录的信任目录也能被识别。
- 测试（beta.3）：CI 现在会用真实 Neo4j 跑 Graph Provider 的集成测试，并在 Windows 上跑全部 Node 测试。
- 任务与定时任务（beta.4）：
  - 之前的运行结果不明、或运行记录没读全时，重新提交前必须确认可能的外部影响；没有权限时，旧记录和弹窗一起清掉。
  - 重新提交的结果和必须告知你的招募提示，在页面刷新后仍然保留。
  - 新建定时任务时，请求发出后表单锁住；30 秒没有回应就按「结果未确认」处理，显示实际发出的内容和时间，只能重新读取列表核对，不会再建一次。
  - 默认的首次计划时间如果已经过去，会重新计算并请你再确认一次。
  - 定时任务的记录可以直接打开对应的任务；有人同时修改时，会告诉你哪些地方变了，你确认后按最新版本保存。
- 对话（beta.4）：
  - 切换空间或失去权限时，列表和详情全部清空，迟到的旧响应直接丢弃。
  - 通过链接打开的对话，不会再被列表的「加载中 / 空」状态盖住。
  - 每次读取最多等 30 秒，同一类读取同时只有一个。同一个群聊的读取按顺序进行，已经显示的消息不会被迟到的响应收回。
  - 实时更新断开时一直提示，直到真正重新读到内容。
  - 读者停在末尾时自动跟随新消息；不在末尾或正在选中文字时，只提示并提供跳转。
  - 每条消息和整段对话都能展开完整的原始记录。手机上的长标题和成员列表会随正文一起滚动，返回列表时停在原来的位置。
- Codex 入口（beta.4）：
  - 首次启动较慢时，入口 Hook 最多等 15 秒，不再 5 秒就放弃。
  - 失败提示会写明是「超时」还是「出错」。
  - 没有 Hook 上下文的兜底任务由 Stop Hook 如实收尾，单次运行的 `codex exec` 不会一直留着未收尾的任务。
  - 转录导入超时时，提示「推迟到下一次」，不再说成「历史未验证」。
- 圆桌（beta.4）：等待消息时每 2 秒再读一次数据库，跨进程的通知即使丢了，最多晚 2 秒收到。
- 文档与网站（beta.4）：中英文 README 补充了 0.20 的新内容，修复了 GitHub 上流程图报错和中文加粗显示成星号的问题；网站同步更新。
- 升级（beta.5）：从本机 `rc` 版换到公开的 `beta` 版时，`fuli setup` 会因为 Provider 版本号更低而拒绝；现在可以先备份数据目录，再加 `--allow-provider-downgrade` 明确同意。
- 记忆（beta.5）：「写作品味」改名为「品味」。
- 测试（beta.5）：两个跨设备聊天测试在 Windows CI 上的时间上限从 7 秒放宽到 20 秒（平时要 2.5～6.4 秒）。
- 升级（beta.6）：Windows 安装版的 Update-Fuli 也加入了专门的开关 `--allow-downgrade`，可以明确允许从本机 `rc` 版替换成公开的 `beta` 版这种降版本号的更新：一条命令完成，数据和旧版本照常保留，可以用 Rollback-Fuli 回退。`fuli start` 同样接受 `--allow-provider-downgrade`。
- Astro 立项建议（beta.6）：同一话题累计 3 个会话、跨至少 2 天还没有项目时，Astro 不再自动立项，而是在那次对话的回复末尾问你，并在控制台 Astro 工作台和 Agents 页「待归属」上方显示「建议立项」卡片。选「成立项目并招人」：用话题名建项目（简介是 AI 草稿，可改），配一位负责人，负责人按需要再招成员，这个话题的会话全部归入新项目；选「暂不」：再多 3 个会话才再问。只读数据库里的话题统计，不调用模型。
- Agents 页（beta.6）：项目、状态、排序三个筛选靠在一起，不再被拉开；「按成员 / 按项目」和搜索放在右边。
- 网站（beta.6）：补充任务（只指派不开工、定时创建、执行记录与重新提交）和 Stop Hook 省 Token 的说明。
- 首次启动选择记录范围：新安装第一次打开控制台（或在终端运行 `fuli setup`）时问一次「FULI 要在哪些项目里记录？」——全部项目 / 只记我选的项目 / 先不记录。选好之前什么都不记；Agent 没有代答入口（MCP / fuli_call 都不能回答），没有终端或带 --yes 的 setup 不会提问；之后随时能在「设置 → 记忆」里改。已有用户升级不会被问，记录范围保持「全部项目」，行为和升级前一样；记录关闭时，回执里会附上打开记录的设置链接。
- 更省 Token（beta.7）：偏好、品味、性格和判断按场景送达；同一个会话里只送变化的部分（每份内容带版本号，没变就不再发）；换一个客户端也能接上最近的对话；恢复会话或读过的历史不会在下一轮再发一遍。在固定的合成回放数据上（不是真实使用数据）：较大的一组 61 轮从 328,111 字节降到 180,894 字节（约 −45%），较小的一组从 103,923 字节降到 93,500 字节（约 −10%）；每个场景的总量都不超过不做增量时。
- 记录控制（beta.7）：
  - 可以只记选定的项目，或者除了某些项目都记：项目页有「记忆这个项目」开关，设置里有「按项目记录」。
  - 在会话里说「这次别记」，只暂停这个会话的记录。单独一行输入 `/fuli stop`、`/fuli start`、`/fuli restart` 或 `/fuli status`（也可以不带斜杠），只对当前会话关闭或打开 FULI，不影响别的会话，也不删任何记忆。
  - Agent 想改长期的记录设置时，先给你看改动，你确认后才生效。
  - 每轮回复末尾列出这一轮真正存下的内容（新增 / 更新），每条都能直接点进去改；还可以查看一个会话总共记了什么。
  - 每次写入都经过同一个记录判断；判断不了时不写。
- 知识（beta.7）：
  - 修改一条知识会生成新版本，旧版本和它的来源保留为历史；「标记过时」只是不再使用，历史还在。
  - 彻底删除：只能由你在本机控制台里操作，两步确认，删除的就是你预览过的那一条。也可以删除一条来源（一段记录或整个会话）的原文，同时清理本机副本和 Agent 记忆里直接来自它的文字。Agent 没有删除入口，最多建议你打开条目页。
  - 你拒绝过的偏好，不会再因为旧的使用记录被重新提升为有效。
  - 临时项目里的会话可以批量迁到正式项目；一条事实可以同时属于多个项目，在每个选中的项目里都能搜到。
- 标签（beta.7）：标签不再写死，先复用已有标签再新建；你可以合并、重定向标签，给标签建关系。搜索会参考标签，但加权有上限（最多 ×1.25，多个标签不叠加），不会凭标签多出结果，也不绕过范围限制；条目详情可以按需解释它为什么排在这里。
- 内置 Agent 的模型（beta.7）：
  - 新的「设置 → 模型与用量」：可以给 Astro、Bole、Jefa、Tonborg 各配一个模型（地址、模型、密钥引用、允许做的事、每次和每期的预算），并查看用量。没配模型的角色由当前会话来回答，不会另起一个 CLI。
  - Bole 的绩效复盘、Astro 的「这个任务可能属于哪个项目」、Jefa 的「这可能是看板上的哪个任务」都只是建议：不绑定、不写入，可以在控制台里查看。
  - Tonborg 用你配置的模型审核知识时，可以直接写回结果；每个角色都有「只给建议」开关（默认关闭），打开后只给建议。由会话代答的结果始终只是建议。
  - 本机模型的版本（例如 Ollama）只显示在设置页，方便你和 `ollama list` 对照。
  - 模型请求不再跟随跳转，请求内容不会被转发到没核对过的地址。
- Bole（beta.7）：不调用模型的评分卡，完成情况、验收结果等分项显示、各带样本数；开除 Agent 时一定先问原因，并留下经验和交接文档。
- 客户端接入（beta.7）：Codex、Claude Code、Cursor 的接入方式改为可固定版本的描述包。`fuli clients trust|update|status|rollback`：更新先预览，已接入客户端的每个改动文件都要你单独确认（`--yes` 跳不过），失败可以回滚。
- Codex（beta.7）：单独一行输入 `fuli review` 会运行 flreview Skill（Codex 会直接拒绝 `/flreview`）。
- 任务（beta.7）：看板可以拖动卡片，也可以用「移动到…」菜单，支持键盘操作；定时任务在进程崩溃后能接着处理已认领的那一次，不会再一直卡住。
- Agent 应用（beta.7，本版还不能运行）：Agent 可以提交应用包，你批准后按版本保存；运行器、App Host 和 Windows Hello 本人验证已经就位。但本版没有隔离环境，任何应用都不会被运行（beta.9 起可以运行，见下）。
- 控制台（beta.7）：所有页面改为单一画布，不再左右分栏，详情在居中的快速查看里打开；按钮和表单控件统一；回执里的 Agent 显示为「名字 [职位]」。

## 0.20.0-beta.10：升级步骤与已知限制

**平台**：这一轮以 macOS 为主要平台。Windows（包括托盘版）在这一轮只是 beta 水平：功能都在，CI 也跑全部测试，但实测少于 macOS。

**从 beta.6 或更早的 beta 升级**（从 beta.8 或 beta.9 升级时，第 2 步可以省略，其余照做；从 beta.8 升级时 Agent 应用登记库会自动升到格式 8，beta.9 之后没有格式变化）：

1. **先备份**：导出图谱（`fuli graph export --output <备份目录>`），再 `fuli stop`，然后复制整个数据目录。图谱出问题时只能从导出整库恢复（`fuli graph import`）。
2. **先停掉旧 Hook**：0.20.0-beta.6 及更早版本的 Hook 没有会话台账格式 2 的保护（见下面「数据格式迁移」），会照旧读写台账、丢掉新内容，版本号拦不住它们。升级前退出所有接入 FULI 的 Agent 客户端（Claude Code、Codex、Cursor 等），或者先停用它们的 FULI Hook；不要让新旧 Hook 同时运行。
3. 安装新版：`npm install -g fuli-context@beta`。Windows 托盘版：退出托盘，从新包运行 `Update-Fuli.cmd`。
4. 重新运行 `fuli setup`，让每个客户端换上新的 Hook；Codex 如果提示，用 `/hooks` 再信任一次。
5. 运行 `fuli migrate status`（只读，不改任何东西）。大多数存储打开时会自动升级。显示有等你确认的步骤（`pending_confirmation`）时，先 `fuli migrate preview` 看计划，再在终端运行 `fuli migrate apply --digest <预览给出的摘要>`，或者在控制台「设置 → 数据格式迁移」确认。从 beta.6 升级时，用过定时任务的数据通常会有一步 `task-schedules/3-run-recovery`：确认之前定时任务不可用。
6. 重启 Agent 客户端。

**退回**：撤销一次迁移用 `fuli migrate rollback`。beta.6 及更早版本没有数据格式保护，读不了新格式（例如按项目记录的设置、格式 2 的会话台账），所以要退回 beta.6，只能用第 1 步的数据目录备份和图谱导出。

**已知限制**：

- Agent 应用不在沙箱里运行，拥有你账户的全部权限（见上）；`--force` 停止不支持；Windows Hello 只是 Windows 上可选的额外确认。
- Codex 的 Hook 没有可以确认的帧编号，偏好有变化时 Codex 仍会整份重发。
- 彻底删除收不回已经发布到公开项目的内容；正在运行的模型可能还记得之前的上下文。
- 模型的回答无法证明来自哪个具体版本；设置页里的本机模型版本只是观察，不是证据。
- FULI 拦不住直接写图谱的其他程序（Neo4j 客户端、cypher-shell 等）；应用或撤销迁移前先停掉它们。
- 曾从 main 或源码运行过未发布构建的环境，不保证能自动升级（见下面「兼容性」）。

In English: macOS is the primary platform this cycle and Windows is beta-level. Before upgrading, export the graph and back up the data directory, then quit every Agent client or disable its FULI hooks: hooks from 0.20.0-beta.6 and earlier are not guarded by the version 2 capture ledger and must not run next to the new ones. After `npm install -g fuli-context@beta` and `fuli setup`, run `fuli migrate status`; when it lists steps waiting for confirmation, run `fuli migrate preview`, then `fuli migrate apply --digest …` (or confirm in Settings → Data format migrations). Going back to beta.6 means restoring that backup; beta.6 cannot read the new formats.

## 数据格式迁移（首个受保护的数据格式版本）

- 升级时，FULI 只自动做不改动已有数据的格式变化（新增索引、约束、可空列），改动文件型存储前先做一致性备份；会改写或删除已有数据的步骤等你确认。用 `fuli migrate status` / `fuli migrate preview` 查看（只读），在终端用 `fuli migrate apply --digest …` 或在控制台「设置 → 数据格式迁移」确认；确认的是你看到的那份计划，计划有变化需要重新确认。
- 撤销一次迁移（`fuli migrate rollback` 或控制台）只放回这次改动的记录，之后有改动就不执行；整库恢复是单独的操作（`fuli migrate restore`，需先停止 FULI），会丢失备份之后的写入。
- 应用或撤销迁移前，请先停掉 FULI 以外直接写图谱的程序（Neo4j 客户端、cypher-shell 等工具）：FULI 拦不住它们的写入。
- 格式备份和图谱撤销日志共用一个保留预算：每个存储保留最近 3 份格式备份，图谱保留最近 3 份撤销日志；备份和日志合计最多约 1024 MB（1 GiB），超出时先清理最旧的。撤销或当前版本还需要的始终保留，即使因此超出预算。数量和总量可用 `FULI_FORMAT_BACKUP_KEEP`、`FULI_FORMAT_BACKUP_MAX_MB` 调整。`fuli migrate prune` 和每次应用、撤销迁移之后按合计预算清理；控制台启动时和整库恢复之后只清理本地备份（图谱 Provider 可能还没运行），连不上图谱时也只按预算清理本地备份。
- **兼容性**：0.20.0-beta.8 是第一个带数据格式保护、发布到 npm 的公开版本（beta.7 内容相同，但没有发布到 npm；图谱格式 11；格式 10 → 11 只新增索引和约束，自动完成）。曾从 main 分支或源码运行过未发布构建的环境，图谱可能已经是格式 10 或 11，但那些构建之后又加了存储字段，没有对应的迁移步骤，因此**不保证能自动兼容**。遇到数据格式报错时，先运行 `fuli migrate status` 查看；必要时从图谱导出恢复（`fuli graph import`）。
  - Compatibility: 0.20.0-beta.8 is the first release on npm with guarded data formats (beta.7 has the same content but never reached npm; graph format 11; 10 to 11 only adds indexes and constraints and runs automatically). Installations that ran unreleased graph format 10 or 11 builds from main or from source are not guaranteed to upgrade automatically; run `fuli migrate status` and, if needed, restore a graph export (`fuli graph import`).
- **会话记录台账升到格式 2（rec#15）**：每个会话的转录记录台账（数据目录 `transcript-capture/`）新增「任务归属未确认的轮次」。它决定这段转录能不能导入、当前任务能不能被 Stop 自动结算，所以不是可以丢掉的附加信息。格式 1 的台账照原样读取（视为没有未确认的轮次），每次写入都是格式 2。台账写不进时，这一轮改记在 `transcript-turn-holds/`；两处都写不进时，FULI 会拦下这条消息，不让它在没有保护的情况下继续。读不了、内容损坏或版本更新的台账，一律当作「仍有未确认的轮次」：不导入，也不自动结算，直到下一次真正开始新任务。
  - **边界**：这和上面的格式基线一样。0.20.0-beta.6 及更早的版本对这个存储没有格式保护，它们的 Hook 仍会照旧读写台账，会丢掉格式 2 的内容，版本号拦不住它们。**升级前请先停掉或升级所有接入同一数据目录的 Hook**（各客户端重新运行 `fuli setup`，或者先退出这些客户端），不要让新旧 Hook 同时运行。
  - **Codex 同样适用（rec#28）**：FULI 核对过的 Codex 源码（openai/codex deede720）里，Hook 输入没有 `isMeta` 字段，所以带这个标记的输入来源无法证明。它不再被直接当作“保留当前任务”，而是先检查会话是否停用 FULI，再原地刷新当前任务、标记为未确认，Stop 也读同一份台账。Codex 上 checkpoint 不会解除这种未确认状态，只有另一个任务成为当前任务时才会结束。因此 Codex 会话的台账读不了时，Stop 同样不导入、不自动结算，直到下一次真正开始新任务。没有转录路径的任务入口也不会解除未确认的轮次（两个客户端都是）。
    Codex too (rec#28): in the Codex source FULI checked (openai/codex deede720) the hook input has no `isMeta` field, so a turn marked that way has an unprovable source. It is no longer taken as "keep the current task": it passes the session-off check, refreshes the current task in place and is held as unresolved, and the Codex Stop reads the same ledger. On Codex a checkpoint does not resolve such a turn; it ends only when another task becomes current. An unreadable ledger therefore holds a Codex session as well until a fresh task entry. A task entry without a transcript path never releases held turns (both clients).
  - **导入超时不再丢掉开启期的内容（rec#16）**：任务入口的导入在交接中途超时，新任务仍会建立，交接由下一次 Hook（通常是这一轮的 Stop）按入口当时看到的内容接着完成，这一轮照常记在新任务下；旧任务来不及导入的尾部只留一条不含内容的省略标记。Stop 的导入超时后紧接着关闭了记录时，超时前这一段按当时的设置导入到当时的任务下；设置在这期间变过、或者任务已经换了，就标成“无法确认”而不是“录制已关闭”，关闭期的内容仍然一律不导入。台账多了一个可选字段 `unsynced`，仍是格式 2：旧版本丢掉它，只会退回原来的标记，不会导入任何内容。
    Capture timeouts no longer drop on-period turns (rec#16): an entry whose import times out mid-handoff still enters its task, and the next hook (usually that turn's Stop) finishes the handoff from what the entry saw, so the turn is recorded under the new task; only an old-task tail the entry could not flush becomes one content-free omission. When a Stop's import times out just before recording is switched off, the bytes it saw are imported under the task that was current then, or, if the settings changed meanwhile or the task has changed since, marked "could not be confirmed" instead of "recording was off"; off-period content is still never imported. The ledger gains an optional `unsynced` field and stays format 2: an older build that drops it only falls back to the previous marker and never imports.
  - Transcript capture ledger format 2 (rec#15): each session's ledger (`transcript-capture/`) now records turns whose task ownership is unresolved, which decides whether the transcript may be imported and whether Stop may settle the current task. Version 1 records are read as they are; every write is version 2. When the ledger cannot be written, the turn is kept in `transcript-turn-holds/`; when neither can be written, FULI holds the message back. An unreadable, corrupt or newer ledger is read as held: nothing is imported or settled until a fresh task entry. Boundary: like the baseline above, 0.20.0-beta.6 and earlier have no format guard on this store, so their hooks still read and rewrite it and drop version 2 state; the version number does not stop them. Stop or upgrade every hook that uses the same data directory before upgrading.
