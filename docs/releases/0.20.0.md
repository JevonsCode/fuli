# FULI 0.20.0（草稿；当前公开预览版 0.20.0-beta.6）

- 会话不再自动建项目、自动招人：没有归属的会话交给固定助理接待，Jefa 在收尾时分诊，同一话题反复出现（累计 3 个会话、跨至少 2 天）时，Astro 先问你要不要成立项目、招人长期维护（beta.6 起，之前是自动立项）；同意后这些会话归入新项目，选「暂不」则再多 3 个会话才再问。
- 项目必须有简介；Agent 必须有职业，Bole 按职业招聘，组长只负责拆活、派活和收口。
- 新增项目间取记忆权重（有关系 / 常往来 / 密切），项目关系图和项目页可直接看到；权重不授予权限。
- 圆桌可以按项目找到对方组长，完成限定请求后把结果交回原组长。
- 任务入口大幅缩小（约 −66%），共享规则改为按需读取；新增 Token 门禁，入口或工具说明变大会被测试拦下。
- Windows 已安装版本可以用 Update-Fuli 预览并升级，保留数据和旧版本，失败自动回退。
- 新控制台外壳：六个入口（星图、Agents、对话、项目、记忆、设置），侧边栏可展开，窄屏用底部 Tab；统一的按钮、下拉、开关等共享组件。
- 按住 Alt（Mac 上是 Option）或点顶栏的 ⓘ，再点任意状态或名词，就能看到解释。
- 知识和偏好显示权重百分比（待确认 10–69%、Agent 确认 70–95%、你确认 100%），不再用二元的确认状态。
- 日常审核交给 Tonborg；真正需要你判断的，在会话里用宿主原生的选择题问你。
- Agent 举手等你决定时，可以通知本机的 DingDong（设置 → 通知）。
- 圆桌新增 Agent 私聊、群组和互相发现（包括跨电脑），只管通信、不计权重。
- 项目列表默认隐藏临时项目，一键可以显示。
- 内置助理改名 Astro，有了自己的头像。
- 更省 Token：默认工具说明缩小约 25%，每个任务的入口减半；Hook 已经下发上下文、又没有内容可记的任务，由 Stop Hook 自动收尾，省掉一次模型往返。
- 更省 Token（rc.3）：Codex 默认用精简的 chat 工具档（工具说明 30 KB → 7.8 KB），少用的工具通过 fuli_call 按需调用；采集 Skill 从 33 KB 拆成 7 KB 核心加按需读取的参考；自动带上的旧上下文最多 4 KB，搜索结果按 8 KB 分页、可以继续读完；升级后还在运行的旧 MCP 进程会提示重启客户端。Codex 拿到的说明只提默认已列出的工具，不再每个任务先多花一次模型往返去找工具。
- 记忆的四个页面（知识、偏好、品味、知识整理）用同一套布局；偏好详情就地展开。
- 对话：圆桌和问过你用同一种左右布局；圆桌能看到 Agent 之间的私聊和群聊，座位圆环换成成员标签。
- 职业目录：内置更多职业，自定义职业必须写清楚要做的事，点职业就能看到职责；四个内置角色的职业不能改。
- Agents 页：筛选行可以按最近工作或名字排序，搜索收成一个图标；团队管理只保留一个「编排」入口。
- 不再有「待审核」页：日常审核交给 Tonborg，发布到公开项目的决定放在「公开项目 → 待发布」，有内容时才出现。
- 设置可以搜索；AI 客户端能解释每个设置的作用和影响，并给出直接打开该设置的链接（设备设置仍由你来改）。
- 工作台有四种设计可在设计实验室里切换，其中「星图」把项目画成星球、Agent 绕着转，等你的会闪、在干活的会呼吸；设计实验室还能试配色、卡片、密度、圆角和运行光环。
- 设置 → 客户端接入能发现本机已装的 Agent 客户端（新增 Gemini CLI、OpenCode、Qwen Code、Kiro），点一下就接入，接入后重启客户端即可。
- 更省 Token（rc.4）：没有可记内容的任务不再单独调一次收尾（下一次入口自动收尾）；Claude Code 不再常驻加载全部 FULI 工具说明，用到时才加载。
- 会话很长时不再卡住：转录交接失败只跳过导入，偏好和任务上下文照常送达；后台通知不再触发交接；新对话不会带出别的对话的收尾记录。
- Agent 主页把 AI 自己跑的测试、输入建议标成「AI 内部」，不再和你的任务混在一起。
- 更多页面用上统一的按钮样式。
- 3D 工作台（rc.5）：工作台新增「办公室」和「星系」两种 3D 设计，星系里项目之间按取记忆的多少画出光束；窄屏下镜头不会再卡住。
- 子组长（rc.5）：项目变大后可以在组长下面设子组长，组员向直属子组长汇报；把组员改成子组长时会自动从组员名单移出。
- 「问过你」改名「待决策」，各分区页显示目标页面的标题。
- 导出数据时会等正在退出的控制台真正停下，不再误报失败。
- Windows 卸载与回退（rc.6）：已安装目录里新增 Uninstall-Fuli（停服务、断开 Agent 客户端、删除快捷方式和全部版本，数据目录保留）和 Rollback-Fuli（回到更新前保留的旧版本，只切换程序、不回退数据）；两者都可以先 `--preview`。
- 更省 Token（rc.6）：入口的自动召回在没有已确认知识命中时，会带上 Agent 记下但还没确认的相关知识（标明「未确认」），「沿用之前的做法」类任务不用再多两次模型往返去检索。
- 长偏好完整送达（rc.6）：偏好很多时，Codex 按页读完全部偏好（每页不超过 32 KB，同一快照），不会因为工具结果被截断而只看到一部分。
- 圆桌推送（rc.6）：Agent 可以用 `agent_chat` 的 `wait` 等消息，有新消息立刻返回，不用定时去扫；控制台实时收到聊天更新；私聊或 `@` 点名会唤醒不在等待的 Agent。
- Jefa 看板（rc.6）：各项目读到就先显示，等了 8 秒会说明在等什么，30 秒结束本轮，已读到的保留、失败的标出来，可以手动重读。
- 安装脚本支持 `FULI_NPM_PACKAGE_SPEC`，正式发布前可以用候选包走一遍新用户安装。
- 记忆不再丢（rc.7）：checkpoint 记下的偏好、项目事实和经验改为按内容区分，之前后一个任务的新内容会和旧内容撞在一起被丢掉；你说「记住…」时会写进 FULI，不只写进客户端自己的记忆文件。
- 任务（rc.7）：可以只指派不开工（backlog）；可以定时创建任务，连续失败会自动暂停；每次执行（run）都会记录结果，临时故障在确定没发出指令时才自动重试；可以停止正在执行的任务、把失败的任务重新提交、查看执行记录。
- 工作台（rc.7）：先显示等你处理的事，再显示失败原因和进行中的工作；每类数据单独加载、单独报错；手机默认列表视图。
- 入口召回（rc.7）：「沿用之前的…」类问题能直接带上相关的未确认知识，提示里引用的参数不再干扰；从上次进度回答时标注「接续上次进度」。
- Windows 卸载（rc.7）：卸载后程序目录会真正删除；安装路径大小写不同也能识别。Astro 页面样式修复。
- 待决策（beta.3）：你在「待决策」里的回复会送到发起请求的 Agent。正在等的会话会被立刻唤醒；不在线的 Agent 下次进入任务时会看到。要你亲手做的事可以回复「我已完成」。
- 任务（beta.3）：任务详情里可以看运行记录、停止某一次运行，也可以把失败或取消的任务重新提交。重新提交时由你选择怎么开工；如果之前的结果不明，要你先确认。新增「定时任务」页，可以新建、暂停和恢复。
- 对话（beta.3）：手机上先看列表，点进去看详情，返回时回到原来的位置。问答和群聊分开加载，一边读不到不影响另一边。群聊可以继续加载更多会话和后续消息。
- 偏好详情（beta.3）：展开后按「摘要 → 依据 → 原始记录」显示；内容读取完整之前不能修改。Astro 里没有标题的会话显示为「未命名会话 #编号」。
- 稳定性（beta.3）：
  - 旧的执行迟到上报时，不再覆盖新的执行状态。
  - 停止操作能找到任何一次执行。
  - 状态冲突会返回明确的错误，不再是笼统的服务错误。
  - 定时任务恢复后会真正重置熔断计数。
  - Windows 上读取记录文件时不再跟随符号链接。
  - Codex ACP 冷启动较慢时不再超时。
  - Codex 用短路径记录的信任目录也能被识别。
- 测试（beta.3）：CI 现在会用真实 Neo4j 跑 Graph Provider 的集成测试，并在 Windows 上跑全部 Node 测试。
- 任务与定时任务（beta.4）：
  - 之前的运行结果不明、或运行记录没读全时，重新提交前必须确认可能的外部影响；没有权限时，旧记录和弹窗一起清掉。
  - 重新提交的结果和必须告知你的招募提示，在页面刷新后仍然保留。
  - 新建定时任务时，请求发出后表单锁住；30 秒没有回应就按「结果未确认」处理，显示实际发出的内容和时间，只能重新读取列表核对，不会再建一次。
  - 默认的首次计划时间如果已经过去，会重新计算并请你再确认一次。
  - 定时任务的记录可以直接打开对应的任务；有人同时修改时，会告诉你哪些地方变了，你确认后按最新版本保存。
- 对话（beta.4）：
  - 切换空间或失去权限时，列表和详情全部清空，迟到的旧响应直接丢弃。
  - 通过链接打开的对话，不会再被列表的「加载中 / 空」状态盖住。
  - 每次读取最多等 30 秒，同一类读取同时只有一个。同一个群聊的读取按顺序进行，已经显示的消息不会被迟到的响应收回。
  - 实时更新断开时一直提示，直到真正重新读到内容。
  - 读者停在末尾时自动跟随新消息；不在末尾或正在选中文字时，只提示并提供跳转。
  - 每条消息和整段对话都能展开完整的原始记录。手机上的长标题和成员列表会随正文一起滚动，返回列表时停在原来的位置。
- Codex 入口（beta.4）：
  - 首次启动较慢时，入口 Hook 最多等 15 秒，不再 5 秒就放弃。
  - 失败提示会写明是「超时」还是「出错」。
  - 没有 Hook 上下文的兜底任务由 Stop Hook 如实收尾，单次运行的 `codex exec` 不会一直留着未收尾的任务。
  - 转录导入超时时，提示「推迟到下一次」，不再说成「历史未验证」。
- 圆桌（beta.4）：等待消息时每 2 秒再读一次数据库，跨进程的通知即使丢了，最多晚 2 秒收到。
- 文档与网站（beta.4）：中英文 README 补充了 0.20 的新内容，修复了 GitHub 上流程图报错和中文加粗显示成星号的问题；网站同步更新。
- 升级（beta.5）：从本机 `rc` 版换到公开的 `beta` 版时，`fuli setup` 会因为 Provider 版本号更低而拒绝；现在可以先备份数据目录，再加 `--allow-provider-downgrade` 明确同意。
- 记忆（beta.5）：「写作品味」改名为「品味」。
- 测试（beta.5）：两个跨设备聊天测试在 Windows CI 上的时间上限从 7 秒放宽到 20 秒（平时要 2.5～6.4 秒）。
- 升级（beta.6）：Windows 安装版的 Update-Fuli 也加入了专门的开关 `--allow-downgrade`，可以明确允许从本机 `rc` 版替换成公开的 `beta` 版这种降版本号的更新：一条命令完成，数据和旧版本照常保留，可以用 Rollback-Fuli 回退。`fuli start` 同样接受 `--allow-provider-downgrade`。
- Astro 立项建议（beta.6）：同一话题累计 3 个会话、跨至少 2 天还没有项目时，Astro 不再自动立项，而是在那次对话的回复末尾问你，并在控制台 Astro 工作台和 Agents 页「待归属」上方显示「建议立项」卡片。选「成立项目并招人」：用话题名建项目（简介是 AI 草稿，可改），配一位负责人，负责人按需要再招成员，这个话题的会话全部归入新项目；选「暂不」：再多 3 个会话才再问。只读数据库里的话题统计，不调用模型。
- Agents 页（beta.6）：项目、状态、排序三个筛选靠在一起，不再被拉开；「按成员 / 按项目」和搜索放在右边。
- 网站（beta.6）：补充任务（只指派不开工、定时创建、执行记录与重新提交）和 Stop Hook 省 Token 的说明。
- 首次启动选择记录范围：新安装第一次打开控制台（或在终端运行 `fuli setup`）时问一次「FULI 要在哪些项目里记录？」——全部项目 / 只记我选的项目 / 先不记录。选好之前什么都不记，Agent 不能替你回答；之后随时能在「设置 → 记忆」里改。已有用户升级不会被问，记录范围保持「全部项目」，行为和升级前一样；记录关闭时，回执里会附上打开记录的设置链接。

## 从旧版本升级

| 你现在用的 | 怎么升级到 0.20.0 | 说明 |
| --- | --- | --- |
| npm 安装的 0.20.0-beta.0 至 beta.4 | `npm install -g fuli-context@beta`，然后重启已接入的 Agent 客户端 | 数据目录不变；Graph Provider 启动时会自动补齐旧数据缺的字段。 |
| 本机验收用的 0.20.0-rc.N | 先备份数据目录。npm 安装：`fuli stop` → `npm install -g fuli-context@beta` → `fuli setup --yes --connected-only --allow-provider-downgrade`。Windows 托盘版（beta.6 起）：先退出托盘，从新包运行 `Update-Fuli.cmd --allow-downgrade` | rc 是本机验收版本号，按版本规则排在 beta 前面，所以要明确同意「降版」；数据目录不变。Codex 重新接入后要用 `/hooks` 再信任一次。 |
| Windows 托盘版 0.20.0 预览版（rc.1 起） | 退出托盘，从新版候选目录运行 `Update-Fuli.cmd` | 要求已是 native 模式，且新旧包的 Neo4j 版本相同；切换失败会自动回到原版本。之后可以用 `Rollback-Fuli.cmd` 回到更新前的版本。 |
| npm 全局安装的 0.12.x 及更早（Docker 容器数据） | Windows：安装托盘版时加 `--adopt-existing-data` 接入原数据目录，再运行安装完成时提示的 `graph migrate --to native`；macOS / Linux：`npm install -g fuli-context@0.20.0` 后运行 `fuli setup` | 迁移会先导出容器数据并核对计数，失败自动切回容器。Graph Provider 启动时会自动补齐旧数据缺的字段（项目协作、知识生命周期、项目关系审核、空间可见性、发布记录、旧分组 ID），不需要手动操作。 |
| 项目组长没有职业的旧数据 | `python -m fuli_graph.migrate_lead_occupation`，先预览，再用预览摘要确认 | 只改职业字段；可以用返回的迁移 ID 撤销。 |
| 0.20.0 之前按会话自动建出的项目 | 等你确认后再迁移（R-03） | 目前只提供只读预览，不会自动改动。 |

已实测：PC 上的日常数据从 2026-09 的旧版本一路升级到 rc.5——容器数据导出、迁移到 native、托盘接入原数据、再从 rc.2 用 Update-Fuli 升到 rc.5，数据和 Agent 都在。

不支持：回退数据库内容或 schema；自动跨 Neo4j 大版本升级（需要单独迁移）；从 0.12.4 之前的版本直接升级未单独实测，建议先升级到 0.12.4 再按上表升级。
