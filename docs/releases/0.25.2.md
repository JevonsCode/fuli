# FULI 0.25.2

0.25.2 是 0.25.1 的修复版，发在 `latest` 渠道。圆桌存储会自动加三列（见「数据格式」），升级不用手动迁移；退回 0.25.1 需要用升级前的备份。
0.25.2 is a fix release for 0.25.1 on the `latest` channel. The roundtable store adds three columns automatically (see Data format), so upgrading needs no manual step; going back to 0.25.1 needs the backup made before the upgrade.

## 更新内容 / What's new

又一个小修版：叫不醒的同事，FULI 先看看它的进程还在不在，再决定让不让位。Tonborg 的模型被拒或没额度时，直接说停下，不再劝你重试。钩子出错时会说是哪条规则拦的、自己是哪个版本，排查快多了。

Another small fix: before freeing a stuck wake, FULI checks whether its process still runs. When Tonborg's model is refused or out of budget, it says stop, not try again. A failed hook now names the rule that stopped it and its own version.

## 修复

- **卡住的唤醒，先看进程再放开（rec#97）**：0.25.1 里，一个小时没人结束的唤醒会直接作废。但被唤醒的进程如果还在跑，作废后会被再叫醒一次，同一件事做两遍。现在每次唤醒一启动就记下它的进程；一小时后，查到这个进程已经结束（或者 PID 已被别的程序占用）才放开。macOS 和 Linux 上还要它启动的整个进程组都已结束；Windows 没有进程组，只看这个进程。系统判断不了时继续保留。证明不了的情况要等满 24 小时才放开：0.25.1 之前留下的、没有进程记录的占位，还没记下进程就中断的唤醒，以及 PID 被占用但进程组还在的占位。这 24 小时只是时间上限，不能证明旧进程已经退出。
- **Tonborg 的模型被拒或没额度时说停下（rec#10）**：`assess_agent_action` 等判断调用遇到外发未授权、403 或额度用完时，以前返回「可重试」并提示再试一次；现在返回不可重试，说清楚是被拒还是暂停，并提醒：用户已经做出的选择照旧有效，但要用自己的运行证据记录，不能替这次判断做决定。
- **钩子失败时说出是哪条规则（rec#85）**：以前只显示 `the hook failed: validation` 这样的错误码。现在还会写出钩子自己的 FULI 版本，以及 FULI 自己拒绝时的规则名（不带你传的值）；图谱服务拒绝时只给 HTTP 状态，不转述它的说明。一眼能分清是旧安装还是新问题。
- **协调者的进度上报不再被拒（rec#85）**：没带参与者 `agentId` 的 `record_project_agent_task_activity`，以前会从上报方自己的会话自动补 token 用量，结果被服务拒绝。现在没有参与者就不补，这类状态上报不会再因此被拒；其他校验（比如 completed、failed 的要求）照旧。
- **更正 0.25.1 的说法（rec#105）**：0.25.1 写的「图谱服务没响应时，任务照常开始」不够准确。准确地说，是入口调用不再报错，会返回 `preferences_unavailable` 并告诉 AI 继续干活；这时拿不到偏好，也不保证有任务令牌。

## In English

- **A stuck wake is checked against its process before it is freed (rec#97).** In 0.25.1 a wake that nothing ended within an hour simply expired. If the woken process was still running, it could be woken again and do the same work twice. Now each wake records its process the moment it starts. After an hour the claim is freed when that process has ended, or its PID now belongs to another program; on macOS and Linux its whole process group must also be gone. Windows has no process groups, so only that process is checked there. When the system cannot tell, the claim stays. Cases that cannot be proven wait 24 hours: claims from before 0.25.2 with no process record, a wake interrupted before its process was recorded, and a reused PID whose group still runs. That 24 hours is a time limit, not proof that the old process has ended.
- **A refused or paused Tonborg model call says stop (rec#10).** When `assess_agent_action` or another judgment hits unapproved egress, a 403 or an exhausted budget, it used to return retryable with a "try again" hint. It now returns not retryable, says whether it was refused or paused, and notes that the person's existing choice still stands but must be recorded with its own run evidence, never as this judgment.
- **A failed hook names the rule (rec#85).** It used to show only a code such as `the hook failed: validation`. It now adds the FULI version the hook ran and, when FULI itself refused, the rule (never the values you sent); a refusal from the graph service shows only its HTTP status, not its detail.
- **Coordinator status reports are accepted (rec#85).** `record_project_agent_task_activity` without a participating `agentId` used to collect token usage from the reporter's own session, and the service refused it. Without a participant no usage is collected, so it is no longer refused for that; other checks, such as those for completed or failed, still apply.
- **A correction to 0.25.1 (rec#105).** 0.25.1 said tasks still start when the graph service does not answer. More precisely, the entry call no longer errors: it returns `preferences_unavailable` and tells the AI to carry on. Preferences are missing then, and a task token is not guaranteed.

## 数据格式 / Data format

圆桌存储 `agent-roundtable.sqlite` 从格式 6 升到 7：`roundtable/7-wake-process` 给消息加三列，记录每次唤醒启动的进程。这一步在备份之后自动完成。升级后 0.25.1 会拒绝打开这个存储（圆桌和聊天在 0.25.1 里不可用）；要退回 0.25.1，需要恢复升级前的备份，恢复后会丢掉升级之后写入的圆桌消息。其他存储没有变化。

The roundtable store `agent-roundtable.sqlite` moves from format 6 to 7: `roundtable/7-wake-process` adds three message columns recording the process each wake started. It runs automatically after a backup. After the upgrade, 0.25.1 refuses to open this store, so roundtable and chat do not work there. Going back to 0.25.1 needs the pre-upgrade backup, which loses roundtable messages written after the upgrade. No other store changes.

## 安装和升级

需要 Node.js >= 24.12（桌面客户端已内置）。

- **Windows**：在控制台「设置 › 版本」点「更新到 v0.25.2」一键更新。也可以下载 `FULI-Setup-0.25.2.exe` 双击（先核对同名 `.sha256`），已装过的会直接更新，数据保留。还可以下载 `fuli-windows-tray-0.25.2.zip`（同样核对 `.sha256`），解压后运行 `Update-Fuli.cmd`。
- **macOS（FULI.app，Apple 芯片）**：在「设置 › 版本」点「更新到 v0.25.2」一键更新。第一次安装：下载 `fuli-macos-arm64-0.25.2.dmg`（核对同名 `.sha256`），把 FULI 拖进「应用程序」再打开。
- **npm**（虚拟机、云和服务器）：

```sh
fuli stop
npm install --global fuli-context@latest
fuli setup --yes --connected-only
fuli --version
```

升级后重启一下已接入的 AI 客户端，让它们用上新版的 MCP 和 Hook。

Requires Node.js >= 24.12 (built into the desktop client).

- **Windows**: click 更新到 v0.25.2 in Settings › Version. You can also double-click `FULI-Setup-0.25.2.exe` (check its `.sha256` first), which updates an existing install and keeps your data. Or unzip `fuli-windows-tray-0.25.2.zip` (check its `.sha256`) and run `Update-Fuli.cmd`.
- **macOS (Apple silicon)**: click 更新到 v0.25.2 in Settings › Version. For a first install, download `fuli-macos-arm64-0.25.2.dmg` (check its `.sha256`) and drag FULI to Applications.
- **npm** (VMs, cloud, servers): run the commands above.

After upgrading, restart your connected AI clients so they load the new MCP server and hooks.
