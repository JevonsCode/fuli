# FULI 0.27.5

0.27.5 发在 `latest` 渠道。这一版修的是「活回你这边做」第一次在两台真电脑之间跑时撞上的问题，另外更正 0.27.4 说明里的一句话。没有数据格式变化。

0.27.5 is on the `latest` channel. It fixes what work sent between two real computers ran into on its first try, and corrects one sentence of the 0.27.4 notes. No data format change.

## 更新内容 / What's new

把活派到另一台电脑，第一次在两台真电脑上跑，连撞三堵墙：对方看不到有活在等他；活被领进一个不是仓库的文件夹；设置里点了保存，FULI 一声不吭。这一版把这三堵墙拆了。

Sending work to another computer met three walls on its first real run: the owner could not see that work was waiting; the work was led into a folder that is no repository; and Save in settings said nothing at all. This version takes the three walls down.

## 修复

- **等你拍板的活看得见了**：别的电脑发来、等你批准的活，不用刷新就出现在「今天」页，也不会被别的事项挤出去。
- **不用再填文件夹**：你的助手平时待在一个「装着项目仓库的工作区」里时，FULI 直接用里面以项目名命名的那个仓库。
- **文件夹不是仓库时直说**：这件活在出方案之前就结束并写明原因，不再白白唤醒助手，也不再多报一条清理失败。
- **保存共享会说结果**：浮出一句「已保存共享：N 个项目」，或者为什么没保存。
- Git 步骤失败时，本机记下 Git 的最后一行原因（不含本机路径）；不会发给对方。
- 共享里「本机项目文件夹」的说明改了：对方发来的活也在它的副本里做，请填仓库所在的目录。

## 更正 0.27.4 的说明

0.27.4 写「被别的电脑唤醒的助手只带 FULI 的工具」。这在 Claude Code 上成立；在 Codex 上不成立：一次实测里，你自己在 Codex 里接的其他服务仍被带了进去。修好之前，如果不希望这样，共享项目时只勾 Claude Code。

## In English

### Fixed

- **Work waiting for you is visible.** Work another computer sent that needs your approval shows on Today without a reload and is never pushed out by other items.
- **No folder to fill in.** When your assistant works in a workspace folder that holds the project's repository, FULI uses the repository in it that carries the project's name.
- **A folder that is no repository is named as such.** The request ends before a plan is made, with its reason; no assistant is woken for nothing and no false cleanup failure is added.
- **Saving shares says what happened.** A line floats up: how many projects are shared, or why it was not saved.
- When a Git step fails, this computer records the last line of Git's message (without local paths); it is never sent to the other computer.
- The hint under a share's local project folder now says that sent work runs in a copy of it, so it should name the repository folder.

### A correction to the 0.27.4 notes

The 0.27.4 notes said an assistant woken by another computer carries FULI's tools only. That holds for Claude Code. It does not hold for Codex: in one real run, other services you had added to Codex were still loaded. Until that is fixed, tick only Claude Code on a share if you do not want this.

## 已知限制 / Known limits

- 两台真电脑之间还没有一件活完整跑完：五次尝试都停在「文件夹不是仓库」这一步。这一版里，保存共享的提示和一次真实更新在一台 Windows 上走过；其余修复只在自动测试里验过，macOS 上都还没验。
- macOS 应用内的一键更新，从 0.27.4 起由修过的更新程序执行，但还没有在真实的 Mac 上走过一次。想稳妥就下载 dmg 覆盖安装。
- 其余限制同 0.27.4：活只用 Claude Code 执行；访客链接在网络上是明文；Claude Code、Cursor、OpenCode 的任务入口拿不到模型名。

- No piece of work has run to the end between two real computers yet: five tries all stopped at the folder that is no repository. In this version the save message and one real update were run on one Windows computer; the other fixes were checked by automated tests only, and nothing on macOS.
- The in-app update on macOS is run by the corrected updater from 0.27.4 on, but it has not gone through a real update on a real Mac yet. Installing the dmg over the app is the safe way.
- The other limits are those of 0.27.4: work is run by Claude Code only; a guest link travels unencrypted; the task entries of Claude Code, Cursor and OpenCode cannot learn the model name.

## 数据格式 / Data format

没有变化。可以直接退回 0.27.4。

No change. Going back to 0.27.4 needs nothing.
