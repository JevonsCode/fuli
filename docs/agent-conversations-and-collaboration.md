# 对话与协作

同一 FLA 在兼容 MCP 的客户端中沿用持久身份。历史对话、版本化工作记忆和已确认知识各自保存；
记忆层与权限见[员工身份与记忆](project-agent-memory.md)。

## 恢复与压缩

| 设置 | 默认行为 |
| --- | --- |
| 压缩阈值 | 64 KB；可配 8–1024 KB。只按对话量折叠，不因闲置遗忘 |
| 恢复预算 | 4000 UTF-8 字节；可配 512–16000，属于内容预算，不是计费 Token |
| 自动恢复 | 同一 Agent、同一全局或项目范围的摘要和最近消息 |
| 摘要 | 最近 12 个任务结果及有来源的规则摘录；不调用模型编造摘要 |
| 原文 | 敏感内容过滤后 gzip 保存，按需分页补读；工具输出不自动注入上下文 |

同一原生会话再次进入任务时，宿主已持有最近消息，入口只保留最新任务结果与省略条数；换会话或换客户端
仍交付完整恢复窗口。与任务无关的规则文字（任务、偏好、团队、记忆与接续说明）在入口中只给版本化引用，
全文在 MCP 资源 `fuli://rules/task-entry`；无法读取资源的封闭 worker 仍收到全文。

最新任务结果单独放在 `context.latest_checkpoint`，保留真实状态；较早结果与摘录放在
`context.summary`，标为 `summary_role: historical`。旧 TODO 不代表当前待办，未完成任务
不会因压缩变成完成。两者按 JSON 编码字节计入同一预算，超长和省略明确标注。

自动摘录按固定标记保留请求首行、决定、更正、未完成事项与方法，不分析代码块或工具输出。
每条附角色与事件序号；完全相同的完整文本才去重，并保留首个及最近三个来源。
单条最多 240 UTF-8 字节，摘录文本合计最多 6000 字节、80 条；先舍弃旧请求和方法，最后才舍弃决定、
更正与未完成事项。截断前缀不参与去重，省略数量可见。摘要最多占恢复预算的一半。
摘录未经核实，可能漏掉无标记决定或误分类；原文始终是依据，旧摘录不能覆盖新用户指令。

## 跨客户端接续

1. 收尾保存真实结果，返回当前负责人、保存状态和 `conversation_id`。
2. 在另一客户端选择同一授权范围和 FLA，取得该宿主当前 `taskContextToken`。
3. 用 `resume_agent_conversation` 恢复指定会话；细节用 `read_agent_conversation` 分页补读。

入口支持开头的完整姓名或稳定 `@{agentId}`；正文中的 @ 不切换身份。同名、停用、项目不符
或无权限时不换人兜底。个人页可复制包含 Agent、项目与会话 ID 的接续指令。
接续只传已保存文本与引用，不搬运本地文件、进程或客户端工具状态，也不转交旧任务 token。

偏好仍按全局、项目、Agent 作用域和确认状态读取，完整指令与写作品味域保留；写记忆前完整
读取 revision。自动摘录、工作摘要和 AR 配置的性格不能伪装成人工确认的用户偏好。

## 采集与失败恢复

Codex、Claude Code 的宿主适配器增量读取宿主提供的当前 JSONL transcript，仅识别可见文本、
工具调用及结果，不采集隐藏推理、系统提示或附件二进制。其他客户端通过标准 MCP 保留任务关联
与工作摘要，不宣称已自动同步原文。入口不另存相同提示词，避免与转录采集重复。

- 从当前任务边界开始，不导入安装前历史；稳定事件 ID 去重，事件与游标同事务提交。
- 未完成行等下次读取，数据库失败不推进游标；超限内容保留省略标记，后续记录继续采集。
- 切换 Agent 或项目前先验证提示词边界，旧尾部归旧身份；每阶段最多 8 页，每页最多
  50 条、512 KiB。超批次明确要求重试，从已保存进度继续，不猜测归属。
- EOF 不能单独证明当前提示词边界。未验证消息留在宿主；持续无法绑定时，新建宿主会话并
  显式恢复已保存的会话，不删除 guard 强行切换。
- 本地 guard 只保存不可逆 hash 与游标，0600 原子写入；短期 loopback 互斥锁串行保护同会话。
  `Stop` 只提交确定归属的尾部，不替用户开启新任务。失败提示不能当作记忆恢复成功。

客户端格式、Hook 投递、数据库持久化和模型遵守指令分别验收；配置成功不等于已接续成功。

## 小组与借调

组长负责统筹、集成和交付；AR 与 Jefa 保持同级职责。显式点名先校验目标，组长统筹，
授权委派保留成员身份；自动沿用遵循项目策略，新招聘不覆盖已有组长。
任务路由按有效任职、能力、任务类型、负载和连续性选执行者，
合格员工仅因当前客户端不可用时阻塞任务，不另招替代者。

`plan_agent_collaboration` 用既有任职和派工记录返回分工，不额外启动模型：

| 工作 | 默认安排 |
| --- | --- |
| 低影响小修改或只运行命令 | 当前负责人继续 |
| 实质性改动 | 主线实施 + 非作者 FLA 独立验收 |
| 有明确独立边界的复杂工作 | 主线 + 一个独立工作包 + 验收；强耦合改动保持一起 |

组长按职业派活：请求带 `occupation` 时，同职业成员优先于工作类型匹配，组长本人只统筹；验收默认优先 `testing`。委派工作的执行方式按隔离程度依次选择：新开会话 → subAgent → 分阶段；宿主用 `hostExecutionModes` 说明能运行哪几种，`divisionPlan.execution` 只给选中方式的说明。分阶段只把记忆按工作包分开：每段结束先读取该 Agent 的记忆，再用 `checkpoint_project_agent_memory` 写回，任务仍由组长统一收尾。

规划传入实际作者，验收排除这些作者；只携带目标、范围、授权产物、验收条件与必要查询，
不复制整段会话。先复用合格人员；跨项目执行须来源组长批准借调，并创建目标项目独立任职。
借调不传来源项目私有记忆，不扩大固定小组；任务结束后归还。
`message_agent` 是只读咨询；执行仍需 `coordinate_project_agent_task` 和授权宿主启动 worker。
配置、推荐、计划和借调批准都不代表实际执行。

## 计划与更新

有明确计划时，通过 `record_project_agent_task_activity.executionPlan` 上报稳定步骤 ID、
标题和状态；后续送完整快照，省略表示未更新，`steps: []` 撤回。没有计划不强制生成，
不从内部思考推测进度或百分比，步骤完成不替代任务验收。

Provider 保存活动后用 SSE 通知同一空间读取变化任务；共享连接、重连同步，无任务库轮询。
结束、收起或页面隐藏时取消订阅；断线保留内容并提示。通知只带任务 ID，内容仍走授权读取。
个人 Provider 以单进程运行，重启后重新同步数据库，保活心跳不读取任务库。

## 模型与结果

显式用户策略、客户端与执行器锁优先。能力档位和成本是系统配置，不能凭模型名称猜能力；
满足授权和能力要求后再考虑成本。缺少证据时明确未验证，不将配置模型当实际模型。

验证绑定真实 executor run、模型与 `artifactRevision`，相同 run 不重复计次。两次同档失败
提高能力要求，最高档连续失败交由用户处理；旧版本结果不放行新版本。任务完成保留当前产物
验证要求，模型上报、自动测试和用户验收各自记录。

默认界面突出负责人、状态和当前工作，对话按需展开，技术细节收在高级区域。
