# 自定义客户端接入

状态：优化项已记录；自主注册界面和注册 API 尚未实现。

注册入口应按客户端能力生成配置，避免把支持范围写成固定品牌名单。现有内置适配器继续提供快捷安装，自定义客户端使用同一生命周期协议。

建议流程：填写客户端名称 → 声明能力 → 获取配置 → 发两轮消息验证。注册本身不授予工具、项目或执行器权限。

## 能力声明

- 稳定的客户端、会话、轮次标识及真实项目目录。
- MCP 连接方式，以及是否能在每轮开始时注入上下文。
- Hook 事件名称、输入字段、输出格式、超时和输出大小限制。
- 是否能读取最终答复、校验回执并请求模型纠正。

支持 Hook 的客户端可自动执行入口并校验收尾；仅支持 MCP 的客户端提供模型驱动的入口规则，并明确它不能证明每轮都执行。若支持客户端直接渲染身份栏，应优先展示结构化回执，减少对模型正文的依赖。

## 验收状态

分别显示“已配置”“已连接”“已验证”，保存协议版本、验证时间与结果。连接到 MCP 不等于已注入入口，也不等于身份回执已显示。未知身份必须显示未验证，不能沿用上一轮负责人。

连续两轮验收需检查真实入口事件、独立任务上下文、检查点和可见回执；还应覆盖缺少项目、服务不可用、旧轮次回执和缺失回执。验证只证明所测版本与场景，不保证任意模型永久遵守规则。

## JSON Hook 适配器

本次新增 `src/agents/json-hooks/cli.js`，适用于以下协议：

- `UserPromptSubmit`：stdin 含 `session_id`、`run_id`、`cwd`、`prompt`；stdout 顶层 `additionalContext` 注入当轮。
- `PostToolUse`：匹配检查点工具，stdin 含 `tool_name`、`tool_input`、`tool_response`；收集当前任务检查点返回的最终回执。
- `Stop`：stdin 含相同身份字段与 `last_assistant_message`；stdout 的 `decision: block` 和 `reason` 请求补齐检查点或回执。

三个事件使用同一命令。传入 `--client-id`，以及本机安装对应的 `--runtime-root` 和 `--runtime-config`；路径属于用户本机配置，不写进共享文档。要求 Node.js 版本符合包的 engines。宿主超时需大于 28 秒，stdout 上限至少 64 KiB。事件支持的 matcher 语法由宿主决定。

适配器使用 `sourceApplication: other`，不冒充某个原生客户端。只在运行时保存会话、轮次、任务 token 和当前回执，不保存用户原始消息或工具原始输出。主 Agent 身份不会被继承相同宿主标识的子 Agent 覆盖。

这些字段及流程是待评审的通用接入设计；适配器尚未接入现有自动安装注册表。实际客户端配置和两轮验收应单独记录结果。
