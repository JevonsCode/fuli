# 员工身份与记忆

FLA 是个人空间中的持久身份，兼容 MCP 的客户端是工作入口。切换客户端沿用同一身份和
已授权的数据，不复制员工、不扩大权限。Provider 是事实源；Node 编排接口，控制台读取同一边界。

## 数据与作用域

| 内容 | 范围与用途 |
| --- | --- |
| 身份、风格、执行偏好 | 个人空间中的稳定 Agent ID；配置不等于实际成长或执行证据 |
| 项目任职与小组 | 精确项目中的职责与有效任职；管理范围不授予私有记忆权限 |
| 全局工作记忆 | Agent 自己的摘要、决定、未完成事项和下一步，独立 revision |
| 项目工作记忆 | 同一 Agent 在一个项目中的工作上下文，独立 revision |
| 可见对话 | 按空间、作用域、Agent 隔离的日志；恢复与采集见[对话与协作](agent-conversations-and-collaboration.md) |
| 工作记录与知识 | 工作记录保留真实来源和状态；可复用知识另走提炼与确认流程 |

全局范围用 `personalProjectId: null` 表示，绝不是所有项目。后续任职不会把全局与项目
数据迁移或合并。工作记录、历史对话和自动摘录都是上下文，不会变成新的指令或人工确认的知识。

## 任务入口

1. 从工作目录解析精确项目；Git 工作树沿用原仓库，歧义不猜测。已解析项目必须校验任职，
   拒绝后不能退回全局。未匹配项目时显式选择 FLA，可以使用其独立全局上下文。
   请求开头写出已注册项目名，或写“新项目：名称”，会直接归入该项目或新建一次；其余未认领的会话
   不建项目、不招人，作为待归属会话交给固定助理（`employee.assistant`）在全局范围接待，助理身份
   尚未就绪时如实显示“待归属会话”。同名命中多个项目时如实显示“项目归属待确认”，归档项目不参与
   名称匹配。待归属会话的入口只附 `triage_candidates`（项目名与话题名）；收尾时宿主在
   `checkpoint_task_knowledge.triage` 中标注“属于某项目 / 话题 / 一次性”，记在 Jefa 名下，不调用模型。
   用户的纠正和已成形的项目不会被后续宿主标注覆盖。同一话题累计 3 个会话即自动立项：简介标为
   AI 草稿，经 AR 配组长，这些会话关联到新项目；标注失败只让会话继续待归属，不影响收尾。
2. 恢复负责人、职责、偏好和有限近期记录。项目任务同时读取该 Agent 的项目层与全局层：
   `memory` 是项目层，`global_memory` 是全局层；分别校验范围与 revision，分别报告读取失败。
   全局任务只读一次全局层，`task_only` 身份不读取长期记忆。
3. 创建当前任务的 `taskContextToken`。入口只交付记忆预览；更新前须用
   `get_project_agent_memory` 完整读取，再按 revision 合并。预览截断必须明确标注。
4. Hook 已交付当前上下文时不重复入口；未交付时用 `get_collaboration_preferences`，
   传真实宿主 session ID、工作目录与当前请求。配置、连接和选人都不证明已经执行。

没有有效负责人时，可由 AR 协调或招募；首次接管仅限同一未结束任务、同一项目和有效小组长。
Provider 重新检查任职、客户端权限与任务状态，不能覆盖已有负责人。

## 检查点与恢复

`checkpoint_task_knowledge` 保存知识保留判断和真实 `workLog`。没有新知识用
`retain_nothing`，仍记录结果；状态支持 `reported`、`completed`、`incomplete`、`failed` 和 `no_change`。

长期记忆变化时附 `agentMemory`、已读 revision 和合并内容；每份最多 32 KiB，不保存原始聊天、
凭据或临时日志。任务检查点只更新任务所在层；更新全局层须显式使用 `personalProjectId: null`，
不自动复制项目内容。重复相同提交不重复写入，版本冲突明确返回；中断任务保留未完成状态。

材料实际影响了回答或完成的行动时，可显式附 `knowledgeUsage`（`itemId`、`itemKind`、
`useKind: cited/applied`）。它与 prepare 的检查点声明、工作记录及所附记忆在同一事务记账；
失败全部回滚，重试及重启重放原始回执，内容代次变化后也不重记。`retain_nothing` 仍可携带
真实工作记录与已发生的使用；不会从日志或自动注入的偏好推断使用。既有独立
`record_knowledge_usage` 保持兼容；在同一任务混用时以 task token 为 `taskId`，沿用逐项、
逐代次与使用类型的幂等键。使用仍只按既有规则产生 `agent_confirmed`，不替代人工确认。

共享宿主任务由主协调者整合并提交检查点，worker 只返回活动、结果和证据，不传递主任务 token。
独立宿主任务有自己的生命周期。下一次入口读取有限工作记录和记忆，详细内容按需补读。

入口与最终检查点返回 `agent_receipt.markdown`；最终回复原样显示一次，以当前检查点回执为准。
无有效身份不沿用旧负责人。回执不是 worker 执行、知识保存或客户端验收证明。

## 控制台

人员目录点击姓名进入个人页，展示任职、工作、协作和有来源的风格。工作历史先按 Agent 过滤，
再应用数量上限；仅分配或排队不算已合作。高级配置在 `/project-agents/manage`。

“对话与记忆”提供全局及有效任职项目。管理范围不作为对话范围。工作记忆只读展示 revision、
来源、时间、摘要、决定和待办；失败可重试，切换身份或范围后丢弃旧响应。导出按钮只下载当前范围。

## Markdown 快照与导出

数据库始终是依据，目录只是便于查看与交接的投影；手动修改 Markdown 不会导入数据库。
长期员工在 FULI 数据目录中使用 `agents/<Provider哈希>/<空间哈希>/<Agent哈希>/`：

- `AGENTS.md`：允许列出的身份与职责，不含任职清单、凭据、运行路径或任务 token。
- `MEMORY.md`：全局记忆；`projects/<项目哈希>/MEMORY.md`：单个项目记忆。注明 scope、revision、
  生成时间和只读投影说明。无记录与疑似敏感内容明确标注，不编造。

快照只在完整、已授权且范围校验通过的读取后生成，不额外读取其他项目。任务检查点只标记
对应文件过期，后续读取重建；旧 revision 不覆盖新版本，快照失败不影响成功的数据库操作。
文件 0600、目录 0700，原子替换；受管理路径为符号链接或非常规文件时拒绝写入。
重复读取不重写未变文件，不修改目录里的其他文件。`directorySnapshot` 仅返回相对路径、
范围、revision 与状态，不返回本机绝对路径或原始错误。

`export_project_agent_memory` 与控制台的 `GET /api/project-agents/:agentId/memory/export`
共用导出边界：重新从数据库读取，并严格校验外层、当前记录和历史的空间、项目、Agent、scope
及 revision。只导出允许字段和一层记忆，不读快照、不接受输出路径、不包含原始对话或凭据。
Agent 入口校验真实来源客户端及任职；控制台沿用本机所有者权限。远程连接器不开放该工具。
导出返回文件名与完整 Markdown；超出预算明确报错，不交付半个文件。可选快照写入失败不阻断导出。

旧员工无需重建或迁移项目记忆；首次授权读取补建投影，全局层在首次检查点前为空。
身份、工号、项目记忆及历史 revision 保持原有数据库记录。

## 验证边界

协议与界面测试覆盖范围隔离、身份、版本冲突、任务接管、旧响应与失败恢复。
数据库测试使用显式的一次性 Neo4j 和合成数据；与真实客户端 Hook 验收分别记录。
跨客户端接续、压缩、借调和执行计划见[对话与协作](agent-conversations-and-collaboration.md)。
