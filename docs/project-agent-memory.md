# 员工身份、项目小组与工作接续

员工是持久身份，Codex、Claude Code 和 Cursor 是执行入口。客户端通过同一个
Provider 读取已授权的员工和项目记录。切换客户端不会复制身份，也不会扩大访问范围。

## 人员目录与个人主页

`/project-agents` 是简洁的人员目录，点击姓名进入 `/agents/:spaceId/:agentId`。
个人主页展示 AR 配置的判断、品味、个性、用户期望，以及有来源的任职、招聘、
工作和合作记录。未填写的风格不自动编造；角色描述不等于实际成长证据。
合作次数只统计双方实际参与过的任务，不把排队或仅被分配算作已合作。

组织关系来自各项目的协调策略。AR 人员目录支持名字、技能、职责、项目和任务
模糊检索，在本地完成，不额外调用模型。也可让客户端中的 AR 通过人员工具查询。
主页设置可修改执行平台偏好和期望；锁定的执行平台仍受原策略约束。
技术性配置保留在 `/project-agents/manage` 高级管理入口。

## 数据分层

| 层 | 内容 | 存储和边界 |
| --- | --- | --- |
| 身份 | 姓名、职责、能力、客户端与执行器偏好 | 个人空间中的稳定 Agent ID |
| 任职 | 负责的项目、职责及任职历史 | 精确的空间、项目和 Agent |
| 项目小组 | 小组长、长期成员、自动归组策略 | 项目协调策略；AR、项目经理保持同级 |
| 工作记录 | 本次结果、状态、来源客户端和时间 | Provider 中的任务生命周期记录 |
| 可见对话 | 用户消息、助手回复和工具记录 | 同一数据库中独立日志；按空间、项目、Agent 隔离 |
| 私有工作记忆 | 摘要、决策、未完成问题、下一步 | Neo4j 中按空间、项目、Agent 隔离的版本记录 |
| 项目知识 | 需求、架构、来源和确认状态 | 现有知识提炼与确认流程 |

工作记录与工作记忆是有来源的工作上下文，不是新的用户指令或自动确认的事实。
任何客户端都不能以小组成员关系为由读取其他成员的私有记忆。

## 小组随项目成长

新项目可以没有专业员工。AR 按任务需要招募长期员工；默认首位成为小组长，
后续新员工加入小组。归组与招聘处于同一个事务中，失败时一起回滚。
临时协作者只参加任务，不进入固定小组。

用户可以在项目协作设置中选择小组长和成员，或关闭“新员工自动归组”。
招聘不会覆盖已有的小组长和用户策略。固定小组最多包含一位组长和 32 位成员；
失效任职会明确显示为不可用，并允许移除。策略更新检查版本，避免旧页面覆盖新配置。

自动沿用开启时，项目小组长是默认沟通负责人。显式指定有效员工仍然优先；
关闭自动沿用后需要手动选择。角色、职能、模型策略和执行器偏好仍由用户配置。
小组策略不改变 AR 与项目经理的管理权限，也不授权启动任意 worker。

## 任务入口与首次接管

1. 根据当前目录解析项目：先匹配精确 ID，再允许唯一的大小写等价 ID。工作树以原仓库
   为准，不以任意工作树文件夹名覆盖原项目；多个候选或相近但不同的名字不猜测。
2. 选择具有有效任职、允许当前客户端的员工，并恢复职责、项目简介、近期任务、工作记录和记忆。
   项目任务同时恢复同一员工的全局记忆：`memory` 是当前项目层，`global_memory` 是全局层
   （项目为 `null`），两层各自校验空间、项目、员工和 scope，各自保留 revision；
   任一层读取失败只把该层列入 `unavailable_components`，不隐藏另一层。全局任务只读取一次全局层；
   `task_only` 员工两层都不读取。任务入口预览对每层分别限长并标注 `notesTruncated`。
3. 开始持久化的任务上下文，返回 `taskContextToken` 和当前记忆 revision（只绑定任务所在层）。
   任务检查点只写该层；全局层须用 `personalProjectId: null` 单独、显式写入，不自动复制项目内容。
4. 如果任务入口尚无员工，协调时传入当前 token。新招的小组长可以接管同一任务；
   即使执行器阻塞，也能保留阻塞原因与下一步。

首次接管只允许当前任务、同一项目及协调结果中的小组长。Provider 锁定相关记录后
重新检查有效任职、客户端权限和任务状态，不允许更换已有负责人或接管结束的任务。

宿主 hook 未提供上下文时，先调用 `get_collaboration_preferences` 恢复偏好与员工信息。
钩子配置、客户端允许列表和执行器可用状态都不等于模型已经执行了任务。

Claude Code 的 `UserPromptSubmit` 和 `Stop` 使用独立本地命令适配器
（`src/agents/claude-code/lifecycle-hook.js`）。它通过现有应用接口和运行时租约
访问 Provider，不依赖客户端 MCP 已经连接；模型主动调用工具仍使用原 Fuli MCP。
接入更新会迁移旧 `mcp_tool` Hook，保留其他 Hook 和权限设置。命令通过 stdin
读取事件；只增量读取宿主明确提供且会话身份匹配的当前 transcript，不扫描其他会话，
也不把用户输入拼接进 shell 命令。Provider 不可用时
给出未验证提示，在宿主超时前退出；不能将降级提示记为记忆恢复成功。

Stop 首次发现未提交的检查点时要求补交；第二次仍未完成时只记录 `incomplete`，
避免无限续跑。部署后应在新 Claude Code 会话验证入口上下文和结束检查，独立
`claude mcp get fuli` 成功不能替代该验证。

## 结束与恢复

`checkpoint_task_knowledge` 将知识保留判断和员工工作记录一起结束：

```json
{
  "taskContextToken": "<current task token>",
  "disposition": "retain_nothing",
  "reason": "No confirmed knowledge changed.",
  "workLog": {
    "status": "incomplete",
    "summary": "Implemented the reader; the deployment check still needs attention."
  }
}
```

没有新知识可提炼，也要给已分配的员工留下简短、真实的工作结果。`workLog` 支持
`reported`、`completed`、`incomplete`、`failed` 和 `no_change`。
当长期工作记忆发生变化时，再提供 `agentMemory`，携带已读取的 revision 与合并后的内容。
每份记忆最多 32 KiB；不要保存原始聊天、凭据或临时日志。

Provider 对新任务强制检查工作摘要，并把摘要、状态和幂等指纹绑定。
重复完成不重复写入，修改同一次提交会返回冲突；旧版本任务保留兼容入口，缺失摘要
明确标为 `unreported`。中断而未结束的旧任务标为 `incomplete`，不会伪装成成功。
Codex 的最终 Stop 兜底同样保留未完成状态。

下一次入口读取最近六条工作记录，以及当前版本的长期记忆。员工详情的“工作记录”
按项目展示同样的数据，包含来源客户端、时间、结果和状态。失败的读取提供重试；
切换员工或项目后，旧请求不能覆盖新页面。

## 模块职责

- `project_agent_team_growth.py`：招聘事务内的自动归组。
- `task_context_adoption.py`：首次接管的权限、状态和并发检查。
- `store_task_contexts.py`：生命周期、不可变提交和原子记忆准备。
- `project_agent_work_log.py`：从生命周期记录恢复有限工作历史。
- `project-agent-task-entry.js`：各客户端共用的员工与项目恢复。
- `src/agents/`：客户端适配，保留各宿主的事件协议差异。

Provider 是持久化事实源；Node 负责接口编排；前端消费相同的读取边界。
生产任务上下文只使用 `ProviderTaskContextRegistry`，进程内实现仅作为测试夹具。
共享宿主任务的 worker 只汇报工作活动和结果，主协调者整合后统一提交任务检查点；
分发上下文包含这一生命周期策略，不转交主任务 token。独立宿主任务仍拥有自己的
检查点。共享 MCP 没有可信子进程身份时，这属于宿主协作协议，不能当作服务端强隔离。
角色恢复、任务协调和实际 worker 执行分别记录，不以选择结果代替执行证据。
MCP 上下文有长度上限。被截断时必须显式补读完整记忆后再合并，不能宣称已完整恢复。

## 验证

单元与协议测试覆盖跨客户端映射、工作记录、首次接管、小组策略、前端交互和错误状态。
`graph-provider/tests/test_project_agent_team_lifecycle_neo4j.py` 与已有记忆、任职和招聘
集成测试使用一次性 Neo4j，通过公开 HTTP 接口验证真实持久化、事务、幂等、权限和重启恢复。

运行数据库测试前设置 `FULI_TEST_NEO4J_EPHEMERAL=1` 与指向一次性本机数据库的
`FULI_TEST_NEO4J_URI`。这些测试全部使用合成角色和数据；协议测试、真实数据库测试
与真实模型客户端验收属于不同证据，不能互相替代。

可见对话的按量压缩、跨客户端接续、借调与验证升级见
[对话与协作](agent-conversations-and-collaboration.md)。

## 必需的回复身份回执

`begin_task_context` 和 `get_collaboration_preferences` 始终返回 `agent_receipt`，其中 `required: true` 和 `markdown` 构成统一的回复契约。宿主 Agent 必须在每次最终回复中原样显示一次这行身份与个人页面链接；问候、失败、没有可沉淀知识或关闭自动沉淀都不例外。无可用授权身份时返回 `FULI Agent：未选定`，不借用上次任务的身份。旧版本入口没有回执时应明确说明身份不可用。

MCP 与 Hook 交付会为完整回执保留空间，其他上下文超长时也不截断回执；预算不足以容纳回执时返回明确错误。该要求通过共享 MCP 指令、入口说明和操作 Skill 交付；外部宿主最终生成的文字仍由该宿主负责遵守，Fuli 不伪称能拦截所有客户端输出。身份回执不证明模型工作者已经启动，也不证明知识或会话已经保存。

## 全局 FLA 上下文

FLA 身份、模型策略和执行器偏好属于个人空间，可以没有项目任职。项目仍需负责人。
未匹配项目的会话显式选择 FLA（`projectAgentId` 或开头的 `@{agentId}`）时，直接恢复
该 FLA 的全局对话与工作记忆，不创建会话项目或临时任职；同一宿主会话后续沿用全局身份。
已明确解析出的项目仍走项目任职校验，无法访问时不会回退到全局。

对话与记忆工具省略 `personalProjectId` 或传 `null` 表示精确的全局范围，绝不是所有项目。
全局范围与每个项目分别保存对话、恢复策略、工作摘要及记忆 revision；后续任职不会迁移、
合并或继承这些数据。全局读取不会自动加载任何项目任务或知识。已有项目记录保持兼容。
全局写入仍检查个人空间权限、身份状态、客户端允许列表、任务 token 和记忆版本。

主页和高级管理页的“对话与记忆”都提供“全局”选项；项目选项只来自有效任职，
管理范围本身不会授予项目私有对话权限。无项目 FLA 的全局会话也支持跨客户端接续。

## 检查工作记忆与压缩摘录

“对话与记忆”展开后按所选范围（全局或某个项目）读取已有的
`GET /api/project-agents/:id/memory`，显示当前 revision、来源客户端、时间、摘要、决定、
未完成事项和下一步；没有检查点时明确显示为空，读取失败可重试，切换范围会丢弃旧响应。
工作记忆是任务检查点保存的工作上下文，不等于人工确认的知识。这里只读，不提供编辑入口。

对话超过压缩阈值后，较早消息按固定规则抽取原句，不调用模型，也不声称理解语义：

- 用户消息的首行作为请求标题；用户与 Agent 消息中带有更正、决定、未完成或方法标记
  （如 `Decision:`、`TODO`、`instead`、`决定`、`待办`、`方法`）的行按此分类保留。代码块与工具
  输出不抽取。
- 每条摘录记录来源角色与事件序号；去除首尾空白后完全相同的文本（区分大小写与内部空白）只保留一条并追加来源（保留首个与最近三个，
  同一来源不重复），因此更新的说法与较早的说法并列出现，不会覆盖旧来源。被截断的摘录只是
  前缀，不参与去重，避免把前缀相同的不同决定合并。
- 单条摘录最多 240 UTF-8 字节，整体最多 6000 字节、80 条；超出时先移除最旧的请求标题，
  再移除最旧的方法，最后才移除决定、更正与未完成事项。未抽取的行（含代码块中的代码行）
  和被移除的行计入 `omitted`。
- 恢复上下文时整段摘要（任务结果、旧请求、摘录）最多占预算的一半：任务结果单条按 240 字节
  截断；超出时依次移除旧请求、请求标题与方法、最旧的任务结果，最后才移除决定、更正和未完成
  事项。标题注明“不是经核实的工作记忆、原文仍保留”，并给出省略与截断数量。旧版纯文本摘要
  按序列化后的 JSON 字节（含转义）裁去较早部分，保证整个恢复结果不超过预算。
- 旧摘要中的 `notes`（首行请求）继续可读，新摘录追加在其后，不改写历史数据。

阅读原文时首页返回同一份摘录，界面区分“自动摘录，未经核实”与工作记忆，显示来源序号、
截断与省略说明；原文消息带同样的序号，可在现有分页历史中找回。规则无法识别未带标记的
决定，也可能把带关键词的普通句子误分类；原文始终是依据。设计参考 Mem0 的抽取、合并去重和
保留来源，以及 LongMemEval 关注的时间更新与弃权维度，仅作为合成测试的验收方向，并未运行
这些公开基准。

## 员工目录快照（第一阶段）

每个长期员工（`memory_scope: reviewed_agent`）在 FULI 数据目录下有一个只为查看和交接生成的
目录：`agents/<Provider>/<个人空间>/<员工>/`。三级目录名都是稳定 ID 的哈希，不受显示名、改名
或不安全 ID 影响；不同 Provider、个人空间和同名员工互不重叠。只有通过 runtime config 打开的
应用会生成快照，没有全局回退位置。

- `AGENTS.md`：允许列出的身份与职责（名称、ID、工号、类型、状态、职责、能力、初始偏好、
  性格与期望），不写分配列表、凭据、运行路径、会话或任务 token。
- `MEMORY.md`：全局工作记忆；`projects/<项目哈希>/MEMORY.md`：各项目工作记忆。每个文件注明
  范围、数据库 revision、生成时间，以及“由数据库生成、不是依据、修改不会导入”。没有记忆时
  如实写明尚无记录。疑似含凭据的旧内容不写入文件。

数据库始终是依据。快照在已授权的完整读取之后生成：`get_project_agent_memory` 写入所读范围；
控制台的“对话与记忆”（`inspectProjectAgentMemory`）以本机所有者身份读取，同样补齐或重建所读
范围，不套用员工的客户端白名单；任务入口写入本次已读取的全局层和项目层（在热路径预览裁剪之前），
不额外读取其他项目。写入前用任务入口相同的范围校验检查整个视图和当前记录：员工、项目、空间或
revision 不符时只刷新身份文件，不把内容写到所请求的范围下。
`checkpoint_project_agent_memory` 在数据库提交成功后用返回的记录刷新；任务检查点不返回记忆
内容，只把对应文件标记为 `stale`，下次授权读取时重新生成；较晚到达的旧标记不会撤销尚未
读取的新 revision。快照不属于数据库事务。

旧员工不需要迁移：首次授权读取时补齐目录，不写数据库、不改 revision、不改名或招聘。重复读取
不改写未变化的文件；删除或手动修改的生成文件会按数据库重建；目录里其他文件保持原样。旧
revision 不会覆盖已写入的新 revision（即使新文件已被删除）。

文件 0600、目录 0700，原子替换；任何受管理路径是符号链接或非常规文件时拒绝写入。并发写入用
目录内的短锁：已被占用时立即返回 `busy`，遗留超过 30 秒的锁会被清理。文件系统失败不会影响
已成功的数据库读写。工作记忆读取、记忆检查点、任务检查点（`agent_memory` 内）和任务入口
（`project_agent_context` 内）的结果，包括通过 MCP 返回时，都用公开字段 `directorySnapshot`
报告目录状态；MCP 对内部 `snapshot` 字段的通用屏蔽保持不变。`directorySnapshot` 只包含 `status`（`current`、`stale`、`newer_present`、
`busy`、`unsafe_path`、`unavailable`）、相对 `path` 和每个文件的范围、revision 与状态，不含
绝对路径或原始错误。

## 导出工作记忆（第二阶段）

“对话与记忆”的工作记忆标题旁有一个导出按钮，只下载当前所选范围（全局或一个已分配项目）
的 Markdown。Agent 使用只读工具 `export_project_agent_memory`，所有者控制台使用
`GET /api/project-agents/:agentId/memory/export`，二者共用同一个导出边界：

- 每次导出都重新从数据库读取，从不读取目录快照或用户修改过的文件；快照不存在也不代表
  任何结论。读取结果先经过与任务入口相同的严格范围校验（外层、当前记录、每条历史的员工、
  项目、空间、范围和 revision），任一不符即拒绝，不生成 Markdown。
- 内容只有允许列出的身份字段和所选范围的一层记忆，注明范围、数据库 revision、记录时间、
  生成时间，以及“由数据库生成、不是依据、修改不会导入”。不含原始对话、token、任务或会话 ID、
  完整分配列表或运行路径；疑似凭据的内容被隐去。结果只返回建议文件名和 Markdown 文本，
  不接受输出路径参数，也不写导出文件；记忆内容按纯文本返回。MCP 为该工具单独预留 512 KiB，
  足以容纳最大的合法身份资料（含 UTF-8 与 JSON 转义）和一层记忆；万一仍超出，会明确报错，
  而不是返回被截断的半个文件。
- Agent 工具沿用 `get_project_agent_memory` 的权限：活动的长期员工、可信宿主注入的来源客户端
  必须在白名单内，调用方不能自报来源；项目必须由 Provider 校验分配，不会隐式读取其他项目。
  该工具不在远程连接器的允许列表中。控制台按现有所有者检查权限导出，只要求长期员工。
- 导出时会顺带刷新可选的目录快照；快照目录不可写不影响导出，结果也不声称已在本机保存。
- 界面在请求期间禁用按钮并显示进度；切换范围、员工或收起面板后才返回的结果会被丢弃，
  不会下载错误范围；失败时说明并可重试。

### 升级说明

从 0.12.4 升级不需要迁移，现有数据库保持不变：员工 ID、工号、资料、各项目工作记忆的历史与
revision 以及访问 token 都沿用。目录在首次授权读取时才补齐。0.12.4 没有全局工作记忆，升级后
全局层为空，直到第一次检查点。删除生成目录或文件后，下次读取会按数据库重新生成；手动修改的
Markdown 永远不会导入。目录权限出错时不影响读写和导出，修复权限后下次读取即可恢复。以上
升级结果目前只在一条路径上验证过（已发布的 0.12.4 → 新 Provider，同一隔离 Neo4j），并非
覆盖所有旧版本。
