# 角色 Agent：持久记忆、唯一负责人和自动唤醒

角色是长期身份；Claude Code、Cursor、Codex 是执行入口。切换入口不等于换人。
本实现复用现有 Neo4j，不增加第二个数据库，不把聊天记录当记忆库。

## 当前验收结论（2026-09-01）

下文各轮测试数量是各自时点的记录，不相加为一个总数。所有隔离验收角色、会话和记忆
均为合成样本；真实数据库、协议子进程、产品客户端三个证据层级不能互相替代。
恢复后的审查显式使用用户指定的 `claude-gpt-5.6-sol`（GPT 5.6 Sol 网关别名）；
Claude Code 是执行客户端，不表示本轮模型仍是 Opus。CLI 统计窗口为 200k，不按旧 1M 使用。

本次新增两项运行时保护：外部执行器最后一个租约释放后删除临时运行条目，不删除持久
角色身份、工作记忆或任务历史；异常成功租约响应不再静默作为关闭模式继续执行。
有返回 ID 时尝试回收，没有 ID 或回收失败时仍依赖远端 TTL，不宣称立即释放成功。
后续第三次限定更新已将这些修复、员工 URL 编码保护、checkpoint 记忆存在性绑定和选人
解释一起安装；离线备份校验与新的 23 项安装检查通过。检查结果针对限定候选，
不表示部署了工作区的其他构建变化，也不代表既有客户端会话已热重载。
第四次限定更新另将招聘事务、HR 守卫和旧策略警告一起安装，25 项安装检查全部通过，
其中包括在线旧策略 schema 与 deprecated 路由。最新源码真实库核心 48 项通过；
候选另外通过 25 项 Node、45 项真实库核心和 6 项 HTTP/MCP 接续。测试数据均为合成样本，
不等于普通输入自动唤醒已验收，未改动宿主信任或其他员工包。

## 记忆分层

| 层 | 内容 | 边界 |
| --- | --- | --- |
| 身份与任职 | 稳定 Agent ID、职责、能力、个人初始偏好、项目任职 | 身份属于个人空间，任职属于项目 |
| 私有工作记忆 | 当前摘要、重要决策、未完成问题、下一步 | 严格按个人空间 + 项目 + Agent 隔离 |
| 项目知识 | 已记录的需求、架构、约束、来源与确认状态 | 当前项目共享；其他角色私有知识不注入 |
| 任务生命周期 | 本次负责人、宿主会话、回写状态 | 持久化元数据，不保存输入提示词、本机目录或完整对话 |

工作记忆是有来源和时间的工作上下文，不是新的用户指令，也不是自动确认的事实。
共享知识仍走原有知识提炼和确认流程。每份工作摘要限制在 32 KiB 内；历史版本保留，
入口只取当前版本和少量相关知识，需要更多时按主题检索。对项目的熟悉来自“恢复摘要 +
读取有来源的项目知识 + 检查当前代码”，不是无限复制全部聊天。

## 如何分配一个负责人

1. 精确解析当前项目；多项目歧义不猜测，不跨项目读取私有记忆。
2. 同一已开始任务再次加载上下文，复用持久化的负责人；宿主提供稳定 turn ID 时，同轮重试也不换人。
3. 对新任务，显式指定的有效 Agent 优先，且必须有有效任职、允许该客户端。
4. 自动选择先满足全部显式能力要求，再优先匹配工作类型。
5. 同等匹配时，优先当前负载较低者，再看项目工作历史、已有记忆，最后稳定排序。
6. 无显式能力要求、没有专门匹配者时，任务入口可选项目默认负责人；不会凭空宣称具备能力。
7. 项目关闭自动复用时，返回需要显式选人的状态。没有合格角色不会偷偷招聘。

当前实现约定：非空任职能力列表覆盖角色档案能力，不做并集；空任职列表则回退到档案。
全部能力要求是新任务自动选择的门槛，不会暗中替换显式指定的有效角色或当前任务负责人。
自动选择的说明同时给出工作类型匹配情况、所选角色当前任务数，以及工作类型和负载优先于
历史的顺序。无精确工作类型的兜底明确标注仅用于连续性，不是理解任务内容后的语义匹配；
项目默认路径报告实际合格候选数。这些说明不改变排序或机器可读 reason。
实际招聘确认只由项目级 `askBeforeRecruitment` 控制。旧空间级 recruitment-policy
接口保留读写兼容，但响应明确标注 `superseded`、不生效及替代工具，OpenAPI/MCP 也标明
废弃；它不会覆盖任何项目开关。需要改变实际授权时必须指定确切项目。
审批招聘时，HR 必须仍处于 active；inactive/archived HR 不得创建身份，但不阻止取消。
前置招聘的 claim/audit 保留用于 TTL 后重试；未过期的 claim 不允许被立即重放抢占。
创建身份、任职和 fulfillment 使用同一请求私有事务，按 task → recruitment 加锁，
最终守卫失败整体回滚，不留下“返回失败但角色已创建”的部分状态。
首次任务提交还在更外层使用一个请求私有事务，把协调、招聘、claim/provision、身份、任职、
执行器决策、任务主记录及其关系一起提交。任一点失败都不留下任务、招聘审计、身份或任职，
同一幂等请求可立即安全重试。独立审批流程仍保留自己的 requested 审计和 TTL 恢复语义。
显式指定另一个有效角色可覆盖当前会话负责人；其他客户端即使提交同名 session ID，
也不会继承该会话的负责人。角色能否接新工作与“这次任务是谁在做”应分别判断。

执行器路由对任职采取 fail-closed：任职必须属于目标项目且为 active，缺失、失效或其他项目的
assignment 都会被拒绝。工作类型是自动选人的排序偏好，不是对已经由显式任职或能力筛选选中的
角色再加一道绝对门槛；因此一个满足所需能力的有效任职可以承担另一种工作。调用方没有传入
assignment ID、要求执行器自行解析任职时，仍须匹配该 work kind，避免无依据地扩大职责。

负载包含协调任务和最近两小时未回写的当前宿主任务；旧的中断会话不会永远占用名额。
这是选人提示，不是“某个模型进程正在运行”的证据。同一个角色可以在不同宿主执行不同任务，
但每个任务只有一个负责人；需要并行协作者时仍通过协调计划、租约和实际执行报告管理。

新任务的主记录、初始事件、路由决策、参与者和招聘关联在同一 Neo4j 事务中保存。
关系写入异常或目标缺失时整体回滚，公开列表不会暴露一个只保存了一半的任务。
相同幂等键重试不会重置既有参与者状态和事件；旧版本遗留的缺边仍通过重试修复，
修复事务先锁住任务，再读取最新状态和更新时间。并发取消已提交时，新补的参与者关系
继承取消状态与终止时间，不覆盖既有参与者和事件；该交错顺序已用公开 HTTP + 隔离 Neo4j 验证。

活动接口也以单个事务保存任务状态、参与者、事件、实际执行器观察、结果证据、统计汇总与
临时角色归档。任何验证或数据库写入失败都会整体回滚，不占用该次事件的幂等键。
事务在读取状态和版本前锁住目标任务；同一 `expected_revision` 的并发修改只能有一个成功，
同键同载荷重放不会重复推进版本。每个请求使用自己的事务入口，不替换共享运行时的驱动。
这不自动修补旧版本已经留下的缺失审计。

源码中的独立 actual 接口也使用请求私有事务，按 task → Agent → executor → permission
加锁后重新校验客户端、策略、预检与权限。迟到观察保留在历史里，不覆盖更晚的当前执行；
旧投影没有执行时间时，从其关联观察恢复时间，缺少关联证据时保留原投影等待修复。
独立 outcome、ignore、reset 与对应统计汇总原子提交，同一统计组的并发更新串行处理。

新的 outcome 写入必须匹配任务参与者、工作类型、策略及已记录执行。`runId` 可以省略，
但不能把未记录的执行器当成已执行者记分；指定 run 时必须属于该任务、Agent 和执行器。
系统终态只接受匹配活动事件的状态、时间、引用与 canonical 幂等键，不允许换键重复记分。
外部测试与用户反馈的引用仍是授权调用方提供的声明，不是系统独立验证或用户本人认证。
新增 actual/outcome/reset 时间必须带时区；旧无时区评价仍可读取、忽略，不猜测其原始时区。
存在旧无时区评价或重置时间时，统计返回 `validationWarnings`、中性贡献及 `ignored=true`，
暂停整个统计组的学习权重。逐条显式忽略问题评价，或以新幂等键提交带时区的重置后恢复；
不自动改写原时间、不把未知先后次序用于算分。实际模型也必须满足任务模式、推理强度及能力提示。
这些独立证据修复已通过隔离 Neo4j 回归和两轮 Claude Code 复审；首轮指出同次运行的旧投影
会污染新观察的时间基线，修复后复审为 clean。它们不追溯伪造旧历史；是否已进入当前运行实例，
仍以相应的安装后文件、在线接口和客户端连接验证为准，不能仅由源码结果推断。

## 入口、回写和休眠

- `begin_task_context`：解析项目、选择负责人、恢复记忆和偏好，并持久化任务上下文。
- `get_collaboration_preferences`：无入口注入时的回退，也返回角色上下文。
  有宿主会话标识时传 `sessionId`，使回退绑定同一任务负责人。
- `get_project_agent_context`：显式角色与 worker 的隔离上下文，也包含工作记忆、项目摘要和近期任务。
- `get_project_agent_memory`：写之前读取完整当前版本；不要从被截断的入口内容覆盖记忆。
- `checkpoint_project_agent_memory`：独立保存角色摘要。`expectedRevision` 防止覆盖他人的新版本，
  `idempotencyKey` 防止同一写入重试产生重复历史。
- `checkpoint_task_knowledge`：结束时完成一次知识检查；选择 `capture_candidates` 或 `retain_nothing`。
  角色上下文有变化时可同时传 `agentMemory: { expectedRevision, memory }`。
  角色目标从持久化任务取得，调用方不能另填一个角色覆盖。
- `verify_task_checkpoint`：从 Provider 检查，不依赖入口进程的内存。
  未回写时给出原任务 token；自动继续不会创建一个新的待回写任务而陷入循环。

Stop hook 不生成或保存工作摘要。第一次检查未完成时，宿主继续提示模型，由模型调用
checkpoint。Codex 的受信任本地 Stop 适配器若在这次继续后仍发现同一 token 未完成，
只为该 token 写入 `retain_nothing` 作为防循环兜底；它不会生成候选知识、角色记忆或摘要。
因此仍须同时验证宿主确实继续执行以及 Provider 最终返回 `checkpointed`。仅看到 Stop 配置
或 `checkpoint_required` 返回值，不能证明自动收尾已经完成。

角色工作记忆冲突返回 409：读最新版、保留仍有效内容、合并后重试；禁止盲目覆盖。
角色、记忆头、历史和任务上下文的读取都先绑定个人空间与目标项目；相同 Agent ID 或记忆 ID
不能从另一个项目借用。列表也不会因为调用方只知道空间而混入其他项目的角色或私有历史。
同一已完成检查的重试不重复写入；不同检查内容不能复用同一个已认领的 checkpoint。
候选知识的本地校验在 checkpoint 认领和角色记忆写入之前完成；缺少推理依据等校验错误
可以修正后用原任务 token 重试，不会提前推进记忆版本。附带工作记忆时，Provider 将
`prepare` 认领和记忆 CAS 放在同一事务：竞争检查、新轮次替代、记忆版本冲突或客户端
授权失败导致准备被拒时，两者一起回滚。记忆目标及会话来源从持久任务取得，不接受调用方另指定。
成功 `prepare` 是记忆提交点；后续知识提炼及 `complete` 不在这个数据库事务中，失败时
已提交记忆不会撤销。已知 CAS 失败后可读取新版、合并并重试；准备响应丢失等结果不确定时，
必须以相同内容重试，不能用另一份内容覆盖已认领检查。跨应用实例的重试也不会重复增加记忆版本。
首次认领还绑定是否携带工作记忆：没有记忆的检查不能在后续 prepare 重放或完成后再追加记忆，
即便调用方重复使用相同指纹也返回 409。旧记录通过该 token 的既有记忆检查兼容；同内容记忆
重试仍保持原版本，不额外增加历史。成功 prepare 后若被新轮次替代，旧 token 的 complete
仍被拒绝；已提交记忆保留，新轮次暴露上次未完成回写，不能据此宣称整个捕获流程原子化。
此原子路径要求 MCP 与 Provider 一起更新；不能以工作区测试结果推断当前安装版已经支持。
关闭 capture 后不写工作记忆或知识，生命周期本身仍只记录完成检查所需的最小元数据。
临时角色、已结束的任职、归档角色不能写持久工作记忆。
角色限定的 `allowed_clients` 同样适用于工作记忆写入，未获该角色允许的来源返回 403。
任务 token 是空间内的唯一句柄，不得借给另一个会话；重复占用返回 409，而非数据库异常。
同一当前轮次可幂等恢复；已被新轮次替代的旧轮次返回明确 409，不返回随后无法回写的旧 token。
入口记录的 `memory_revision` 是该轮观察到的基线，不是长期读锁；写入仍须用 `expectedRevision`
与最新记忆头做 CAS 校验。

“唤醒”有两层：宿主的任务入口恢复角色上下文；启用原有 adaptive runtime 时，
真实图请求通过租约唤醒 Provider / Neo4j。空闲后释放运行资源，数据库里的身份和记忆不消失。
本改动不为每个角色常驻进程，也不自动启动一个未获授权的外部模型。

运行租约的有效期从唤醒和执行资源准备完成后开始计时。冷启动期间调用方尚未拿到
租约句柄，不能要求它提前发送心跳；启动耗时不会提前消耗交付给调用方的续期窗口。
若协调器在排队或唤醒期间关闭，尚未交付的租约获取失败，不返回已被清理的成功句柄。
一次瞬时续期失败不会永久终止心跳；后续周期重试，直到显式释放/关闭或远端确认租约失效。
休眠失败至少等待 30 秒再重试，状态接口同步显示退避后的时间，避免过期闲置期限引发忙循环。
启动失败的错误摘要保留在运行状态中，便于诊断。
托管执行器关闭会等待其适配器停止；没有托管适配器的外部宿主不会被启停。
闲置时托管停止失败后间隔 30 秒重试；新获取须先确认失败实例已清理，避免重复启动。
部分启动失败仍清理资源，但保留原始启动错误。显式关闭会等待所有托管停止完成，
任何停止失败都返回错误；同时仍关闭服务拥有的 application。`createServer()` 返回的
`close()` 可等待完整关闭，重复调用保留同一结果；旧的 `server.close()` 仍兼容并记录收尾错误。
监听失败也会等待运行时清理；若清理同时失败，聚合两种错误并保留启动 cause。
响应已经发送后若租约清理失败，不再发送第二个响应。
HTTP 调用方在冷启动等待期间断开后，迟到租约立即释放，不等待整个 TTL。
容器停机只检查现有引擎，不调用会启动 Docker/Rancher 的唤醒方法。

## 执行会话与上报会话

持久 Agent、具体 worker、报告者宿主是不同身份。`record_project_agent_task_activity`
仍由 MCP 把外层 `sourceApplication` / `sourceSessionId` 绑定到报告者，调用者不能用子
执行器的 ID 覆盖它。可选 `workerRuntime` 单独保存实际观察到的执行器应用、会话 ID 和
已知链接，例如：

```json
{
  "workerId": "verification-worker",
  "workerRuntime": {
    "application": "claude_code",
    "sessionId": "observed-worker-session",
    "sessionUrl": null
  }
}
```

这是活动请求中的证据片段，不是完整可调用参数，也不证明模型请求成功。报告仍须提供
已参与任务的 Agent；报告者和 worker 应用都须符合该 Agent 的客户端限制。会话 URL
不能含凭据、查询参数或片段，未知链接留空；表格不会给子会话借用宿主链接。

`executionSummary` 每个已观察 worker 一行，展示当前会话的最新累积用量，不把重试
快照相加。同一 worker 换应用或会话 ID 后，模型、工具、Token 从新会话重新取证；旧事件
仍保留。空工具列表是已报告为空，缺少 Token 是未知而不是零；错误回执中的零仅代表该
回执范围，不能据此声称整任务免费。仅追加同一会话链接时可以保留此前的有效执行证据。

此契约需要 Provider、MCP 和 Web 使用支持该字段的版本；本地测试通过不等于正在运行的
服务已更新，也不能替代真实外部执行器验收。

## 不同宿主的支持范围

| 宿主 | 接入方式 | 注意事项 |
| --- | --- | --- |
| Codex | `UserPromptSubmit` MCP tool + 受信任的本地 `Stop` 命令，保留原有指令回退 | 重连 Fuli 后，按宿主要求审阅并信任 hooks；首次 Stop 让模型完成 checkpoint，二次重入仅以 `retain_nothing` 防循环；不会改信任存储或绕过审查 |
| Claude Code | 现有 `UserPromptSubmit` / `Stop` 的 MCP tool hooks | MCP 必须已连接，结束检查现在跨进程持久化 |
| Cursor | `sessionStart` 注入引导；`beforeSubmitPrompt` 建立任务；`stop` 做有限次数的回写提醒 | 原生 prompt hook 没有同轮上下文注入字段；每轮按引导调用偏好入口，传入宿主 sessionId |
| 云端环境 | 需部署同一受保护的 Provider，并为该宿主配置授权连接和相同项目映射 | 云机器无法直接访问本机 loopback；用户级本机 hooks 不自动同步到云端 |
| Claude 网页版 / Cowork 的远程连接器 | `fuli remote-mcp` 提供受 bearer 保护、绑定单一项目的 Streamable HTTP 上游；来源独立记录为 `claude` | 命令只监听 loopback，必须放在公开 HTTPS + OAuth 2.1 代理之后；远程连接器没有 Claude Code 的本地 hooks，初始化指令会要求每项任务先恢复角色、结束前 checkpoint，但仍须做真实 claude.ai 产品验收 |

安装器只合并或移除 Fuli 管理的 hooks，保留其他配置。更新 Provider 与客户端代码后，
在 Fuli 的接入设置中重新连接相应宿主，再新建任务。配置已写入不等于实际客户端已加载、
hooks 已受信任、角色已执行或结果已通过验收。

直接 CLI 调用同样先走工具名、参数 schema、空间/项目/会话绑定校验；未知字段、缺失必填字段、
错误会话或损坏的 Provider 2xx 响应都明确失败，不能绕过 MCP 会话边界进入存储层。配置备份目录
和文件分别使用 0700/0600，回滚前重新校验摘要；这些保护不等同于宿主已重新加载配置。

`fl setup` 安装或更新 Codex hooks 后会保留 `trustReviewRequired`，并提示在 Codex CLI
使用 `/hooks` 审阅、信任 Fuli 项。重复安装若未改变配置，仍提示 setup 不验证宿主信任状态，
不会据此宣称 hooks 已受信任。安装器不读取或改写信任存储；其他 Agent 的安装输出不受影响。
公开 CLI 回归在临时目录中使用真实配置、备份与 Skill 安装；仅图运行时启动使用替身。
这两项回归验证安装交付提示，不等于已完成普通输入自动唤醒。

`--ephemeral`、只读 sandbox 与精确 MCP 工具白名单；这不代替 hooks 信任。
Cursor 的 `CURSOR_CONFIG_DIR` 文档只承诺 CLI 配置目录覆盖；当前安装版 MCP 加载器
仍读取用户级 MCP 文件。不能把临时项目目录或该变量当作全局 MCP 隔离，更不能在未核实

[Codex CLI](https://developers.openai.com/codex/cli/reference)、
[Cursor CLI 配置](https://prod.cursor.com/docs/cli/reference/configuration) 与

### 远程 Claude / Cowork 上游

`fuli remote-mcp` 不暴露管理台、HTTP Provider 或 Neo4j，只提供任务入口、checkpoint、
当前项目检索、角色上下文/记忆与任务证据读取。每个进程绑定一个明确的
`personalProjectId` 和当前个人空间；客户端传入的路径、项目、空间、来源与宿主会话归因
会被服务端绑定值覆盖，不属于工具 schema 的身份字段会直接被拒绝。请求必须带内部
bearer，跨站 `Origin` 会被拒绝。任务入口自动选择的角色会绑定到当前 MCP 会话；角色上下文
与私有记忆读取只能访问该角色。checkpoint token 还同时绑定该进程的项目和创建它的 MCP
会话，其他项目或同项目的其他远程会话都不能借用。

```sh
umask 077
openssl rand -hex 32 > ./fuli-remote.token
fuli remote-mcp \
  --personal-project-id YOUR_PROJECT_ID \
  --bearer-token-file ./fuli-remote.token \
  --port 2728
```

POSIX 上 token 以 nonblocking + no-follow 打开并要求 `0600`；Windows 无法经 Node.js 获得
等价的 `O_NOFOLLOW` 与 POSIX mode 保证，必须用 Windows ACL 保护 token 所在目录，并确保
它是普通文件而不是链接。

进程启动前会确认项目存在于当前个人空间，默认限制 8 个并发会话并清理空闲超过
15 分钟的会话；可通过 `--max-sessions` 和 `--session-idle-ttl-seconds` 调整。“空闲”指没有
已完成的 MCP 应用请求：静默的独立 SSE 通知流不视为持续活动，也不会永久占用会话槽；
达到 TTL 后客户端须重新连接并初始化。关闭服务时，已进入分发的请求、会话关闭与 HTTP
连接共用一个真实时间宽限截止点，任一清理步骤都不能无限延长关闭。若代理转发
`Origin` 或保留公网 Host，必须显式增加
`--allowed-origin https://connector.example --allowed-host connector.example`；否则代理必须把
Host 重写为实际 loopback 上游地址。服务端始终按监听地址和显式 allowlist 独立核对 Host。

监听器固定为 loopback。生产接入必须由 HTTPS/OAuth 代理完成用户登录、token audience
校验、最小 scope、限流与审计，再把请求转发到本机上游；外部 OAuth token 不得透传给
其他服务，代理也不得开放 Fuli Provider 或 Neo4j 端口。Claude 自定义连接器从 Anthropic
云端发起请求，只有完成公开域名、OAuth 与连接器配置后才算产品接入。本仓库不会自动创建
公网隧道、域名、证书或 OAuth 客户端，也不会把内部 bearer 写入仓库或客户端配置。

## 验证与复跑

仓库内自动测试分两类，不混同证据等级：

- 普通测试：MCP 工具边界、schema、授权客户端、配置保留、有限输出、禁用 capture、入口不递归等。
  包括候选校验失败后修正输入、用原任务 token 继续完成检查。
  部分使用明确的 HTTP 边界替身；不能据此证明数据库持久化。
- 可选真实验收：真实 Neo4j、FastAPI HTTP Provider、独立 Node/MCP 子进程，使用隔离样本。
  覆盖 Provider 重建后的记忆恢复、并发冲突与幂等、空间/项目/角色隔离、归档禁写、唯一负责人、
  当前会话复用，以及 Codex、Claude、Claude Code、Cursor 四个来源标识的连续写读、分进程结束检查和继续任务的协议语义。
  每个来源还验证：候选知识被本地拒绝时，附带的角色记忆不会推进版本，修正后可以完成回写。
  这些工具调用由测试直接发起，不是三个真实客户端的原生 hook 事件。

普通输入自动唤醒须另做产品验收：使用同一个隔离项目，提示中不包含工具名、隐藏摘要、
任务 token、固定角色或调用协议；hooks 必须由宿主真实加载并获用户审核。证据应同时包含
模型处理前的入口 hook、恢复的角色上下文、结束 hook 及必要的继续执行，并用独立 HTTP
读回核验记忆版本与内容。工具返回中的 hook 名称、来源标签、模型自报或版本增长单独出现，
都不能证明该调用来自宿主 hook。若宿主不能提供足够的事件来源证据，结果应保留为未验证。
