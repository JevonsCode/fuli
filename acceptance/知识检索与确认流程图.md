# Fuli 知识检索与确认流程图

## 一、任务开始与偏好注入

```mermaid
flowchart TD
    A["收到用户任务"] --> B["根据当前工作目录识别个人空间和当前项目"]
    B --> C["读取个人全局偏好"]
    B --> D["读取当前精确项目偏好"]
    B --> E["排除其他项目偏好"]
    C --> F["合并候选偏好"]
    D --> F
    E --> F
    F --> G{"是否存在与当前任务相关的偏好冲突？"}
    G -- "是" --> H["只处理当前任务需要的冲突"]
    G -- "否" --> I["形成有效偏好上下文"]
    H --> I
    I --> J["排除待确认、无效和无关项目偏好"]
    J --> K["把有效偏好交给智能体"]
    K --> L{"任务是否可能依赖历史知识？"}
    L -- "否" --> M["直接完成任务"]
    L -- "是" --> N["执行有界知识检索，并允许返回待确认知识"]
```

## 二、项目知识检索范围

```mermaid
flowchart TD
    A["当前项目发起知识检索"] --> B["加入个人全局知识"]
    A --> C["加入当前项目本地知识"]
    A --> D["加入明确点名的其他个人项目"]
    A --> E["加入已订阅且与任务相关的公共项目"]
    C --> F{"本地是否已有相同稳定键？"}
    F -- "是" --> G["本地知识覆盖继承知识"]
    F -- "否" --> H["检查上级知识继承"]
    H --> I{"知识继承模式是什么？"}
    I -- "仅限本项目" --> J["不继承"]
    I -- "仅向指定项目继承" --> K{"当前项目是否在授权清单？"}
    K -- "否" --> J
    K -- "是" --> L["允许进入候选结果"]
    I -- "向后代项目继承" --> M["沿明确项目关系向上查找"]
    M --> N{"关系是否为父子关系或知识复用关系？"}
    N -- "否，只有普通关联" --> J
    N -- "是" --> O{"作用域距离是否不超过两跳？"}
    O -- "否" --> J
    O -- "是" --> L
    B --> P["汇总候选知识"]
    D --> P
    E --> P
    G --> P
    L --> P
    P --> Q["保留已确认、智能体已确认和允许检索的待确认知识"]
    Q --> R["按权威性、相关性和作用域距离排序"]
    R --> S["返回正文、确认状态、双分数、继承路径和来源标记"]
```

## 三、知识确认状态流转

```mermaid
flowchart TD
    A["新增知识或内容发生变化"] --> B{"是否有用户或权威来源明确确认？"}
    B -- "是" --> C["状态：已确认"]
    B -- "否" --> D["状态：待确认"]
    D --> E["可以按需检索"]
    D --> F["不能作为自动注入偏好"]
    E --> G{"知识是否真正影响回答、实现或决策？"}
    G -- "否，仅检索或查看" --> H["不记录有效使用"]
    G -- "是" --> I["记录引用或应用事件"]
    I --> J["按知识、任务、使用类型和内容代次幂等去重"]
    J --> K{"是否为新的唯一事件？"}
    K -- "否" --> H
    K -- "是" --> L["增加有效使用次数并更新双分数"]
    L --> M{"是否存在未解决冲突？"}
    M -- "是" --> D
    M -- "否" --> N{"是否达到五次且跨三个任务？"}
    N -- "否" --> D
    N -- "是" --> O["状态：智能体已确认"]
    O --> P["可以使用或自动注入，但权威性低于人工确认"]
    O --> Q{"用户或权威来源之后是否明确确认？"}
    Q -- "是" --> C
    Q -- "否" --> O
    C --> R["最高确认权威"]
    C --> S{"正文内容是否被修改？"}
    O --> S
    S -- "否" --> T["保持当前状态"]
    S -- "是" --> U["内容代次加一"]
    U --> V["计数归零、效用分数归零、置信分数回到初始值"]
    V --> D
```

## 四、四象限与确认状态的关系

```mermaid
flowchart LR
    A["原始象限：记录知识最初如何被发现"] --> B["保持不可变"]
    C["当前象限：记录现在如何理解这条知识"] --> D["可以随证据变化"]
    E["确认状态：表示当前权威程度"] --> F["待确认、智能体已确认、已确认"]
    G["检索排序"] --> H["不使用原始象限作为个人知识权重"]
    B --> I["保留发现来源"]
    D --> I
    F --> J["影响使用资格和权威排序"]
    H --> J
```

## 人工检查结论

- 四象限、确认状态和双分数是三个独立维度。
- 项目关系只负责确定“到哪里找”，不自动改变知识真伪。
- 待确认知识可以进入检索，但不会因为被看见就自动增强。
- 智能体已确认是可用但较低权威的中间状态，不等同于人工已确认。
- 内容变化会开启新的确认代次，旧使用次数不能继续累积。
- 命中时可以显示顶部标记和底部来源；未命中时只显示顶部标记，空页脚不重复渲染。
- Fuli Web 使用发布包内的小图标；Codex 链接前的地球图标属于客户端渲染边界。
