# 多智能体关系网验收

本验收中的 A–E 项目、偏好、步骤和编号全部是 **MOCK（合成）数据**，不代表真实项目事实。

## 产品理念

FULI 验证的是人在持续与 Agent 协作中形成的关系网。关系节点可以连接本地文档、外部知识源、项目、决定、工作步骤和其他知识库，但文档存储本身不是产品目标。

关系网应逐渐沉淀个人品味、个性与判断偏好，并保留人的最终决定权：

- 多个项目重复出现的共同核心可以成为更高作用域候选；
- 相似度、使用次数、项目距离、时效、确认权威和负面证据分别影响候选排序；
- 分数不能自行改变偏好作用域或越过冲突与人工确认。

## 关系

```text
travel-d      --PART_OF--> platform-a
travel-d      --PART_OF--> platform-b
preference-e  --PART_OF--> platform-a
related-c     --RELATED_TO--> travel-d
```

## 公开验收边界

1. Codex 从 MOCK（合成）文档沉淀 A、B 的共享上下文和 C/D/E 的项目偏好。
2. Cursor 在空工作区中只通过 FULI 检索，验证多父继承与关联项目不自动扩张。
3. Claude Code 在另一个空工作区中重新检索相同关系，验证跨 Agent 可用性。
4. FULI 的确定性 API 检查共同核心候选是否可发现、是否保持只读，并保留局部限定与来源。

## Graphiti 捕获契约

- `known_known` 可以直接保存来源明确、已确认的文档事实。
- `known_unknown`、`unknown_known`、`unknown_unknown` 都必须提供
  `reasoningSummary`，说明为什么这是推断、疑问或探索性节点，而不是已确认事实。
- Provider 的结构化 422 校验错误必须向调用 Agent 暴露安全的字段路径和原因，不能只返回
  “Graphiti provider request failed”。

## 预期判定

- `travel-d` 能取得 `NETWORK-A-GUIDE-101` 与 `NETWORK-B-GUIDE-202`，并保留两条来源路径。
- `related-c` 不自动取得 D 的项目知识，只能提示扩展搜索。
- C、D 与 E 的共同核心可以提高候选优先级，但不能自动成为全局偏好。
- “注释使用中文”只属于 E，不能被提升为所有项目的默认规则。
- D/E 的共同核心形成候选时，父项目 A 是可选作用域；候选不会自动写入，
  D/E 原文、来源与 E 的中文限定继续保留。
